# 程序化植被转换与入库

交付可由 Galacean 独立生成的最终植物结构、材质和目录引用。先确认源模型、验收目标及资产的实际消费者。以下路径和命令以 Engine 仓库根为基准，见 [代码入口与入库](references/engine-map.md)。

## 从源模型到最终结构

1. 读取源模型的单位、坐标轴、根部 pivot、节点变换、LOD 顺序、网格与材质绑定、UV、着色法线、顶点色、贴图和采样设置。依据几何、UV 连通域和父子挂接识别部件。保留源模型作为各级 LOD 的对照基准。
2. 用现有生成器表达树干及主次枝的中心线、半径变化和挂接，再还原叶片、叶簇或其他器官的形状、朝向与分布。按需要选择管体或参数曲面。连续部件共用边界采样，UV 断开处保留独立的采样域。Blender 用于离线提取、拟合和验证。运行时从最终参数生成网格，源网格、逐顶点属性和拟合残差留在离线环节。
3. 同时还原材质。先检查已注册的公共外观，再为确有差异的轮廓或纹理新增贴图。基础色按中性灰度加线性颜色恢复，保留 Alpha、源 PBR 数据图和采样行为。裁图时同步各 LOD 的 UV，按本次预算核对实际图片尺寸。详见 [外观拆分与复用](references/appearance-sharing.md)。
4. 同形变种共享一个主株，颜色、尺寸、朝向和株数由实例配置表达。不同拓扑或冠形使用独立结构。沿用 `PlantParameterEncoding.ts` 对重复形状、UV 变换、法线字段和数值无损编码。编解码往返保留数值、字段缺省和顺序，编辑共享数据前先复制。

明确区分源模型还原和经确认的主动改形。减枝、合并不同树形、改用整株面片等编辑按新目标验收，使用目录已有的 `geometryEdited` 语义记录。可共用的完整叶簇或草卡保留有效茎叶轮廓。纯色根茎仅在任务采用该外观规则时去除占位图。

## 注册资产并验证使用入口

在消费者实际读取的物种目录登记稳定 ID、原型或结构文件、材质槽和别名、实例变换、各级 LOD 和植被层。乔木尺寸以运行时编译的 LOD0 米制包络为准。生产项目还需沿实际清单解析到项目内结构、材质、贴图及相关原生资源。目录条目引用公共资源，Seed World 场景只持久化所需资源引用和实例数据。

兼容变种共享 Mesh、SubMesh 和 Material，颜色走既有实例数据。沿用原生自动合批和剔除，按实测绘制提交确认共享有效。更新后核对所有仍在使用的引用，再清理已替换的产物。Gallery、Seed World 项目和 Editor 资源交付各以自己的加载入口验收。

严格还原先通过几何与外观门槛，再完成所需的运行时验收。5% 指标、LOD 预算、实机证据和失败状态见 [验收规则](references/acceptance.md)。只完成离线转换时，报告最终结构和已测项目。
