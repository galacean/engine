# 程序化植被验收规则

以源项目、对应 LOD 和实际运行时编译结果为基准。先确认本次接受的几何、材质和三角面预算，记录测试使用的源、资产 ID、LOD、视图及对齐方式。使用参考图重建时，只评价能观测的尺寸比例、轮廓和分枝，不标记为通过源 3D 网格还原。

## 1. 几何还原与 LOD

- 将源与生成结果统一到同一米制坐标、根部和朝向。正交对照共用相机、画幅和比例，不对候选单独缩放以消除尺寸误差。记录每级包络、三角面数和最差项。没有源网格的额外远景 LOD 单独验证预期轮廓、过渡和面数预算。
- **严格源模型还原使用 5% 门槛**。树木按树干 → 主枝 → 次枝 → 叶片与整树轮廓验收；前一阶段失败时保留后续结果为未通过或未验收。使用树木重建工具时，读取每阶段规则指标与无材质三视图误差的最大值、整树误差及各 LOD 预算。记录工具采用的分辨率、视角和像素容差。
- 对参数曲面拟合，逐部件、逐源 LOD 双向采样表面距离。用源部件包围盒对角线归一化，检查最差值；正交前、侧、顶视投影用 `1 − IoU` 检查最差视角。现有通用拟合器分别报告表面误差、投影误差和面数，5% 分别应用于表面与投影。注明采样方式，不将有限采样当成连续曲面的误差上界。不同测量工具的蒙版容差和指标各自记录。
- 检查部件完整性与挂接、枝管接缝、绕序、退化三角形、UV 方向与连续性，以及源着色法线与实际法线图。逐级对照实际三角面数和约定预算。验收时只向运行时编译器提供最终结构，源模型只交给对照工具。

## 2. 材质与共享资源

- 在同相机和光照下对照源材质与实际编译结果，分别看树皮、叶片正反面、冠层背光、Alpha 细边及 LOD 切换。检查裁切前后 UV、法线、贴图通道和过滤效果。纯几何对照无法证明材质或风动正确。
- 用主株默认色还原源外观，再用两个实例色检验可改色及共享。核对真实图片、Mesh/SubMesh、Material 身份以及兼容的 shader、采样、双面和阴影状态。同图和同类名称本身不能证明已合批。
- 改了编码时，比较解码后的结构与每级实际编译属性，包括位置、法线、UV 和索引。检查资源闭包和实际文件大小；无损压缩、面数和绘制次数分别报告。

## 3. 资产可用性与运行时

- 从实际目录或项目清单查到目标 ID，并解析原型、LOD、材质和贴图引用。检查缺失或悬空引用。主株和变种按同一资源关系在目标环境加载，颜色与摆放保持独立。
- 在目标浏览器打开实际服务。Asset Assembly 验证单株近景、变种、各 LOD 和整类可见实例。Seed World 交付还要在目标项目中生成或放置，检查 LOD、阴影、风动与可编辑项。涉及持久化时，保存后重开并再次运行，核对资源、外观与实例。Editor 包交付用实际导入、放置和重开证明可用。
- 使用实际提交统计核对 Instancing。分别记录主画面和阴影的 Draw Call、可见实例数和 LOD；共享的提交按实际 draw 去重。若要报告帧率或 GPU 时间，保持设备、渲染分辨率、相机、可见集合和阴影设置可比，并注明真机条件。

验收记录写明资产与源、各 LOD 最差几何误差及三角面数、外观对照、引用与合批结果、实际打开的入口。分别标记通过、未通过或未测。`geometryAccepted` 只记录几何验收，不能用它推断材质、Seed World 注册或性能。保留明确的候选状态，避免把预览可见或某个单项通过当成完整验收。
