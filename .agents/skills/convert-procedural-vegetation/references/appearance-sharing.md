# 外观拆分、颜色分离与跨类别复用

当任务涉及拆图、灰度化、裁切、白图清理、相似图片合并、材质分批或 UV 重映射时阅读。代码入口见 [代码入口与入库](engine-map.md)，场景验收见 [验收规则](acceptance.md)。

还原转换的目标是用灰度图与颜色参数恢复源材质的效果，再支持实例改色。颜色分离、贴图缩小与共用不能被解释成统一材质风格；保留源粗糙度、金属度、法线、AO、发光、透明、双面及采样契约。

## 图片本身的视觉验收

- **灰度与换色**：检查可见像素 R/G/B 一致、无残留源色；用至少两种明显不同的实例色观察同一图，确认是参数改色且图片引用不变。保留纹理明暗，不把基础图当二值 Alpha 图使用。
- **透明轮廓**：在灰度＋透明和 Alpha 视图检查完整轮廓、孔隙和细茎。检查缩小及实际采样后的断裂、边缘漏色、粘连；透明棋盘格只用于预览，不进入输出图片。
- **内部间距**：分别检查外围边距和图内留白。针对已要求收紧的多形状贴图，对照修改前后确认大空隙缩小、原有轮廓仍可辨、形状间仍有间隔；不设置凭空的统一间距或填充率阈值。
- **形状布局与采样单位**：若整图是一张叶簇/整株外观，调整内部排布属于这张外观的改编；若图内多个区域被独立 UV 引用，移动区域时必须同步各采样域。不能挪像素却保留失效 UV。
- **完整性与冗余**：整株卡包含需要的茎叶，不重复叠加已被替代的叶片；纯色组件没有占位图；预览中的每张图都能追到真实使用者。
- **复用结果**：对比最终资源引用与颜色参数，确认相似外观已共用，且有实质轮廓差异的外观没有误并。新增图必须有现有公共资源无法覆盖的实际用途。

## 1. 先建立真实使用关系

对每个最终外观记录：源材质/纹理与 UV 区域、使用它的部件和 LOD、当前公共图片、语义角色、Alpha/采样设置、默认色、实际 Material 与 Mesh 身份。

检查范围包含整个已注册外观库、其他资产包/类别、原型及当前未展示的实例。候选查找与兼容性判定分开：先找内容相同或可以归并的图片，再核对纹理用途、通道布局、UV、Alpha、采样、色彩空间及材质契约。不能把某一种图片或某次归并案例写成全库流程。只改预览面板去重不会改变运行时资源；重命名文件或把同类样本放一行不会形成合批。

### 决策

| 观察 | 处理 |
| --- | --- |
| 相同轮廓/细节，仅源色或明暗略有变化 | 经视觉核对，使用一张公共灰度图及实例颜色；主动统一细节时注明改编 |
| 同一图像内容出现在不同资产包/类别 | 比较实际像素/Alpha/朝向与 UV 域，不因路径、部件名称或源材质名不同而重复输出 |
| 形状数量、轮廓或结构有实质差别 | 保留不同公共外观；用户已确认的归并范围内可以统一形态，无需逐图重复确认 |
| 本项目按纯色组件规则处理的独立非木质茎/根/柄 | 使用纯色：`albedo: null`，`alphaCutoff: 0`，清空占位纹理；原材质还原任务中的必要质感不按此规则删除 |
| 完整植物卡含茎叶透明轮廓 | 保留整图及 Alpha Test，茎的轮廓包含在整图中，不另拆图 |
| 木质主干/枝条共用同类树皮 | 统一灰度树皮和兼容材质，以正确 UV/平铺保留纹理密度 |
| 两张图片一样但语义角色不同 | 先核对实际 shader、光照、风动与状态；纠正误分类，不盲改角色以压低 draw 数 |

材质槽 ID 是引用身份，不等于当前图片 ID。只换图片无需随意重命名槽；确需改槽时，结构、`normalFields`、目录别名及外观绑定一起更新。

## 2. 灰度与颜色

这里的灰度规则仅适用于颜色基础图：RGB 保存中性明暗，R=G=B；Alpha 保存覆盖，颜色独立且可编辑。法线、高度、粗糙度等数据图保持各自通道定义和线性/非线性约定，不能为去重改成灰度颜色图。颜色数据是线性值，显示用的十六进制色值要走既有色彩转换，不直接当作线性通道。

对颜色比例基本一致的图，已有 Meadow 方法先将源 sRGB 转线性，用最大通道构造标量明暗、以 Alpha 加权颜色比例提取默认色，再输出 sRGB 灰度图。使用现有实现并检验重建结果，避免重复 gamma 转换。

多色图按实际需要分解为多个中性灰度分量和颜色向量，在光照前重建 `RGB_linear = Σ(gray_i_linear × color_i_linear)`，Alpha 独立保留。基色与发光颜色图分别处理，保留各自原始因子；不能用全图平均颜色代替源色斑、渐变或不同色相。需要独立编辑花心/花瓣等部件时，使用明确的组件或颜色遮罩契约。

材质接入优先复用原生 PBR 的光照与数据通道，灰度乘色只改变颜色输入。保留源着色法线与法线贴图各自的作用，不能用统一粗糙度、删除法线图或改成纯色来代替原材质还原。

实例颜色应在光照前进入既有实例 shader 契约，不能为每株 clone 颜色材质。角色统一的 Meadow 灰度材质可使用 `[role, albedo, alphaCutoff]`；原材质还原路径还需包含影响兼容性的 PBR 参数、数据图、采样、透明、双面与 shader 状态。实例颜色不进入兼容材质的缓存键；源材质固有参数不能因此被遗漏。

当前叶片角色可能走 Overlay 的 `2 × tint × sample` 分支，材质绑定使用中性增益适配后再乘实例颜色。复用既有绑定逻辑，不把该公式的补偿烘进图像或机械应用到所有角色。

## 3. 拆图、裁切和 UV

- 以源模型真正使用的 UV 区域和 Alpha 支撑裁图。一个可复用的完整叶簇/枝条可以保留整张图，不需要逐叶拆解。
- 透明区依据 Alpha 判定；Alpha 预览中的黑区代表透明留白，RGB 的黑色可能是有效树皮、阴影或纹理细节，不能按颜色阈值删去。
- 内部形状间距调整与裁切是两类操作：先明确需要改善哪种留白。收紧排布保持必要分隔，不把密度要求解释为无缝叠满整图。
- 裁切前后保持模型尺寸和几何不变，把 UV 域变化组合进最终参数。材质分组变化不能丢失对应法线场。
- 同一材质的基色、发光、法线、ORM/AO 等图使用对应一致的采样域变换；涉及 UV 旋转或镜像时还需保持法线图与切线空间方向一致。
- 先确认源 UV 的 V 方向、文件像素原点和加载翻转。不要在导出、纹理上传、shader 多处同时翻转。
- 保留重复轴的周期；裁切轴用 Clamp。裁切图的 padding 按输出过滤足迹推导，检查缩小后的边缘与 mipmap 漏色。
- 按任务上限处理全部颜色图和数据图。要求最长边 512 时，将大图等比缩至最长边 512，保留宽高比；同时核对 manifest、加载器和实际图片尺寸，不能只修改尺寸声明。其他任务的尺寸预算以其要求及当前消费者契约为准。
- 缩小在**线性、预乘 Alpha**空间处理，再正确编码 RGB 与 Alpha。检查当前 Alpha Test 阈值下的覆盖率和 mip 层表现；基础级覆盖保持不代表所有 mip 都自动正确。
- 法线图按向量语义缩小并归一化，粗糙度、金属度、AO 等按各自数据通道过滤，不套用颜色图的 sRGB 灰度流程。
- UV 映射验收比较所有 LOD 的实际编译结果：positions/normals/indices 应保持；UV 应只发生预期仿射变换。

对像素完全相同的图可以自动按内容去重。对相似图，图像哈希/Alpha IoU/尺寸仅用于寻找候选，不能代替视觉和语义判断；不要用某次样本的相似度阈值决定全库形态归并。

材质验收先比较默认参数下的源图采样与重建结果，再查看原模型和程序化植被的实际受光效果，最后切换实例颜色确认共用同一组图片与 Material。灰度外观正确、源材质质感保留、实例可改色分别验证。

## 4. 公共资源清理

选择现有公共图片后，无论其具体类型为何，执行同一套引用更新与验证：

1. 更新全部材质清单引用，保留独立 `baseColor`，修正必要的语义角色及 prototype `materialSlots` 名称。
2. 核对公共图归一化 UV 域。裁切/朝向不同要用明确变换，不能通过拉伸网格掩盖。
3. 检查所有活动及保留资产的运行时绑定都不再引用旧图，然后移除旧图片与纹理 descriptor。原图身份、哈希、裁切域和替代关系用于转换时核对，不默认生成或保留来源报告、旧图副本或归档。
4. 重新测量最终图片数量、尺寸及体积，交付实际结果。当前 manifest、文件系统和实际加载是验收依据，不沿用历史拟合计数。
5. UI 按真实图片资源聚合使用者和颜色色块，纯色绑定不展示白图；不得仅隐藏重复预览而继续加载重复图片。

默认复用、裁切或颜色分离应走已核对的确定性资产转换代码。确需创作新图时另行遵循会话中的图片生成工具与供应商约束，不以转换任务暗中扩大生成范围。

## 5. 图集与 draw 数的边界

统一图集/纹理数组是可选的资产与 shader 设计，不是自动合批的同义词。只共用一张图却仍保留不同网格或材质对象，仍可能有多次绘制。需要进一步压缩材质组时先量化代价：像素密度、过滤边距、UV 域、相同 sampler/shader 状态、实例可编辑性和各级 LOD。

同一公共图片可以被完整植株 Mesh、组件 Mesh 或其他基础形状使用。它们共用图片和 Material 后，若 Mesh 不同，仍是不同兼容组，这是引擎规则的正常结果；图片复用不能替代几何复用。

绘制次数和性能收益依据实际测量，不预设固定结果。报告真实可见集合的主画面/阴影提交及性能；阴影级联、容量拆分、过渡 LOD 和剔除会改变计数。
