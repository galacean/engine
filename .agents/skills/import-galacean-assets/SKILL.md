# Galacean 资产入库

先准备资产和描述，再请用户确认。确认后发布这一批资产。
仅要求创建或解释 Skill 时，不发布资产。

## 职责与环境

- 本 Skill 负责本地素材检查、描述生成、用户确认和发布。
- OSS 始终只读。不得上传、覆盖或删除 OSS 对象。
- CDN 上传和召回目录构建复用 [同步 Skill](../sync-galacean-assets/SKILL.md)。先读取其配置和资源限制。
- 核对用户指定的项目工作树和分支。目标项目必须包含 `packages/retrieval/src/retrieval/src/build.ts`。不要沿用历史绝对路径。
- Python 依赖使用同步 Skill 的要求。Node 使用目标项目要求的版本。优先使用现有环境，缺少依赖时按同步 Skill 安装。
- 草稿、审阅文件和同步账本存放在项目外。保留用户原件。只清理本流程创建的临时副本。

这是开发环境的 Skill，不注册为游戏内 VFS Skill。

## 1. 准备资产

读取 [素材准备说明](references/intake.md)。按目标项目的实际导入能力检查资产。
OSS 分类只用于检索，不能证明编辑器支持该格式。

1. 识别资产入口和依赖。一个文件夹可能包含一个资产，也可能包含多个资产。
2. 展示资产分组。不要自动将依赖贴图拆成独立资产。
3. 解压前检查总展开大小、路径穿越和符号链接。解压时执行资源上限。
4. 在项目外整理物料、`describe.json`、必要的 `.meta` 和可选 README。保留相对引用。
5. 根据文件和实际预览编写描述。尺寸、动画和依赖等可解析信息必须从文件提取。
6. 运行 [intake.py](scripts/intake.py) 的 `prepare` 命令。

不要执行资产中的脚本。不要通过猜测类型或更改扩展名绕过校验。
格式、脚本或自定义类型无法通过校验时，说明缺少的导入能力。

`describe.json` 保存搜索信息和资产事实。README 说明使用方法。
用途推测必须标为建议。不要将静态模型描述为已实现的玩法。
简单资产不强制提供 manifest 或 README。

`prepare` 检查真实导入链路和远端目录冲突。
它将文件指纹、项目版本和发布目标写入审阅文件。
准备失败时，不请求最终确认，也不发布。
OSS 无法访问时，可以先编写本地草稿。恢复访问后再完成 `prepare`。

## 2. 请求用户确认

展示每个资产的以下内容：

- 预览。无法取得预览时说明原因。
- 名称、描述、用途和使用限制。
- 文件分组及资产入口。
- 本次操作：新增、复用或更新。
- 更新后不再包含的旧文件。

提供原始描述、目录结构和审阅文件的链接。用户无需阅读技术字段。
说明本次确认授权上传 CDN，并更新目标项目的召回目录。不会写入 OSS。

通过 `request_user_input_async` 弹出确认卡片，展示本批摘要和发布范围。提供“确认，按此发布”“需要修改”“暂不发布”选项。等待用户明确答复，不能将默认选项视为确认。工具不可用时才使用普通消息询问。

由用户确认资产范围和描述。确认前不上传 CDN。
Agent 将确认关联到刚展示的 `review.digest`。不要要求用户手输指纹，也不要自行生成确认。

同名且内容不同时，请用户选择更新或新名称。
同一路径的完整文件集和内容相同时，复用已有资产。
文件、描述、发布目标或项目契约变化后，重新运行 `prepare`，再请用户确认变化部分。

## 3. 发布确认的批次

调用 `intake.py publish --approved-digest <已确认的指纹>`。
一次发布处理整批资产。不要按文件拆分发布任务。

### 并发与入口更新

- 同一资源库的本机任务共用一个同步目录和排他锁。
- 最多同时上传 2 个本地资产。每个资产按文件串行上传。
- 每个文件上传并校验后，立即删除其临时副本。
- OSS 同步流程仍按资产串行执行。
- 整批上传完成后，串行构建召回目录，并更新一次项目入口。

该锁只协调同一台电脑。它不提供跨电脑互斥。
同一资源库应使用固定发布机。不要另建账本绕过锁。

### 来源与账本

首次使用前，先通过同步 Skill 建立完整资源库。
账本必须对应项目当前 manifest。存在未完成的普通同步时，先恢复该同步。

本次只合并用户确认的本地资产。其他 OSS 变化不随本批发布。
本地资产建议使用 `assets/local/...` 逻辑目录。
检测到 OSS 同路径素材时，停止发布，不覆盖任一来源。

外部 SQLite 的 `local_assets` 表标识本地来源。
后续 OSS 同步不会因为找不到这些资产而移除它们。
保留规范账本。它保存本地发布记录和已校验的 CDN 地址。

### 失败与恢复

文件变化、目录冲突、CDN 回读校验失败或目录构建失败时，明确报告失败。
不要静默跳过资产，也不要发布半批结果。

发布失败时保留旧入口。已上传物料可以用于重试。
`pendingIntake` 标记会阻止同步器发布未完成的批次。
使用原审阅文件和原同步目录恢复，不要删除标记强行解锁。
原件变化或丢失时停止。说明需要恢复已确认版本，或人工处理未发布记录。

## 4. 交付与可选测试

按 [交付和可选测试规则](../sync-galacean-assets/references/acceptance.md) 报告结果并询问用户。
本地资产的导入结构和依赖校验属于发布前检查，不能替代运行时测试。

不自动提交 Git、部署项目或修改用户正在编辑的工程。
