# 交付与可选测试

## 发布检查

自动检查以下结果，无需再次请求用户确认：

- CDN 回读的文件长度和 SHA-256。
- 指定来源的 CORS 响应。
- 召回目录构建结果。
- 项目 `catalog.json` 中的 `manifestUrl`。

不能只凭 HTTP 200 判断发布成功。
发布检查不证明渲染、玩法或真实 LLM 任务已经通过。

## 询问是否测试

发布成功后，通过 `request_user_input_async` 弹出测试选择卡片。提供“需要，开始测试”和“暂不测试”选项。工具不可用时才使用普通消息询问。

卡片使用以下提示：

> 已发布 N 个资产。是否需要我自动测试这些资产的召回和使用效果？预计需要 X～Y 分钟。

N 只包含本批已发布的资产，不包含失败或延后项。另行说明复用数量和失败项。
根据资产数量、类型和环境启动成本估算时间。无法可靠估算时，省略预计时间。
用户已在本轮明确要求测试时，直接测试，不重复询问。
否则，只有用户选择需要后，才启动项目、真实模型或浏览器。

## 执行测试

使用当前项目的调试 Skill。在独立测试项目中串行检查：

1. 使用自然语言搜索本批资产。
2. 读取完整描述，核对名称、来源路径和 CDN 地址。
3. 导入资产。
4. 检查适用的使用方式和呈现效果。
5. 需要验证持久化时，检查保存和刷新结果。

使用当前 RetrievalClient。优先复用已有调试环境。
最多启动一个浏览器实例和一个前端端口。
不要修改用户正在编辑的工程。

测试范围限于本批资产。只测试部分资产时，报告覆盖数量。
测试失败不等于发布失败，应分别报告。
用户不需要测试时，报告“发布及完整性校验通过，项目实际使用未验收”。
