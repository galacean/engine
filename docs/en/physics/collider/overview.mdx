A Collider ([Collider](/apis/core/#Collider)) is a component that gives an Entity a collision shape. Each shape type is its own component:

| Component | Shape | Notes |
| :-- | :-- | :-- |
| [**BoxCollider**](/apis/core/#BoxCollider) | Box |  |
| [**SphereCollider**](/apis/core/#SphereCollider) | Sphere |  |
| [**CapsuleCollider**](/apis/core/#CapsuleCollider) | Capsule |  |
| [**PlaneCollider**](/apis/core/#PlaneCollider) | Infinite plane facing the Entity's local +Y axis | Static or kinematic only |
| [**MeshCollider**](/apis/core/#MeshCollider) | Convex hull or triangle mesh built from a mesh | Triangle mesh (`convex = false`) is static or kinematic only |
| [**CharacterController**](/apis/core/#CharacterController) | Capsule with its own movement algorithm | See [Character Controller](/en/docs/physics/collider/characterController) |

## Static or Simulated

Whether a Collider moves with physics is decided by the hierarchy, not by the Collider itself:

- **Static**: a Collider without a [Rigidbody](/en/docs/physics/collider/rigidbody) on its Entity or any ancestor is static. It follows its own Entity; changing the Entity's transform moves (teleports) it.
- **Owned by a Rigidbody**: the nearest Rigidbody on the Collider's Entity or its ancestors owns the Collider, and the Collider moves with that Rigidbody. `collider.attachedRigidbody` returns this owner, or `null` for a static Collider.

To build a compound shape, add several Collider components to the same Entity, or put them on child Entities under one Rigidbody. A nested Rigidbody starts its own group: Colliders below it belong to it, not to the outer Rigidbody.

[PlaneCollider](/apis/core/#PlaneCollider) and a [MeshCollider](/apis/core/#MeshCollider) with `convex = false` can only be static or belong to a kinematic Rigidbody. Under a non-kinematic Rigidbody they are excluded from simulation and queries with a console error until the Rigidbody becomes kinematic.

### Disable vs. Remove

| Action | Result |
| :-- | :-- |
| Disable a Collider | The Collider leaves simulation and queries until it is enabled again |
| Disable the owning Rigidbody | The Rigidbody and all the Colliders it owns leave simulation and queries; they do **not** become static. Their `enabled` values are unchanged |
| Remove (destroy) the owning Rigidbody | The Colliders it owned become static, or join the next Rigidbody further up the hierarchy |

Component changes are collected and applied in one pass before each simulation step and before each query (raycast, shape cast, overlap), so the order in which you add or enable components does not matter.

## Shared Properties

All Collider components share these properties:

| Property | Description | Default |
| :-- | :-- | :-- |
| [**center**](/apis/core/#Collider-center) | Center of the shape in the Entity's local space, scaled by the Entity's signed world scale | (0, 0, 0) |
| [**isTrigger**](/apis/core/#Collider-isTrigger) | Whether the Collider is a trigger, which reports overlaps without a collision response. See [Collision Events](/en/docs/physics/collider/event) | false |
| [**material**](/apis/core/#Collider-material) | The assigned [physics material](#physics-material), or `null` to use the shared default material | null |
| [**collisionLayer**](/apis/core/#Collider-collisionLayer) | The collision layer of this Collider, a single layer only. See [Collision Layer](/en/docs/physics/collider/collisionLayer) | Layer.Layer0 |
| [**contactOffset**](/apis/core/#Collider-contactOffset) | Contact offset. Non-finite values throw; negative values are clamped to 0 | 0.02 |
| [**attachedRigidbody**](/apis/core/#Collider-attachedRigidbody) | Read-only. The Rigidbody that owns this Collider, or `null` | - |

Shape sizes follow the absolute values of the Entity's world scale, while `center` uses signed world scale so negative scaling mirrors offsets. Physics ignores shear, which can occur when an Entity rotates under a non-uniformly scaled ancestor. With logging enabled, the Collider warns once.

| Method | Description |
| :-- | :-- |
| [**getClosestPoint**](/apis/core/#Collider-getClosestPoint) | Returns the distance from a world-space point to the Collider and writes the closest point. Returns -1 when the Collider is not in simulation. Not supported by PlaneCollider, CharacterController, and non-convex MeshCollider |

## Shape Properties

### BoxCollider

| Property                                 | Description                                 | Default   |
| :--------------------------------------- | :------------------------------------------ | :-------- |
| [**size**](/apis/core/#BoxCollider-size) | Size of the box in the Entity's local space | (1, 1, 1) |

### SphereCollider

| Property                                        | Description                                      | Default |
| :---------------------------------------------- | :----------------------------------------------- | :------ |
| [**radius**](/apis/core/#SphereCollider-radius) | Radius of the sphere in the Entity's local space | 1       |

### CapsuleCollider

| Property | Description | Default |
| :-- | :-- | :-- |
| [**radius**](/apis/core/#CapsuleCollider-radius) | Radius of the capsule in the Entity's local space | 1 |
| [**height**](/apis/core/#CapsuleCollider-height) | Total height including both caps | 4 |
| [**direction**](/apis/core/#CapsuleCollider-direction) | The local axis the capsule is aligned with | CapsuleColliderDirection.Y |

### PlaneCollider

PlaneCollider has no shape properties. It is an infinite plane facing the Entity's local +Y axis; use the Entity's rotation to orient it. It can only be static or belong to a kinematic Rigidbody, and does not support `getClosestPoint()` (returns `-1`) or volume-distance queries.

### MeshCollider

| Property | Description | Default |
| :-- | :-- | :-- |
| [**mesh**](/apis/core/#MeshCollider-mesh) | The [ModelMesh](/apis/core/#ModelMesh) used for collision. Its data must stay accessible after upload, and a triangle mesh also needs indices; invalid meshes are excluded from simulation and queries until replaced with a valid mesh | null |
| [**convex**](/apis/core/#MeshCollider-convex) | Whether to use a convex hull generated from the mesh vertices. A non-convex mesh cannot be a trigger or belong to a non-kinematic Rigidbody; invalid combinations are excluded until resolved | false |
| [**cookingFlags**](/apis/core/#MeshCollider-cookingFlags) | Mesh cooking flags (`MeshColliderCookingFlag`) | Cleaning \| VertexWelding |

## Physics Material

- [**material**](/apis/core/#Collider-material): Gets or assigns a [PhysicsMaterial](/apis/core/#PhysicsMaterial) without creating or cloning one. Changes affect every Collider that references it. `null` selects the shared default material. Assigning a material that belongs to another Engine throws.

A cloned Entity's Colliders share the original material reference; assign `collider.material.clone()` or `new PhysicsMaterial(engine)` when a Collider needs an independent material. Release materials you create with `destroy()` once no Collider uses them. The shared default material needs no manual cleanup.

| Property | Description | Default |
| :-- | :-- | :-- |
| [**staticFriction**](/apis/core/#PhysicsMaterial-staticFriction) | Friction when the object is stationary | 0.6 |
| [**dynamicFriction**](/apis/core/#PhysicsMaterial-dynamicFriction) | Friction when the object is moving | 0.6 |
| [**bounciness**](/apis/core/#PhysicsMaterial-bounciness) | Restitution, between 0 (no bounce) and 1 | 0 |
| [**bounceCombine**](/apis/core/#PhysicsMaterial-bounceCombine) | How the bounciness of two objects is combined: Average, Minimum, Maximum or Multiply | Average |
| [**frictionCombine**](/apis/core/#PhysicsMaterial-frictionCombine) | How the friction of two objects is combined: Average, Minimum, Maximum or Multiply | Average |

## Script Usage

### Static Colliders

```typescript
import { BoxCollider, PlaneCollider, Vector3 } from "@galacean/engine";

// Without a Rigidbody here or on an ancestor, the wall is static.
const wall = rootEntity.createChild("wall");
const wallCollider = wall.addComponent(BoxCollider);
wallCollider.size = new Vector3(5, 3, 0.5);

const ground = rootEntity.createChild("ground");
ground.addComponent(PlaneCollider);
```

### Simulated Colliders

```typescript
import { BoxCollider, Rigidbody, SphereCollider, Vector3 } from "@galacean/engine";

const box = rootEntity.createChild("box");
box.transform.setPosition(0, 5, 0);
box.addComponent(Rigidbody);
box.addComponent(BoxCollider);

// The robot's Rigidbody owns both the body and head colliders.
const robot = rootEntity.createChild("robot");
robot.addComponent(Rigidbody);
const body = robot.addComponent(BoxCollider);
body.size = new Vector3(1, 2, 1);
const head = robot.createChild("head");
head.transform.setPosition(0, 1.5, 0);
head.addComponent(SphereCollider).radius = 0.5;
```

### Triggers

```typescript
import { BoxCollider, Collider, Script, Vector3 } from "@galacean/engine";

const zone = rootEntity.createChild("zone");
const zoneCollider = zone.addComponent(BoxCollider);
zoneCollider.size = new Vector3(4, 2, 4);
zoneCollider.isTrigger = true;

class ZoneScript extends Script {
  onTriggerEnter(other: Collider, self: Collider) {
    console.log(`${other.entity.name} entered ${self.entity.name}`);
  }
}
zone.addComponent(ZoneScript);
```

### Physics Material

```typescript
import { BoxCollider, PhysicsMaterial, SphereCollider } from "@galacean/engine";

const sharedMaterial = new PhysicsMaterial(engine);
sharedMaterial.dynamicFriction = 0.4;

const box = entity.addComponent(BoxCollider);
const sphere = entity.addComponent(SphereCollider);
box.material = sharedMaterial;
sphere.material = sharedMaterial;

// The box gets its own material so the sphere keeps using the shared settings.
const customMaterial = sharedMaterial.clone();
customMaterial.bounciness = 0.8;
box.material = customMaterial;
```

## Best Practices

- Prefer the simplest shape that fits: boxes, spheres and capsules are cheaper than mesh colliders.
- Use a convex MeshCollider for moving objects; use a triangle mesh (`convex = false`) only for static or kinematic geometry.
- Keep objects that never move free of a Rigidbody so they stay static.
- Use triggers instead of physical collisions when only overlap detection is needed.

## Migrating from Shapes

Earlier versions attached shape objects to a `StaticCollider` or `DynamicCollider` component. Shapes are now Collider components, and motion comes from a separate Rigidbody. There is no compatibility layer.

| Before | Now |
| :-- | :-- |
| `DynamicCollider` | [`Rigidbody`](/en/docs/physics/collider/rigidbody) for rigid-body properties and motion |
| `DynamicColliderConstraints` | `RigidbodyConstraints` |
| `StaticCollider` | Removed: a Collider without a Rigidbody on its Entity or ancestors is static |
| `new BoxColliderShape()` + `collider.addShape(shape)` | `entity.addComponent(BoxCollider)`; likewise `SphereCollider`, `CapsuleCollider`, `PlaneCollider`, `MeshCollider` |
| Several shapes on one collider | Several Collider components on the same Entity, or on child Entities under the Rigidbody |
| `removeShape()` / `clearShapes()` / `shapes` | Removed: disable or destroy the Collider component |
| `shape.position` | `collider.center` |
| `shape.rotation` | Use the Entity's or a child Entity's `Transform.rotation` |
| `meshShape.isConvex` | `meshCollider.convex` |
| `capsuleShape.upAxis` | `capsuleCollider.direction` |
| `ColliderShapeUpAxis` | `CapsuleColliderDirection` |
| `MeshColliderShapeCookingFlag` | `MeshColliderCookingFlag` |
| `shape.material` / `shape.getInstanceMaterial()` | `collider.material` (assign `material.clone()` or `new PhysicsMaterial(engine)` for an independent material) |
| `shape.isTrigger` | `collider.isTrigger` |
| `joint.connectedCollider` | `joint.connectedBody` (a `Rigidbody` or `null`) |
| `onTriggerEnter(other: ColliderShape)` (Stay/Exit likewise) | `onTriggerEnter(other: Collider, self: Collider)` |
| `collision.shape` | `collision.collider` (the other Collider) and `collision.selfCollider` |
| `hitResult.shape` | `hitResult.collider` |
| `overlap*All()` returning `ColliderShape[]` | `overlap*All()` returning `Collider[]` |
| `characterController.addShape(capsule)` | `characterController.radius`, `height` and `center` |

To preserve existing gameplay, add twice the radius to authored capsule heights on both colliders and character controllers, and multiply authored angular velocities and angular velocity limits by `Math.PI / 180` to convert them to radians per second. `PhysicsScene.capsuleCast` and `overlapCapsuleAll` now align default capsules with the local Y axis (matching `CapsuleCollider` and `CharacterController`) instead of PhysX's native X axis, and negative world scale mirrors `Collider.center` offsets rather than discarding the sign.
