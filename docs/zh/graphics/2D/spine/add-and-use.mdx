本页介绍 Engine 2.0 的 Spine 运行时 API。编辑器的导入界面和资产命名见[资产导入](/docs/graphics/2D/spine/editor)；编辑器接入单独迁移。

## 安装与注册

业务代码使用 `@galacean/engine-spine` 提供的对象。根据资产导出版本，安装匹配的 `@galacean/engine-spine-core-3.8` 或 `@galacean/engine-spine-core-4.2`，并在应用入口、加载资产之前注册一次：

```typescript
import { registerSpineRuntime } from "@galacean/engine-spine";
import { Spine38Runtime } from "@galacean/engine-spine-core-3.8";
import { Spine42Runtime } from "@galacean/engine-spine-core-4.2";

registerSpineRuntime(new Spine38Runtime());
registerSpineRuntime(new Spine42Runtime());
```

两种资产可以在同一项目中共存。只使用一种版本时，只安装并注册对应后端。加载器读取资产头中的版本，选择匹配的后端；不会自动下载缺少的后端。仅导入后端包不会完成注册，也不需要给每个 Engine 重复创建后端实例。

## 加载和创建角色

下面的 `engine` 是已创建且具有活动场景的引擎实例。场景中的相机需要覆盖角色所在位置。

```typescript
import { SpineAnimationRenderer, SpineResource } from "@galacean/engine-spine";

const resource = await engine.resourceManager.load<SpineResource>({
  url: "/spine/character.skel",
  type: "Spine"
});
const entity = resource.instantiate();
engine.sceneManager.activeScene!.addRootEntity(entity);
const renderer = entity.getComponent(SpineAnimationRenderer)!;
renderer.state.setAnimation(0, "idle", true);
```

示例中的动画、皮肤、插槽和附件名称需要替换为资产中实际存在的名称。

| 输入            | 加载方式                                              |
| --------------- | ----------------------------------------------------- |
| `.skel`         | 可自动选择 Spine loader，也可显式指定 `type: "Spine"` |
| `.json`、`.bin` | 显式指定 `type: "Spine"`                              |

加载器支持 Spine JSON 和二进制骨骼数据，按内容识别格式。文件后缀用于选择 loader，不代表文件内容一定是二进制。

单 URL 加载时，优先使用资产依赖提供的 atlas 地址；没有依赖信息时推导同名 `.atlas`。例如 `character.skel?v=2` 对应 `character.atlas`，推导地址不会继承骨骼 URL 的查询参数。需要指定 atlas 或贴图地址时使用 `urls`：

```typescript
const explicitResource = await engine.resourceManager.load<SpineResource>({
  type: "Spine",
  urls: ["/spine/character.json?v=2", "/spine/character.atlas?v=3", "/spine/body.png?v=4", "/spine/weapon.png?v=5"]
});
```

通常只需提供骨骼和 atlas，贴图会根据 atlas 页名加载。显式贴图地址应与 atlas 页名匹配；贴图被重命名而无法按页名匹配时，使用列表中对应页位置的地址。请求仍使用完整地址。

`SpineResource` 共享骨骼数据、皮肤、混合配置和贴图；每次 `instantiate()` 都创建独立的骨骼姿态和播放状态。下面的示例沿用 `resource` 和 `renderer`。

## 编排动画、控制时间

`renderer.state` 是当前实例的 `SpineAnimationState`。用 `setAnimation` 替换指定轨道的动画，用 `addAnimation` 排队；引擎自动推进动画，不需要手动调用 `update`。

```typescript
resource.stateData.defaultMix = 0.2;
resource.stateData.setMix("attack", "idle", 0.15);

const state = renderer.state;
state.setAnimation(0, "attack", false);
state.addAnimation(0, "idle", true, 0);
```

轨道可以并行播放，按索引从低到高应用；高轨道上的动画可以覆盖或混合低轨道的姿态。混合时长配置属于资源，影响该资源的所有实例。

`setAnimation`、`addAnimation` 返回 `SpineTrackEntry`，表示一次播放安排。它可控制单条播放的混合权重、时间和回调。它不是可长期复用的动画资产。

```typescript
renderer.timeScale = 0.5; // 动画与骨骼时间（包括 4.2 物理）统一减半。
const previousTimeScale = renderer.timeScale;
renderer.timeScale = 0; // 暂停时间推进，仍应用姿态和绘制。
renderer.timeScale = previousTimeScale;

const entry = renderer.state.getCurrent(0);
if (entry) entry.trackTime = 1.5; // 下一次更新时应用动画的 1.5 秒位置。
```

`state.timeScale` 和 `entry.timeScale` 是额外的动画时间控制，不缩放骨骼物理时间。通常使用 `renderer.timeScale` 即可。跳转动画时间不会重建物理模拟历史。

已知的播放顺序优先用队列；需要接收单次播放通知时使用 `entry.listener`：

```typescript
const attack = renderer.state.setAnimation(0, "attack", false);
attack.listener = {
  complete(entry) {
    console.log("完成一次播放", entry.animation?.name);
  },
  event(entry, event) {
    console.log("动画事件", event.data.name, event.stringValue);
  }
};
```

也可以使用 `state.addListener(listener)` 监听整个状态，并用 `removeListener` 移除。循环动画每完成一轮都会通知 `complete`。`dispose` 回调结束后，该 `TrackEntry` 失效，不应继续使用；动画事件值是可以保留的快照。命令产生的回调同步派发；命令返回后才设置的 listener 不会收到已经发生的 `start`。

## 皮肤、骨骼与插槽

`renderer.skeleton` 是此实例的 `SpineSkeleton`。切换皮肤后，恢复插槽初始姿态，使附件使用新皮肤的配置：

```typescript
renderer.skeleton.setSkinByName("winter");
renderer.skeleton.setSlotsToSetupPose();
```

通过资源创建组合皮肤，再加入同一资源里的皮肤：

```typescript
const outfit = resource.createSkin("outfit");
for (const name of ["base", "hair/brown", "clothes/winter"]) {
  const skin = resource.skeletonData.findSkin(name);
  if (skin) outfit.addSkin(skin);
}
renderer.skeleton.setSkin(outfit);
renderer.skeleton.setSlotsToSetupPose();
```

皮肤属于资源，可以被它的多个实例共享。不能跨资源组合皮肤。使用 `findBone(name)`、`findSlot(name)` 获取稳定复用的实例对象；名称不存在时返回 `null`。

```typescript
const weapon = renderer.skeleton.findSlot("weapon");
if (weapon) {
  weapon.setAttachment("sword");
  weapon.setAttachment(null); // 隐藏附件。
  weapon.setToSetupPose(); // 恢复初始配置。
}
```

附件名称从当前皮肤查找，并回退到默认皮肤。`skeleton.slots` 按初始顺序排列，不随动画绘制顺序变化。骨骼的局部变换可读写，但动画驱动的属性会在动画应用阶段被重新赋值。

公共 API 提供皮肤组合和按名称替换附件；原生 `TextureAtlas`、`RegionAttachment`、`MeshAttachment` 不属于这套公共接口。额外加载 atlas 并直接修改原生 attachment 的旧示例不适用于本版本。

## 材质与透明度

同一引擎中的角色默认共享 `SpineMaterial`。使用 `setMaterial(material)` 设置默认材质，或用 `getInstanceMaterial()` 获取独立副本。`setMaterial(0, material)` 与默认材质对应；数字不是插槽编号或内部绘制批次编号。

按插槽覆盖材质时，传入这个角色自己的 `SpineSlot`：

```typescript
import { SpineMaterial } from "@galacean/engine-spine";

const material = new SpineMaterial(engine);
const weapon = renderer.skeleton.findSlot("weapon");
if (weapon) {
  renderer.setMaterial(weapon, material);
  renderer.setMaterial(weapon, null); // 移除覆盖，恢复默认材质。
}
```

`new SpineMaterial(engine, customShader)` 支持自定义 shader。启用 `renderer.tintBlack` 可渲染资产的双色 tint。自定义 shader 需匹配 Spine 顶点格式，并按批次读取贴图和混合参数；使用内置混合参数时，在线性空间完成 tint 后，将最终 RGB 乘最终 alpha。详细输入见 [Spine 包说明](https://github.com/galacean/engine/blob/dev/2.0/packages/spine/README.md#materials)。

alpha 编码属于 atlas 页。优先导出带颜色扩边的 Straight Alpha 贴图；loader 按 atlas 的 `pma` 信息识别，未提供时按 straight 处理。旧资产缺少元数据，或导入流程已转换贴图时，可以在首次加载前指定：

```typescript
const legacyResource = await engine.resourceManager.load<SpineResource>({
  url: "/spine/legacy.skel",
  type: "Spine",
  params: { alphaMode: "premultiplied" }
});
```

`alphaMode` 也可以按 atlas 页名配置。ResourceManager 按 URL 缓存资源，因此更换同一 URL 的加载参数不会重新转换已缓存资产。RGBA8 PMA 页会转换为独立的 straight-alpha 贴图；压缩 PMA 贴图需要在压缩前完成转换。组件上没有 `premultipliedAlpha` 开关。

## 物理能力和解绑

4.2 后端提供 Spine 物理约束；3.8 会明确返回不支持。先检查能力，再使用：

```typescript
const physics = renderer.physics;
if (physics?.supported) {
  for (const constraint of physics.value.physicsConstraints) constraint.reset();
}
```

`renderer.resource = null` 可清空资源。解绑后不要再访问 `state` 或 `skeleton`；重新绑定资源会创建新的实例状态，并清理插槽材质覆盖。实体销毁后，不要继续持有其播放对象来控制动画。
