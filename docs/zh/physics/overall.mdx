物理引擎是游戏运行时的核心组成部分。Galacean 通过统一的 [物理系统 API](https://github.com/galacean/engine/tree/main/packages/design/src/physics) 暴露物理能力，内置实现为基于 [PhysX.js](https://github.com/galacean/physX.js) 的 PhysX 后端。有关物理系统的详细设计说明，请参考 [设计文档](https://github.com/galacean/engine/wiki/Physical-system-design)。

对于需要使用物理组件或 `InputManager` Raycast 拾取的场景，需要在使用前初始化物理后端：

- [physics-physx](https://github.com/galacean/engine/tree/main/packages/physics-physx)

开发者可以在 [主菜单](/docs/interface/sidebar) 界面打开的 **项目设置** 面板中设置物理后端。

## 脚本使用

```typescript
import { WebGLEngine } from "@galacean/engine";
import { PhysXPhysics } from "@galacean/engine-physics-physx";

const engine = await WebGLEngine.create({
  canvas: htmlCanvas,
  physics: new PhysXPhysics()
});
```

默认情况下，`PhysXPhysics` 加载 npm 包自带的运行时。自行托管构建产物时，按入口保留对应的相对路径。

- `dist/browser.js` 和 `dist/browser.min.js`（UMD）从脚本同级的 `./libs/` 加载。
- `dist/module.js`（ESM）和 `dist/main.js`（CommonJS）从相对入口的 `../libs/` 加载，即包根目录下的 `libs/`。

使用 Vite 开发时，将 `@galacean/engine-physics-physx` 加入 `optimizeDeps.exclude`，使资源按包内路径解析。

专用模块 Worker 和 Node.js 默认使用包内的 `.mjs` 加载器。网页和经典 Worker 使用 `.js` 加载器。经典 Worker 通过 `importScripts()` 加载 UMD 时需要显式指定加载器 URL。

要从其他位置加载运行时，在构造函数的第二个参数中用 `wasmModeUrl` 指定标准版，用 `wasmSIMDModeUrl` 指定 SIMD 版。将同一发行版的 `.wasm` 放在对应加载器的同一目录下。

## 后端说明

PhysX 依赖 WebAssembly。`Auto` 在支持 SIMD 时选择 SIMD 构建，否则选择标准构建。启动时只加载所选模式的 JavaScript 加载器和配套的 WASM，压缩前合计约为标准版 2.5 MiB、SIMD 版 3.0 MiB。

| 功能           | physics-physx |
| -------------- | ------------- |
| 碰撞检测       | 支持          |
| 物理效果及反馈 | 支持          |
| 连续碰撞检测   | 支持          |
| 关节系统       | 支持          |
