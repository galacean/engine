# Merge dev/2.0 into feat/migrate-2.0

## Context

- Target branch before merge: `feat/migrate-2.0` at `4dab08da528bb5284b17afdfbabfe3f95aa7832b`.
- Incoming branch: `origin/dev/2.0` at `8e114779815954d3a62c7e8dd5758d0e076b3111`.
- The branches had independently evolved clone, physics, mask, resource-loading, shader, and particle code.

## Decision

Use the `dev/2.0` clone protocol as the canonical architecture:

- `CloneDecorators`, `ICloneHook`, and `_onClone` replace `CloneManager`, the old `CloneMode` location, and `_cloneTo`.
- The canonical `Clone.test.ts` replaces the obsolete `CloneManager.test.ts`.

Preserve the migration branch's non-conflicting runtime behavior:

- virtual-resource registration and URL mapping;
- transactional mesh-collider recooking and native attachment ownership;
- kinematic transform synchronization;
- shared mask rendering and UI clipping;
- text outline/shrink behavior;
- Spine and migration-specific runtime compatibility.

Keep all workspace package versions at `0.0.0-experimental-2.0-migrate.4`. Merging upstream implementation changes must not imply that a new experimental package has already been released.

## Integration fixes

- Ported migration-only clone hooks and decorators to the canonical `_onClone` protocol.
- Kept `SpriteMask` on the migration branch's `MaskRenderable` abstraction instead of reintroducing duplicated mask state.
- Kept `Renderer` mask fields in declarations because `@galacean/engine-ui` subclasses consume them across a package boundary.
- Preserved `UIRenderer.raycastEnabled === false`, which was a migration-branch behavior change hidden by the clone conflict.
- Unified `MeshColliderShape` with the canonical collider-owned attachment state while retaining rollback on failed native recooking.
- Avoided copying automatically calculated `DynamicCollider` mass properties during cloning; copying them invokes mutation callbacks and emits false warnings. Manual values are still copied, while automatic values are recomputed from cloned shapes.
- Updated tests to the canonical `registerVirtualResources` API and restored imports lost in overlapping test edits.
