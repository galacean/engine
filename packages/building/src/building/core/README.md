# 建筑核心层

核心层只提供机制，不包含任何构件类型或风格知识。墙、屋顶、窗这些类型，以及它们之间默认使用的规则，都在上层通过注册接入。核心层不依赖 Engine，可以在主线程或 Worker 中运行，结果完全相同。

```text
应用层      风格预设、LLM 接口（墙高、坡度……这类友好参数）     ../application/
   ↓ 生成 BuildingCoreDraft 和渲染计划，并注册类型
构件类型层  几何生成器、铺设算法、连接规则、类型对默认规则、对等检测  ../partTypes/
   ↓
核心层      身份、种子、几何、单元、连接、派生、执行顺序、诊断     本目录
   ↓ 铺设单元
渲染适配    铺设单元 → 现有渲染输入；打包、预览、shader 原样复用   ../render/
```

## 概念

| 概念     | 类型                    | 说明                                                                            |
| -------- | ----------------------- | ------------------------------------------------------------------------------- |
| 组       | `BuildingGroupDef`      | 身份、随机根 `seed`、共享数据 `shared`、组级规则覆盖 `rules`                    |
| 构件     | `BuildingPartDef`       | 几何 × 铺设算法 × 铺设单元，加上身份和类型名                                    |
| 几何     | `BuildingGeometry`      | 同一个几何可以同时包含点、线、面；元素 id 在各种元素之间唯一                    |
| 修改记录 | `GeometryModification`  | 规则对几何的修改：删除元素、删除、增加或占用面上的区域、删除线上的区间、用平面裁剪单元 |
| 有效几何 | `EffectiveGeometry`     | 原几何加修改记录，用到时计算，不保存                                            |
| 单元原型 | `BuildingUnit`          | 资产引用、包围盒、pivot/position/rotation/scale/range、种子盐                   |
| 铺设算法 | `LayingAlgorithm`       | 有效几何 + 单元原型 + 参数 → 铺设单元                                           |
| 布局     | `PartLayout`            | 铺设算法对一个构件的布局：单元槽位数量和少量布局数据；设计结果只保存它          |
| 铺设单元 | `LaidUnit`              | 按需由布局展开的一个单元：key、种子、坐标系、尺寸、伸缩倍数、矩阵、参数；不保存 |
| 连接     | `AttachDef` / `JoinDef` | 依附（有方向，宿主 1..n）/ 对等（对称，可以自动检测）                           |
| 规则     | `ConnectionRule`        | 读原几何；输出修改记录、派生构件、派生连接、诊断                                |
| 诊断     | `BuildingDiagnostic`    | 失败不抛出，也不静默；其他构件照常生成                                          |

## 执行顺序

1. **组和基础构件：** 参数、`unit` 和 `algorithm` 里写成 `{ "@shared": "name" }` 的值，从组的 `shared` 中读取。
   - `@shared` 旁边的其他键覆盖共享对象的同名键，只覆盖一层。例如 `{ "@shared": "house", side: 0 }`。
   - 共享值有覆盖键时，它必须是对象。
   - 同一个单元原型或算法只在组里存一次，多个构件引用它。
2. **原几何：** 依附连接的宿主先生成，被依附构件后生成，被依附构件可以引用宿主的几何。依附关系成环时报告诊断。
3. **对等检测：** 只在基础构件之间进行。显式写出的 join 优先。
4. **规则逐层执行：** 每层按连接 key 排序。派生连接放到下一层执行，层数超过 `maxDepth` 时报告诊断。
5. **有效几何 → 铺设单元：** 矩阵 = 落位坐标系 · T(position) · R(rotation) · S(scale ⊙ 伸缩倍数) · T(−pivot 点)。

## 选择铺设算法

铺设算法像 Tween 的 ease 函数：内置一组常用算法，也可以注册自己的算法，选用方式完全一样。

- **不指定时的缺省：**
  - 点：每个点一个单元，即 `placeAtPoints`；
  - 线：每条直线段一个单元，伸缩到段长，即 `alongCurves`，参数为 `perSegment`、`stretch`；
  - 面：必须指定，不指定时报告诊断。
- **算法说明：** 每个算法带 `info`，包括接受的几何（`accepts`）、一句话描述（`summary`）和参数说明（`params`）。`describeLaying(registry)` 列出全部算法。算法和构件的几何对不上时，报告诊断，不会换成别的算法。
- **自定义的两种写法：**
  - **简单写法：** `simpleLaying(info, context => units)`。一个函数返回全部单元，核心层在 CPU 上整体运行，`info.cpuOnly` 为 true，不能交给 GPU。
  - **完整写法：** 写 `plan` 加 `unitAt`，见下一节。每个单元可以单独计算，内置算法都用这种写法。

## 布局与展开

铺设算法分两步：

1. `plan(context)`：每个构件运行一次，返回 `{ count, data }`。`count` 是单元槽位数量上限，`data` 是 `unitAt` 需要的少量布局数据，必须是纯 JSON，大小不随单元数量增长。
2. `unitAt(context, data, index)`：纯函数。一个槽位得到一个单元，或返回 `undefined` 表示空槽位。槽位之间互不依赖，可以并行计算。

设计结果只保存布局（`ResolvedPart.layout`），不保存单元。需要单元时用 `expandPart` 或 `expandUnits` 按需展开：测试、查询和兼容适配在 CPU 上展开，渲染以后在 GPU 上按同样的槽位展开。设计阶段默认把每个单元展开一次，检查 key 唯一和伸缩范围后丢弃；另有路径做同样检查时，可以传 `validate: false` 跳过。

## 环境接口

`designBuildingCore(draft, registry, { environment })` 的 `environment` 是建筑向外部世界提出的查询，目前只有地面高度 `ground(x, z)`。

- 它只是接口：由地形系统实现并传入，建筑系统不采样、不缓存、不平整地形，也不做 snap（snap 是 LLM 工具）。
- 几何生成器从上下文的 `environment` 读取；曲面类型在计算坐标系时也会拿到它。
- 必须是纯函数：同样的输入在主线程和 Worker 里都给出同样的结果。草稿里不保存它。

## 单元原型

| 属性       | 维度 | 取值                           | 作用                                           |
| ---------- | ---- | ------------------------------ | ---------------------------------------------- |
| `pivot`    | 三维 | 归一化，相对包围盒，缺省为中心 | 单元上落在落位点的那一点；同一原型的单元都一样 |
| `scale`    | 三维 | 倍数                           | 把原始资产缩放到建筑里合适的大小               |
| `range`    | 三维 | 归一化伸缩倍数 min/max，缺省 1 | 算法能在缩放后尺寸上伸缩的范围                 |
| `rotation` | 三维 | 欧拉角（度）                   | 局部朝向                                       |
| `position` | 三维 | 米，落位坐标系                 | 局部偏移                                       |

铺设算法读取单元的尺寸，只在 `range` 内伸缩，不定义单元。没有“刚性单元”这一类：`min` 等于 `max` 的轴就不能伸缩。伸缩超出范围时，核心层报告诊断，整个构件不发布，不会悄悄截断。

算法输出每个铺设单元的实际尺寸（米，单元局部轴），核心层换算成伸缩倍数检查范围。截短后低于范围下限的单元，内置算法直接不铺。

内置算法的约定：

| 算法          | 参数         | 行为                                                 |
| ------------- | ------------ | ---------------------------------------------------- |
| `surfaceGrid` | 缺省         | 单元首尾相接；只有闭合曲面会伸缩铺满周长             |
|               | `cell`       | 固定间距，只调整间隙                                 |
|               | `stagger`    | 奇数行错开的比例                                     |
|               | `trim`       | 越过曲面边界的单元截短到边界内，而不是丢弃           |
|               | `gap`        | 相邻单元之间留缝，缝宽不超过跨度的 1/5               |
| `alongCurves` | 缺省         | 单元首尾相接，范围允许就伸缩铺满                     |
|               | `spacing`    | 固定间距，只调整间隙                                 |
|               | `perSegment` | 曲线的每一条直线段放一个单元，例如两根立柱之间的横栏 |
|               | `stretch`    | 单元伸缩到所在段的长度（减去 `gap`）                 |

`surfaceGrid` 在每个单元的 `params.uv` 里给出中心的曲面参数，`alongCurves` 在 `params.s` 里给出弧长参数，供渲染适配使用。

随机数按粒子系统的方式分通道：`seed(key, channel)` / `random(key, channel)`。每个随机属性（尺寸、色调、变体……）用自己的通道，互不影响；与粒子不同的是，种子由 key 推导，不依赖铺设顺序。

规则的选择顺序：连接上写的 `rule` → 组级覆盖（依附看被依附构件所在的组，对等看双方所在的组，两组冲突时报告诊断）→ 类型对默认 → 都没有则报告诊断。`none` 表示不处理。

## 三条性质

| 性质 | 做法 | 测试 |
| --- | --- | --- |
| 确定 | 只用整数哈希和固定多项式三角函数，不使用 `Math.random`、`Math.sin`；所有集合按 key 排序 | `CoreDeterminism.spec.ts`：重复构建、打乱输入顺序、黄金种子值 |
| 自由 | 几何生成器、曲面、算法、规则、检测器都通过注册接入；内置项和自定义项走同一条路径；每个注册表实例相互独立 | `CoreConnections.spec.ts` 中的类型层完全在测试里注册 |
| 稳定 | 种子由身份 + 局部 key 推导，铺设单元的 key 按自身坐标编号；编辑只影响相关的单元；同一 id 不能重复注册 | 移动窗时，远处的砖 key、种子、矩阵都不变 |

“不含领域词”和“不引用核心层以外的模块”由 `CoreLayering.spec.ts` 检查。

## 约定

- **身份：** key 是规范化的 JSON。作者构件为 `["p", id]`；派生构件为 `["d", 连接key, localId]`；对等检测出的连接 key 与双方顺序无关。
- **派生构件的组：** 依附时归被依附构件所在的组，对等时归 key 较小的一方所在的组；也可以由规则显式指定。
- **修改范围：** 规则只能修改本次连接的参与者。派生连接只能引用参与者，或者同一次规则结果里派生出的构件。
- **单个依附：** 一个构件最多是一个依附连接的被依附方，但这个连接可以有多个宿主。
- **曲面参数：** 内置曲面（`extrusion`、`plane`）的 u、v 以米为单位。点所在坐标系的 x、y 分别对应宿主曲面的 u、v。
- **旋转顺序：** 欧拉角顺序与 Galacean `Transform.rotation` 相同。

## 当前范围

- **已实现：** 本目录的全部机制，以及测试中的最小类型层：开洞、相交避让并派生接缝、二级派生、多宿主。
- **已接入：** 独立墙、栅栏、房屋（墙、屋顶、腰线、抹灰、门窗壁灯、相连的房屋）走 应用层 → 类型层 → 核心层 → 渲染适配（`../render/CoreBuilding.ts`）。各阶段与线上的对比见 [../MIGRATION.md](../MIGRATION.md)。
- **GPU 铺设原型：** `../render/GridUnitKernel.ts` 用 TransformFeedback（只支持 WebGL2）按槽位直接生成线上 64 字节砖块记录，CPU 只保留布局（约 260 字节）。`world/demos/building-core-preview/gpu.html` 在 8 米、100 米、1000 米三种墙上和 CPU 参考展开逐字节对比。目前只支持平地、无洞口的 `groundStrip` 立面上的 `surfaceGrid`，`draw.html` 把 GPU 生成的记录在显存内拷进砖块记录纹理，由线上砖块 shader 绘制，画面与 CPU 上传的结果相差在逐帧渲染噪声之内。砖块 LOD 仍读取 CPU 上的记录。
- **未接入：** Source 存档、Worker 调度、Mesh 曲面、UV 铺设。
- **删除和占用：** `removeArea` 表示曲面在这里不存在（如开口）；`reserveArea` 表示曲面仍在，但被其他单元占用（如转角石），铺设的单元要避让。
- **继承：** 曲面元素可以声明 `inherit: [{ host, element, offset }]`，表示它延续宿主的某个曲面：宿主元素上的删除、增加和占用按偏移量复制到这个元素上，排在它自己的修改之前。`host` 是依附连接的宿主序号。
- **真实范围和到边缘距离：** 曲面类型可以提供 `region`，给出比定义域矩形更小的真实范围；`EffectiveSurface.edgeDistance(u, v, limit)` 返回到真实范围边界或删除区域边界的距离，闭合曲面的接缝不算边界。
- **连续单元：** 内置铺设算法 `coverSurfaces` 为每个曲面元素放一个覆盖整个有效曲面的单元，渲染器按有效曲面画它，例如抹灰。
- **裁剪平面：** `clip` 修改给元素加一个平面 `[nx, ny, nz, d]`（构件局部坐标，单位法向）。铺在该元素上的单元保留 `n·p + d ≥ 0` 的一侧，切割由渲染完成，元素本身形状不变。`EffectiveGeometry.clips(id)` 按修改顺序返回这些平面。屋顶斜脊用它把两侧瓦片切齐。
- **待实现：** 把删除区域作为裁剪区域交给渲染。
- **已知近似：** 判断一个区域是否落在“原面加若干新增区域的并集”里时，只检查四个角和中心点；删除区域的判断是精确的。
