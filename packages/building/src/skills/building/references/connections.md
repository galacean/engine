# 连接

草稿里的连接由生成器写出，常见的有：

- 屋顶依附墙（`attach`）：坡面和屋面从墙顶起铺。
- 挂件依附墙或屋顶（`attach`）：从宿主切掉洞口，必要时派生小屋顶。
- 抹灰、腰线依附墙（`attach`）：继承墙上的洞口。
- 台基、墙、女儿墙之间的对等连接（`join`）：由检测器自动找出，例如两栋房屋相交、两个女儿墙相接。

连接端点必须是存在的构件。规则由构件类型对决定，连接里可以用 `rule` 覆盖，`"none"` 表示不运行规则。

## 派生构件

规则可以修改宿主（例如切掉洞口）并派生构件（例如转角石、接缝石、斜脊、老虎窗的小屋顶）。派生构件的身份由连接和它在规则里的名称决定，不写回作者构件或存档。移走邻居后，派生构件自然消失。

## 验收

检查多个视角、窗口范围、墙角和屋檐，并验证移动、分离和删除。数值或截图验收要给出具体的案例范围。一种形状通过，不能推导为任意建筑都能自动连接。

管理器生成遇到跨墙角、宿主被切除等安装失败时，会拒绝候选，并通过 `errors()` 报告。旧的可见结果可能仍被保留，所以 `manager.diagnostics()` 的已发布结果不能证明本次成功。

验收窗体时，必须检查非空的洞口和窗体输出，不能只比较两张都没生成窗户的图片。
