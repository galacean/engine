# 墙和开口

欧式生成器通过 attachments 指定窗口/门等配置，形成独立基础构件与 host 关系。墙挂点 u 为 [0,1) 周向参数，bottom/width/height 为米；kind/type 使用实际装饰目录。不要把 u 当米。

设计阶段共享开口和接触预留，实施阶段铺普通墙砖及连接砖；原始墙 support 不保存设计阶段算出的洞口缓存。移动/删除邻居后重新设计。

自定义 meshSurface 不会自动获得欧式 window-cottage 的开洞能力；通过自定义 connection rule 修改真实几何/铺设范围并派生窗框构件。不支持的内置规则明确报错。

墙挂点也可使用 `support.params.point: [x,y,z]`，表示宿主墙标准局部坐标中的实际挂接点。此时 spec 不保存 u/bottom；设计阶段通过墙面的真实折线投影得到它们。墙 Point 构件的节点可以相对宿主平移，平移会叠加到挂点并重新求解开口；旋转和缩放不属于这一挂接契约。初始世界将实际挂点保存在节点 position，support 的 point 为零偏移。旧的非零 point 加同框节点仍有效。屋顶仍使用 uv/bottom，不通过节点平移改安装位置。

普通墙窗、转角窗、门和壁灯的 `attachmentMount` 在设计时解算为精确 Point，开口和碰撞占位同时发布。`mountAttachment` 在实施时消费该 Point、资产选择及材质参数生成窗门网格；不在设计时生成普通附件的渲染网格。可以注册替代挂接算法，返回 `native-attachment/v1`；改放置位置不会自动移动既有墙洞，需同时修改作者挂点并重新设计。转角窗包含窗口和两根过梁的资产成员挂点，替代铺设算法需要处理所有成员。半老虎窗也走挂点与派生小屋面的分阶段流程；替代小屋面算法使用附件 `params.roofAlgorithm`，具体协议与开口约束见[屋顶](roof.md)。
