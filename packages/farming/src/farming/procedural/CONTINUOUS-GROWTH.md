# 农场连续生长实施与验收

> 历史记录：下文描述当时实现与当时测量，旧 API、旧源格式和模型路线已移除。当前契约见 [公共 API](../README.md)，当前格式见 [程序化植物](README.md)，本轮结果见 [验收记录](../ROUND-1-ACCEPTANCE.md)。本轮未执行或追加性能测试。

## 范围

以番茄落实五项：实例复用、连续进度映射与出苗、显示插值、可见性/频率/CPU 预算调度、静态拓扑与动态几何分离。保留其他作物的 GLB 阶段加载。GPU Morph 不属于本轮，只有实测无法达成可接受过渡时才需增加。

## 设计

- 玩法每秒推进，进度来自 growthUnits/growthTarget。表现不写存档、不预测未来、不修改照料与收获规则。
- 表现绑定用阶段 ID 对应 age。番茄幼苗 20%→0、开花 60%→0.55、成熟 100%→1；出苗从幼苗阈值的 75% 开始（当前 15%），根部固定，逐渐展开。
- 作物实例身份跨玩法阶段保持不变；收获、移除、替换、释放时销毁。加载晚到必须核对请求与作物身份。
- 正常快照在一个结算周期内插值；初始化、外部存档刷新、离线追赶、大时间跳跃、成熟与后台恢复直接对齐；停长不外推。
- 单个统一更新入口。选中 20 Hz、近处 10 Hz、远处 2 Hz 上限；无变化/不可见/后台零网格更新。进入视野追齐；每帧 CPU 软预算 1 ms，优先级兼顾等待时间，不能饿死远处植物。
- 编译配方的连接索引、静态索引/UV/遮罩仅初始化一次；动态计算复用位置、法线和工作数组；同进度/株型零上传。
- 测量 CPU 计算与提交、实际 GL bufferSubData 字节、帧间隔及 JS 内存；不将 CPU 提交耗时称为 GPU 时间。

- [x] 初始化、成熟、离线恢复、后台恢复及时对齐；不改变存档/玩法结算。
- [x] 更新频率、预算、公平性、不可见/成熟零更新。

## 实现落点

| 模块                                           | 职责                                                       |
| ---------------------------------------------- | ---------------------------------------------------------- |
| `presentation/CropGrowthMapping.ts`            | 玩法进度到配方 age、出苗曲线、仅朝确认结果插值的显示时间线 |
| `presentation/CropGrowthScheduler.ts`          | 可见性、分频、CPU 软预算与等待优先级                       |
| `presentation/CropStagePresenter.ts`           | 作物实例身份、异步加载、跨阶段复用、移除/换种释放          |
| `procedural/core/PlantGeometryEvaluator.ts`    | 编译挂点与部件关联，复用位置/法线数组求值                  |
| `procedural/runtime/ProceduralPlant.ts`        | 静态 UV/遮罩与动态位置/法线分离，只上传动态缓冲区          |
| `demos/farming/first-person-farm/scene/FarmScene.ts` | 相机视锥和距离分类，每个渲染帧调用统一调度器               |

生成器保持固定拓扑，未出现器官缩为零。一次初始化后，实体、网格、材质和缓冲区都保持身份稳定。`geometry` 是会被下一次更新修改的借用视图。资源检查发现 ModelMesh 销毁仅释放缓冲区引用，因此植物销毁时还显式清除索引、销毁其拥有的顶点缓冲区和支架缓冲区；不调用全局 GC，以免影响其他素材。

## 2026-09-15 实测

环境：本机 Apple M5 Pro，Chrome 153，ANGLE Metal；开发构建，独立 640×480 CSS 像素渲染画布。每组先预热 20 帧，再连续渲染至少 180 帧且至少 3 秒，配方 age 从 0.31 朝 0.40 插值。除首株选中外，其余全部按近处可见处理，故 256 株比通常远近混合场景更重。未同时运行构建或单测。

| 株数 | 调度 CPU P95 | 帧间隔 P95 | 约 3 秒动态上传次数 | 动态上传量 | 一次性批量创建 |
| ---- | -----------: | ---------: | ------------------: | ---------: | -------------: |
| 16   |       0.8 ms |     9.2 ms |                 500 |   10.39 MB |         105 ms |
| 64   |       1.1 ms |     9.0 ms |               1,892 |   39.32 MB |         268 ms |
| 256  |       1.1 ms |     9.2 ms |               3,770 |   78.36 MB |         996 ms |

- 每株 866 顶点，每次实际 `gl.bufferSubData` 上传 20,784 字节（位置+法线），静态 UV/遮罩/索引零重复上传；生长期间没有 `gl.bufferData` 重新分配。
- 256 株在预算内平均约每株每秒 4.9 次更新；10/20 Hz 是上限，不是满负载保底。队列没有饿死的植株，测量结束时所有株已推进到 age ≥ 0.3946。每帧 1 ms 是软预算，本组最大 1.1 ms；64 株组最大 1.3 ms。
- 每株更新 CPU P95 约 0.2 ms。这是 JS 计算与上传提交耗时，不是 GPU 执行时间。帧间隔数据也不是完整农场、移动端或长期稳定性保证。
- 16/64/256 株分别占用 96/384/1,536 个植物 GL 缓冲区，全部释放后回到 0；异步晚到、移除后换种与 Presenter 销毁同样回到基线。
- 暖机后强制 GC 的 JS 堆为 35.12 MB；随后 16/64/256/256 株创建、生长、销毁后为 35.22/35.32/35.43/35.95 MB。此短测没有与植物数量对应的资源残留；小幅堆波动仍含调试器、引擎缓存和预览图片，不据此声称长期 JS 内存绝对不增长。
- 同一株番茄在玩法 40%/80%/100% 时，age 为 0.275/0.775/1，entity/mesh/material/buffer ID 均相同。40% 后一个正常的一秒结算，实际采样 age 依次为 0.2750、0.2756、0.2770、0.2775、0.2789、0.2800、0.2811、0.2825、0.2835、0.2842。
- 16% 玩法进度的出苗比例约 0.104，age 仍为 0，尚无动态网格上传；20% 完全出苗。收获后调度条目移除，仓库番茄加 1，重新加载保持结果。
- 从存档恢复 50% 番茄直接显示 age 0.4125；缺水推进 10 秒 age 和上传次数不变；浇水后恢复连续更新。相机转向其他田格后进度继续结算但网格不更新，回到视野一次追齐。
- 自动化浏览器启用焦点模拟，普通标签切换不能可靠产生 `document.hidden`。后台分支通过临时控制 `document.hidden` 在真实农场中验证，恢复前删除覆盖：隐藏期间更新计数保持 22，恢复后一次追齐至 23。该证据证明后台分支和恢复逻辑，不等同于原生标签/操作系统休眠验收。

原始记录与截图保存在仓库根目录 `output/playwright/continuous-*.json`、`continuous-farm-*.png` 和 `continuous-256.png`，不进入生产构建。

## 复现

先使用仓库正常流程准备 World Gallery，启动 3016 端口。`gallery:sync` 会触发开发服务重载，不要在浏览器测试或性能采样期间执行。

```sh
pnpm --dir world gallery:sync
pnpm --dir world/.materialized/engine/world-gallery typecheck:farming
pnpm --dir world/.materialized/engine/world-gallery test:farming
pnpm --dir world/.materialized/engine/world-gallery build:farming:all
```

三个浏览器检查脚本使用 Playwright CLI 的 `run-code --filename`，从仓库根目录运行，输出截图到 `output/playwright/`；检查过程只使用独立测试存档：

- `shared/farming/tests/browser/continuous-farm.check.js`：真实指针播种/浇水/收获、连续插值、身份、存档。
- `shared/farming/tests/browser/continuous-farm-idle.check.js`：缺水停长、恢复、视锥外零更新、受控后台分支。
- `shared/farming/tests/browser/continuous-benchmark.check.js`：16/64/256 株渲染、实际 GL 上传/删除、内存采样。

以上路径相对 `world/gallery/`。底层可复用浏览器入口为 `/shared/farming/tests/browser/runtime.html` 的 `runContinuousGrowthContracts(16|64|256)`；测试代码不被两个生产入口导入。

## 当前边界

- 本轮完成番茄接入；其他作物只有 GLB 内容时继续原表现。新的程序化植物可复用相同映射/时间线/调度/求值能力。
- 出苗是根部固定的幼苗缩放近似；没有模拟胚根、种皮脱落。
- 视锥判定使用当前农场作物的保守田格范围（根部以上 2 m）。更高或横向跨格植物需要在场景适配层调整包围范围；未做建筑遮挡剔除。
- CPU 分频更新满足本机当前番茄的观看需求；未实现 GPU 两帧形态插值。若近景加速生长仍能看到步进，可在此固定拓扑基础上扩展。
- 1 ms 预算限制生长更新，不包含首次创建。256 株同时首次生成约 1 秒，超大农场的批量创建分帧和材质共享仍是后续优化方向。
