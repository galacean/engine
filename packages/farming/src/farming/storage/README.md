# 实体仓储

固定容器是入库库存的唯一持久化来源，`FarmSnapshot.inventory` 由其完整内容求和；手持篮子中的待卸货内容属于 `FarmSnapshot.items`。卸货时分配设施、写入产物和清空手持篮子在同一个事务中提交；保存或分配失败时保留原库存和篮中内容。失败仍可能结算已经发生的生长时间，调用者应读回回执与状态。

## 初始化与空间

`FarmingService` / `FarmingAreaComponent` 省略 `plots`、提供 `initialLayout: { groundId, centerX?, centerZ? }` 时，生成 3×3 耕地（格距 1.25m），默认空推车与空篮子各一个。自定义布局可显式提供 `grid`、`plots`。初始化容器寻位失败时整体失败，不写入不完整的新农场。

`storageLayout` 可覆盖仓储地形、锚点、搜索半径/步长、间距与 `protectedAreas`。默认锚点位于田地西侧；搜索半径 12m、步长 0.5m，朝向 0°/90°，按距离、z、x、朝向稳定排列。完整容器外包围范围检查宿主覆盖、坡度（不超过 5°）、障碍、水域和草地/土壤表面。它与全部已注册耕地（包括空地和不可用地块）、宿主预留耕地保持 2m，与其他容器保持 0.5m；后续开垦也检查相同间距。宿主必须提供真实地形与障碍事实。

位置属于存档。已有容器不会因取货或添加其他容器重新排列；当前版本不做拖动、推车运输或地形编辑后的自动搬迁。

## 容量与数量

默认马车只有一辆。马车允许小麦、水稻等兼容作物混存，逻辑库存可超过显示容量，装满后不会自动生成新马车；没有马车时卸货返回 `NO_STORAGE_SPACE`，由用户手动添加。手动增车继续支持，先填已有车辆的显示份额，超额库存汇入最早车辆。仓储篮子仍保持单作物和硬容量：先填同种篮子，再填空篮，不足时自动寻找位置创建新篮子。

| 作物               | 容器 | 每容器容量 / 展示上限 |
| ------------------ | ---- | ---------- |
| 小麦、水稻         | 推车 | 合计展示60束，库存不限（安全整数范围） |
| 番茄、土豆         | 篮子 | 20 个      |
| 胡萝卜、萝卜、甜菜 | 篮子 | 16 根/个   |
| 葡萄               | 篮子 | 12 串      |
| 卷心菜             | 篮子 | 4 颗       |
| 甜瓜、南瓜、西瓜   | 篮子 | 2 个       |
| 油菜籽、葵花籽     | 篮子 | 20 份      |

`FarmingDefinitionSet.storage` 定义容器及逐作物容量；自定义作物必须提供映射。静态容器资源与内腔尺寸以默认素材为准，不能把碰撞占地改小于真实模型。默认显示器支持现役 14 种产物，扩展物种需同步提供程序化产物配方。

`setContainerCount({ typeId, count })` 设置当前总数及保留数量，0 合法。马车缩减可将全部作物混存合并进最早保留车辆，有库存时至少留一辆；仓储篮子仍检查硬容量。`withdrawInventory({ itemId, quantity })` 从较新容器扣减完整库存，包括未展示部分；取空后回收超出保留数量的空容器。不会在每次收获后撤销用户刚增加的空容器。

`getContainers` 的 `contents` 提供完整逐作物库存，`quantity` 是总数；混装车辆的 `cropId/itemId` 为 null，按 cropId 过滤会匹配任一内容。马车 `capacity=null`、`displayCapacity` 为展示上限，不能从模型数量反推库存。状态中主作物沿用 `cropId/itemId/quantity`，其余作物只存入可选 `additionalContents`，各份库存只有一个来源；查询汇总不另行持久化。

原生入口为 `getContainers`、`getInventory`、`setContainerCount`、`withdrawInventory`，通过 `FarmingAPI.execute` 调用。它们使用现有版本、命令 ID、持久化和重放契约。自动增补没有合法位置返回 `NO_STORAGE_SPACE`；缩减容量不足返回 `CONTAINER_CAPACITY_INSUFFICIENT`；超量取货返回 `INSUFFICIENT_INVENTORY`。

## 渲染与存档

原生区域默认拥有 `StorageContainerPresenter`；纯领域服务不依赖引擎，显式无渲染宿主可使用 `storagePresentation: false`。渲染只消费已提交快照和事件，不在帧循环轮询库存。每辆马车合计最多创建60份产物实体；定制容量更小时按兼容作物的最小容量显示。超额库存只增加数值，不创建隐藏实体、Renderer或额外马车；取货后按剩余库存重新选择可见内容。篮子仍逐份显示，同物种共享网格与材质。数量标签区分真实库存和展示数量；视图加载失败不回滚已提交库存，可查询 `area.storagePresenter.snapshot()` 并调用 `prepare()` 重试。

静态推车与篮子来自 Farmlands，来源和尺寸见 [资源说明](../assets/storage/README.md)。生长作物与收获物继续由程序化代码生成。手持收获篮子仍为容量20的持久道具，不受马车显示额度影响；独立的 HarvestBasketPreview 仅为动画预览。

小麦产物使用独立的程序化麦束：收拢的弯曲麦秆、成对层叠的尖麦粒、细麦芒与两道束绳，共764个三角形。麦秆、麦粒和束绳使用同一网格内的顶点颜色，不加载作物GLB或新增纹理；手持收获反馈和仓储共用该配方。默认一辆马车中的小麦几何最多45,840面。车内按固定展示槽位摆放，麦束小幅错开方向、相邻层反向，缩放预留旋转包围范围；混装按各列下层货物的实际高度堆放，取货后更新受影响槽位的位置。

当前Schema 10保存容器身份、位置、朝向、主作物数量、可选混存条目、保留数量、规则签名与序列。已有同版本单作物及多车存档直接恢复，库存与位置保留，不自动删车；手动缩减时可合并库存。加载仍验证内容、总数和空间约束；不接受此前版本的快照。Scene/Prefab与IndexedDB使用同一快照，农场案例使用 `first-person-farm-storage-v1` 保存身份。

本次功能验证与复现命令见 [验收记录](ACCEPTANCE.md)。
