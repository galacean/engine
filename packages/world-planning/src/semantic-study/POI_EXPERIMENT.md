# POI 布局实验 · 可调二维规划

2026-09-18，当前结果替代此前独立分布、一村两崖及固定内容按钮版本。POI 只发布尺度、中心位置、所属陆域、较大级 POI 引用及内容引用；不拥有 Voronoi/cell 分区，占地由实际空间元素维护。

## 基线与入口

- 工作树 `engine-next-poi-layout-experiment`，分支 `codex/poi-layout-experiment`。原 `engine-next-seed-world-v2-layout-demo` / 4320 保持备份。
- 入口：`http://127.0.0.1:4321/demos/terrain/seed-world-planner/semantic-study/index.html?seed=7`。
- 1024 × 1024 米。左侧参数、中央彩色规划、右侧层级图层，顶部保留全图、俯视和白盒；F 聚焦，移除常驻底栏。

## 参数与数据职责

左侧保留全局规划 / 选中对象；全局按世界环境（陆域、地貌）、空间布局（POI、场所建筑、道路）、景观组织。语义输入写入 Recipe，实际轮廓、OBB、道路、端口与计数写入 Snapshot；URL 保存配置和局部覆盖。界面不以“默认”命名当前值。

- `poi-layout.json`：间距、内容预算、村庄范围/容积率/建筑尺度/朝向、地貌尺度、景观密度；`network` 暴露米制路宽、弯曲、连接冗余。
- `poi-buildings.json`：中型房舍组、小型独栋的数量预算、建筑间隙与组合尺度。复用同一建筑尺寸配置，不把它们归入村庄。
- `landform-recipes.json`：断崖、台地、峰群的权重和适用 POI 级别。同种子稳定；选中地貌编辑保留组合种类及落点。
- `road-network.json`：寻路步长、预算、净空、坡度限制与候选接入点数量。与面板语义参数分开维护。
- `landscape-contexts.json`：环境距离带、优先级、密度范围、树石比例，以及物种海拔、坡度、局部高差限制。修改道路周边密度使用 Recipe 的 `landscape.contexts.road`；修改距离带使用这里的 `road.distanceM`。
- `units/*.json`：建筑、道路、树石等米制尺寸和基础约束。

生成顺序：陆域 → 大中小 POI → 村庄/地貌/房舍 → 建筑实例覆盖 → 全局道路 → 景观 → 发布检查。面板和绘图只读写配置与快照，不生成几何。

## POI 与图层

`PoiDistribution` 按大型→中型→小型补点；后一级避让之前所有点。当前级最小间距约束当前级与已放置各级之间的中心距离。较细级调整不动较大级；较大级调整会重新求后续各级。

间距范围决定有限最远点采样的停止阈值，收紧当前范围会增加当前点数。最大剩余间隙按 16 米候选网格、当前级与之前各级的合并点集测量；不是道路行走距离。达到预算会报告，不伪造满足。没有细胞多边形。

标记大/中/小直径约 19.5 / 10.4 / 4.6 屏幕像素，颜色不同；仅未填充点保留分级符号，默认隐藏、由辅助开关打开。已填充点显示实际元素，不加圆圈。符号大小不等于占地范围。

`PlanningLayerTree(plan)` 从 `PoiSite.memberIds` 和模块成员关系构造当前实例层级；父节点遮罩所有后代并禁用子开关，重新打开恢复子项偏好。右侧不再维护村庄/断崖特制内容卡。对象仍直接点选并用 F 聚焦。图层操作不重新生成空间内容。

## 道路职责

建筑门、村口在 `PlanningPort.roadAccess` 声明需要接路、位置与出入口朝向，不预选目的地。`GlobalRoadNetwork` 汇总需求并选择可用 POI 节点，使用带种子扰动的连通树及可配置附加边决定拓扑，随后绕障寻路。连接冗余为零允许树状网络；没有强制全局环。

路宽进入实际完整轮廓净空，弯曲控制路径代价变化；复用已有关键点曲线生成器平滑，完整轮廓不合法时保留合法折线。道路图包含实际关键点、曲线分段导航连接和最终轮廓。节点必须位于可通行主连通域，避免选进封闭岩体中的孤立空地。

同一陆域内声明的入口需要连通。当前不跨海自动造桥，离岛独立建网；水、实心岩体与建筑为障碍。路宽/障碍导致不可达时拒绝此次修改并保留上一结果，不暗改宽度、移走建筑或强行穿越。局部编辑保留未受影响的既有边；端点变化或路径被新实体阻挡时，只重建相关路径并保留原连接关系。这仍是有界生成器，不是任意局部增量求解器。

## 景观与局部编辑

`ContextLandscape` 根据真实建筑/道路/地貌/POI 的环境距离带归属候选，读取地面海拔与周边 OBB 高差，按坡度、海拔与实例占地起伏抑制密度，再应用全局/环境密度。复用空间查询索引，避免长曲线引起全量边遍历。仅密度改变会保留已有候选位置；几何变化可能重算景观候选。

单栋可设置 X/Z 偏移、旋转和缩放；村庄可改范围与容积率；地貌可改长度、高度、朝向、起伏。使用原地貌生成器，增高也可能增加支撑占地。碰撞或越界会回退；不会为了局部修改搬走其他场所。

## 验证及范围

测试覆盖跨级避让、点数与间距、确定性、声明入口实际连通、中小型建筑、无强制环、路宽和弯曲几何变化、环境密度独立性、海拔坡度负控、局部修改与失败回退。具体测试和页面操作记录见 `V2_IMPLEMENTATION.md`。

当前仅有限内容组合；剩余 POI 为待填充点。村庄仍复用继承的内部道路/广场组合，未证明任意村落形状。峡谷河段已接入；花草及跨水桥梁尚未接入本入口。地貌是既有 OBB 组合，未实现侵蚀模拟或真实素材渲染。本轮验证二维布局和图层，POI 入口的白盒道路、水面使用独立同源曲面，可以随成员开关显示隐藏；美感由用户验收。

## 2026-09-18 白盒体量一致性

实体白盒由 `PlanningWhiteboxes` 直接适配规划快照；建筑、景观和岩体只使用 OBB 组合，拾取/渲染/漫游共用尺寸、朝向、底高。树不再使用椭球树冠及独立细树干；白盒按完整景观占地保守阻挡。地面、道路、水面继续使用同源轮廓以检查实际接缝，不套具象素材。网格着色器为1m细格、10m粗格。

素材替换的空间约定是尺寸包络、局部轴向和落地基准匹配这些 OBB；白盒不会保证任意未校准素材自动保持相同占地。连通验收从每一陆域同一根节点遍历实际道路，不能把村内与村外独立的连通图当作同一网络。

## POI 内容与参数入口（2026-09-18）

- `landform-recipes.json` 声明峡谷仅使用大型候选，台地/断崖使用中型候选；`poi-buildings.json` 声明中型房舍组；`poi-trees.json` 声明小型高树的占地、净空和高度倍率。`poi-layout.json` 保存全局预算及语义参数，可关闭村庄预算而保留其他类型。
- `PoiCanyon` 以种子生成的三次曲线驱动岸壁 OBB 和河流，复用 `WorldLayoutWater.riverSectionWidths` 与 `WorldRibbon`。河流发布水面/河床纵向高程；地形采样、白盒水面及缓存使用同一数据。当前是有限峡谷河段，不承诺跨地图水文或自动分汊。
- `PoiContents` 通过成员、owner 和 region 引用解析归属；右侧实例树和逐 POI 属性共用。场所内道路、建筑、河流、岩体和景观随各自 POI 显隐，全局路网单独显示。图层操作不重新生成世界。
- `SemanticEdit[poiId].landscape` 保存局部覆盖；密度、树高上下限、海拔/坡度上限以及各环境密度都有 UI。候选点与采样保持确定性，仅树高/密度编辑不移动其他 POI。高树主体先放置，再让全局道路避让；周边植被后生成。
- 点击实际元素或名称，在“选中对象”调整本体和所属 POI 景观；峡谷的河宽/弯曲等也有局部参数。全局参数面板提供同类粗粒度控制。


## 数量、密度作用域与定位（2026-09-18）

- `poiLayout.content.villageCount` 为显式精确数量（0–8）。旧配方的 `villageLimit` 仅作为兼容回退，不再承担显式数量的含义。初始村庄沿用已验证布局；追加村庄依次使用未被占用且实际轮廓可容纳的大型候选，避让现有地貌、房舍、主体树和场所道路。不改 POI 间距，不移动已有内容来凑数。
- 增加村庄后由全局道路系统连接入口，跳过旧的村间直连逻辑。新增村庄使用同一模块、建筑、端口、关系和局部建筑变换。道路和受影响周边景观仍会重算；本轮没有承诺数量编辑的路网局部不变。
- 独立数量检查比较请求与实际结果。有限候选不足，或实际道路/占地检查失败，保留上一有效快照并恢复 UI 原值。提示“现有候选找到”而不是声称地图的绝对空间容量。没有自动降低间距、补采大型点、缩小村庄或将其他内容换成村庄；未来可新增受约束的局部补点操作。
- `poiLayout.landscape.density` → `landscape.tierDensity[large|medium|small]` → `edits[poiId].landscape.density`，缺省继承，显式 0 有效；最终仍受道路/建筑/地貌距离带与海拔坡度约束。UI 与生成器共用 `poiLandscapeConfig` 解析。全局面板显示三级有效密度及恢复上级设置入口；点右侧实例可调单个 POI 的周边密度。主体高树不属于周边密度的候选集合。
- 右侧名称是独立聚焦按钮，使用同一个 F 定位函数；勾选控制显示，箭头控制折叠。小型树 POI 明列“主体高树”和“周边景观”，父级关闭仍遮罩全部后代。
- 颗粒度不是新的一套生成数据：内容目标（数量）、组合参数（村庄范围/容积率、POI 周边密度）、元素参数（建筑位移/旋转/缩放）最终仍写入同一配方与空间快照。目前没有接入自然语言解析器，“4 个村庄”对应的是公开参数 `content.villageCount = 4`。


## 具体元素、统一覆盖与选址证据（2026-09-18）

- 右侧层级增加实际建筑、道路、岩体、河流、景观叶子；点击地图时展开到具体元素并高亮，左侧同时显示所属 POI。几何选择 ID 与参数生成器 owner 分开；峡谷内岩体保持自身白盒拾取 ID，组合参数仍由峡谷负责。子节点按展开创建，避免一次创建全部景观 DOM。
- `ParameterScopes.resolveParameters` 统一按字段解析稀疏覆盖，缺省跟随、零值有效、嵌套字段独立。当前已接入景观、峡谷、村庄的参数解析，不宣称所有历史模块已迁移。种子/内容数量/POI 间距属世界规则；位移旋转缩放属实例操作，不能为每个参数强行增加全部作用域。物理检查仍在解析之后执行。
- 景观有效密度来自全局 → POI 级别 → POI 实例；道路/建筑/地貌/点位邻近带是环境系数，按配置距离带选择，再影响有效密度，并受海拔坡度等适生条件约束。原“POI 周边密度”更名为“点位邻近带密度系数”，避免与 POI 级别覆盖混淆。修复局部只改道路系数却同时复制其他环境值的错误；URL 现在只保存实际改动字段。
- 选址诊断保留独立于已发布快照的本次请求证据：全部大型候选、主陆域限制、180m 预筛选包络越岸、占用内容、实际轮廓越岸/碰撞、已放置数量。点击候选可聚焦其检查轮廓；预筛选失败不会冒充已检查实际村庄。
- 当前截图 seed=1 配方要求6村：18个大型点，1个离岛排除，12个180×180m方框预筛选越岸，仅5个进入并放置。左侧 poi-large-6/14 距海岸约59.2/57.3m；没有扫描点位之间的空地，不能据此断定地图只能容纳5村。本轮没有放松筛选、补点、缩放或挪动内容。


## 组件编辑器迁移（2026-09-18）

当前入口挂载 `spatial/SpatialEditor`：左 Hierarchy/系统页签，中预览，右 schema Inspector。原参数面板定义并入 `PlanningComponents`；Worker 与命令工具使用同一组件文档、求解与发布规则。支持存档/载入、撤销/重做、实例命名，新增岩石/树木/POI 的受约束事务。道路通过组件能力汇总入口、障碍与禁行域。层级树从生成实体归属及显示组件组织，不复制生成算法。

景观各级作用域已覆盖树高与环境等字段；具体树可记录独立尺寸覆盖。编辑失败不改变有效文档，删掉最后一个手工实体会使空间缓存失效。既有选址诊断、同源白盒与景观快速路径继续保留。架构边界、扩展方法、未实现能力和未来真实 query 评测见 [维护入口](../spatial/README.md)。
