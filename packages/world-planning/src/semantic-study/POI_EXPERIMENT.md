# POI 布局与二维规划

当前作者模型更新于 2026-11-06。本文源自 2026-09-18 的布局实验；原工作树、旧面板、URL 存档、数量限制及当时测试记录不再作为当前契约。架构与详细参数见 [空间框架](../spatial/README.md)，历史过程保留在 Seed Demo 的 V2_IMPLEMENTATION.md。

## 入口与作者数据

真实入口是 `world/demos/seed-world/index.html?seed=110513&debug=1`：左侧统一 POI 列表、中央地图、右侧 Inspector；选择 POI 后可调权重，F 聚焦。“生成 3D”把已提交快照交给原生 Seed 场景，不另造验收世界。

参数写入同一 PlanningDocument/项目作者资源；管理轮廓、当前中心、实际面积、OBB、道路和 active 状态属于派生结果。URL 支持当前世界参数和 v2 `poiRecipe` 配置，不代替项目存档。

## 统一候选与权重

- `distribution.spacingM` 控制候选布点间距，`minAreaM2` 控制最小有效管理面积。计算预算不冒充用户请求的精确 POI 数量。
- 每个候选保留稳定 ID、原始位置与独立 `poi.sizeWeight`。权重默认 1，是相对管理区偏好，不是面积、建筑或岩石尺寸倍数。
- 同一求解器计算当前中心、分区轮廓、有效面积和 active 状态；调整权重允许周围中心和边界共同响应。
- 休眠候选仍保留身份，列表标“未显示”，可再次选中调整恢复；不会因为未发布内容而失去作者入口。
- POI 管理区与内容占地分开。建筑、岩体和景观仍用各自的实际轮廓/OBB 做空间检查。

## 预览与提交

`PlanningSession.previewPoi` 是只读预览：只计算分区及锚点，不生成内容、不改变有效文档、不保存。滑条或数字输入实时投影当前预览，地图同时隐藏旧分区和旧锚点，避免叠影。松手、change 或 Enter 通过原有事务更新内容并保存；Esc/取消还原显示。切换选择、版本变化或关闭编辑器会清理旧预览。

白盒模式下先切回俯视再调整。数值非法、事务失败及保存状态沿用现有反馈；休眠不是错误，不显示“若干区域零面积”的告警。恢复默认使用 reset 清除单 POI 覆盖，不能用 set 1 冒充清除。

## 内容与图层

`space-rules.json.defaults` 提供统一组织抽样，`elementProfiles` 提供元素米制尺寸与表现绑定。配方不按 POI 等级准入；实际可放内容仍受可用区域、坡度、互斥、入口和道路条件约束。权重不直接缩放物体，也不保证指定成员数量。

`PlanningLayerTree` 根据稳定 POI、成员归属和显示组件构建统一树。父可见性遮罩后代，重新打开恢复子项偏好；图层控制不改变生成或存档。锚点符号统一，管理区使用同源分区；农场可以保留独立语义颜色。

## 景观与道路

景观继承顺序为世界 → 所属陆地区域 → 单 POI，缺省继承，显式 0 有效。道路/建筑/地貌邻近带是另一个空间影响机制；坡度、海拔、占地与物种规则仍由生态系统负责。休眠候选不充当活动生态来源，主体内容与周边景观密度分开。

道路消费有效 POI 的入口和实际内容占地，局部及全局连接共用发布的物理路网。道路模式、路宽、拓扑与桥梁的具体契约见空间框架；权重预览不提前重建道路。


## 验收边界

需要分别验证：拖动时邻区轮廓和锚点响应、preview 不写文档、松手提交一次、休眠恢复、reset、取消、旧请求隔离、重载重放、活动内容/道路/生态更新。有限 Seed 测试不证明任意布局可行；参数接受、几何正确、保存成功和真实页面视觉体验应分别报告。
