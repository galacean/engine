# 通用空间形状：从参考构图到语义生成

当前构图已获用户认可；这证明参考轮廓可以表达，尚不证明通用随机生成。本稿是下一阶段设计，除规划边界外尚未实现。

## 1. 根因与方向

当前 `BaseMapGenerator.ts` 的陆地、河流、连续山群、分叉山群仍来自指定锚点、固定分支和候选位置。加宽、弯曲、旋转改变的是同一结构；扩大滑杆范围会暴露穿插问题，不会自动产生新的布局。

推荐采用 **可组合的形状构造图 → 连续轮廓 → 统一空间查询 → 规划与栅格输出**。随机生成构造图和局部参数，局部编辑修改同一构造图。图片提取的轮廓也是输入之一，不能成为唯一模板。

“随意形状”的目标是在地图精度与复杂度预算内表达多连通、分叉、有孔洞、非对称的形状。有限几个标量不可能控制所有轮廓；需要可扩展的构造操作，但不要求用户逐点编辑。

## 2. 同一个内核，保留不同空间含义

| 表达 | 数据 | 用途 |
| --- | --- | --- |
| 点 | 位置、身份、附着关系 | 汇流口、入口、连接端点 |
| 线 | 开放/闭合曲线；节点与边组成的图 | 河网、山群轴线、以后加入的通路 |
| 面 | 多个外轮廓及各自孔洞 | 岛屿、河湖、山群用地、村落区域 |
| 体 | 占地面、高度描述、姿态及 OBB | 岩体、建筑占位；不能只用一条边界推断高度 |
| 关系 | 包含、邻接、汇入、跨越、避让、附着 | 约束接口与局部修改的依赖 |

形状内核不认识“村落必须是圆的”或“山群只能有三叉”。语义对象引用形状，并增加自己的含义：河流维护上下游关系；山群沿轴线组织岩体；村落管理建筑与预留空间。山群轴线并不自动代表可走路线。

区域边界、河流中心线和 OBB 也不能互相替代。中心线记录连接，水域面记录实际占地，OBB 记录单个体量的包围范围。

## 3. 结构、轮廓、细节分开控制

| 层级 | 可表达的控制 | 真实变化 |
| --- | --- | --- |
| 结构 | 分支数量、连接方式、分离区域数量、孔洞、开口 | 一整块变成双岛；单带变成分叉山群；增加一条汇入支流 |
| 轮廓 | 面积、长宽比、弯曲、左右宽度、分叉夹角、湾深、开口宽度 | 岛屿变狭长；河岸不对称；海湾深入；山肩展开 |
| 细节 | 圆润度、边界起伏幅度与尺度、最小特征尺寸 | 平滑拐角、增加少量岬角；不擅自改变岛屿数量或封闭山口 |

改变结构必须显式允许。例如“更圆润”保持区域数量、孔洞和预留开口；“封闭海湾形成内湖”才改变连接关系。地理方向只用于定位，不作为形状类别。

## 4. 最小构造能力

1. **围合**：自由闭合曲线形成区域，支持凹形、多外环和孔洞。可接受从图像提取的轮廓，也可由语义生成。
2. **沿线展开**：曲线或分支图配左右宽度函数，形成带状/树状区域；端部、分叉处独立处理。河道、山群共用能力。
3. **组合与切除**：并集、交集、差集组成岛群、海湾、山口和内部空地。保留操作来源，不能布尔后只存一串匿名顶点。
4. **局部变形**：对选定支段或边界片段伸展、弯曲、鼓出、收缩，带平滑影响范围；端点和锁定区域可以固定。
5. **边界过渡**：由同一边界生成有实际宽度的缓坡带，并向后续高度/地表输出。黄色区域不能只是画笔描边。

分支图不是万能形状模板：环岛、带孔区域或复杂湖面直接使用闭合轮廓和组合操作。河流也不能永远是中心线等宽扩展，需要左右岸独立控制，必要时允许局部轮廓覆盖；中心线仍须位于水域内并保持连接。

## 5. 用户意图如何落到操作

以下是建议的参数契约，不是已经存在的新 API。

| 用户意图 | 调整目标 | 保持什么 |
| --- | --- | --- |
| 这个岛更宽 | 局部坐标短轴尺度 | 中心、主方向；面积随宽度增加 |
| 岛岸更圆润 | 曲率/短尺度起伏 | 面积近似不变，保留主要海湾与孔洞 |
| 这里形成更深海湾 | 边界附着的切除区域深度 | 湾口位置与邻近锁定边界 |
| 这段河流更宽、左岸更舒展 | 支段左右宽度及岸线偏移 | 汇入口、上下游端点；联动泥土带 |
| 山群增加一处分叉 | 新增轴线边、长度、夹角、带宽 | 原主干身份；生成对应占地和岩体 |
| 留出更宽的山口 | 切除区域宽度 | 两侧山群身份；相交岩体需重排 |
| 村落沿岸伸展 | 区域主轴附着岸线，调整长宽比 | 建筑位于有效区域，保持临水退距 |
| 增加离岸岛 | 新增区域及与主岛的距离关系 | 原岛不移动，新岛不超出规划边界 |

局部目标按对象 ID、支段和边界关系定位，不依赖“第 38 个采样点”。每个对象默认只暴露规模、形态、结构三个参数组；只显示对该语义有效的选项。

## 6. 随机性如何超过参考构图

生成顺序是：区域数量与关系 → 构造结构 → 大尺度比例和布局 → 连续轮廓 → 局部细节。不能所有区域继续沿同一半径或固定候选点排列。

随机输入描述范围与允许变化，例如：主岛一个、离岸岛 0～3 个；允许深湾；山群允许连续和分叉结构；河流汇入关系明确。每种语义生成器选择并组合通用操作，不把这些案例枚举成封闭的自然形状全集。

修改宽度只改变宽度；“重组这个山群”才重新选择其结构；“重新布局全图”才允许改变全局关系和位置。保留对象身份、局部随机状态和锁定内容，避免编辑一条河重排全部岩石。

先建设形状表达能力，再证明语义生成器能探索它。能存任意轮廓，不等于已经能随机生成有意义的任意布局。

## 7. 几何实现与约束接口

- 曲线推荐向心 Catmull–Rom，再转为分段 Bézier 统一处理；相比现用的均匀参数曲线，更适合不均匀控制点。其单段无尖点/自交性质不保证整个闭合边界无自交，仍需检查。[研究依据](https://www.cemyuksel.com/research/catmullrom_param/)
- 多边形布尔、偏移使用成熟几何实现，不手写通用求交。Clipper2 是候选算法实现；官方主要为 C++/C#/Delphi，浏览器接入方式仍需选型与实测，尚未接入。[文档与代码](https://angusj.com/clipper2/Docs/Overview.htm)
- 构造图是可编辑来源，解析后的多边形是统一查询结果；提供包含、相交、最近边界、面积、局部宽度和采样。距离场可作派生缓存，不能用布尔后的近似距离冒充精确距离。
- 河网采用连接图，再生成区域与高度的顺序有论文依据；本方案借鉴结构与组合思想，不计划此时完整实现水文模拟。[Génevaux 等，2013](https://cs.purdue.edu/homes/bbenes/papers/Genevaux13ToG.pdf)
- 只处理编辑影响的依赖子图。先保证有限坐标、有效区域、必要连接和地图边界；对象间退距按语义配置。不要启动庞大的全局迭代求解器。
- 形状冲突按预先声明的策略局部退让或限制变形幅度；无有效结果则保留上一个有效状态并说明实际生效范围。不能靠无限重试，也不能把超界区域随意裁掉而丢失岛屿或出口语义。

## 8. 2048 米与采样边界

规划域固定为 `[0,2048] × [0,2048]` 米，边框代表 heightmap 覆盖范围，岛屿岸线是框内可变轮廓。主岛、离岸岛和必要海域均包含在框内；框外仅是预览留白，不代表新增地形。

高度 1025×1025 个顶点覆盖两端，间隔 2 米；地表 1024×1024 个单元对应同一范围。形状保留连续表达，输出时才采样，不能将轮廓坐标强行吸附到 2 米网格。

建议初始最小轮廓特征 8～16 米，作为可调质量尺度，而非每隔 8 米必须放一个控制点。曲线采样按误差自适应；控制点数量、边界离散误差、可表达地貌尺寸和栅格采样间距是不同概念。缓坡需要多个像素宽，SVG 抗锯齿本身不能证明 alphamap 过渡合格。

## 9. 最小落地顺序

1. 保留当前验收构图，将其接入自由轮廓、沿线展开与组合操作，输出视觉保持一致。
2. 用同一套操作产生三组结构变化：岛屿的湾/孔洞/分离岛；山群的连续/分叉/山口；河流的支流/非对称宽度/湖面连接。村落复用区域能力。
3. 验证“圆润”不吞掉开口、“加宽”联动岸坡、“新增分支”确实增加结构；局部编辑保留无关区域。再接入有语义约束的布局随机化。

成熟曲线和区域运算让几何表达有较高可行性；局部组合稳定性和语义随机布局仍需实现验证。漂亮程度仍由用户判断。本阶段不增加动线导演和 3D 工作量。
