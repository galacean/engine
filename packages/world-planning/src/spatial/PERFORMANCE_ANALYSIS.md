# 布局与局部调参性能分析（2026-09-24）

本次实现景观百分比衰减；没有把全部参数改成增量执行，也没有修改 shader 或降低生成质量来换速度。

## 测量口径

release 工作树，同机 Node/Vitest，1024×1024，首次访问配方 `createSeedPlanningDocument(seed)`。完整事务通过 `PlanningSession`，阶段时间来自 `SemanticResult.timings`。不包含 Worker 传输、浏览器重绘、localStorage 写入；不能称为浏览器端到端延迟。单次运行存在 JIT/GC 波动，以下保留样本范围，不宣称稳态 P95。

复测命令（从仓库根运行，会先物化 Gallery）：

```sh
PLANNING_PROFILE=1 node world/scripts/run-engine.mjs pnpm --dir world-gallery test:terrain-project demos/terrain/project-tests/PlanningPerformanceProbe.spec.ts --maxWorkers=1
```

该诊断测试默认跳过，不进入产品界面；环境变量开启时输出阶段计时并保存 `/tmp/planning-layout.cpuprofile`。`ecology-island-bounds` 只在实验中直接调用区域路径，并与全图路径逐对象比较，不代表生产事务已经切换到该路径。

## “换布局”的瓶颈

修改百分比前的基准样本（秒）：

| 操作 | 完整事务 | 分区 | 体量 | 道路 | 景观+花丛 | 心理地图 |
|---|---:|---:|---:|---:|---:|---:|
| 初始化 Seed 1 | 10.79 | 0.19 | 5.74 | 3.48 | 1.25 | 0.11 |
| Seed 1 → 2 | 14.23 | 0.17 | 7.27 | 4.94 | 1.38 | 0.10 |
| Seed 2 → 3 | 16.08 | 0.33 | 10.15 | 3.59 | 1.19 | 0.10 |

体量与道路约占生成核心时间的 85%–89%。百分比版本重复测得 Seed 1 为 10.42/11.13 秒、切换 Seed 2 为 12.97/12.47 秒；运行波动和景观数量变化不能作为“百分比提速”的证据。

CPU 采样定位：

- `LayoutKernel.groundVolume → VolumeTerrain.boxGroundBottom → WorldPlanningTerrain`：接地采样反复进入解析地形/岸线查询，首轮采样累计约 3.8 秒（包含子调用）。这不是渲染 shader 开销。
- `VolumeSpacing.coordinateVolumeSpacing`：同轮约 1.26 秒，包含边缘间距、候选接受与接地。最多 6 轮×256 候选/成员，复杂占地会重复做几何工作。
- `RoadAttachments.publish → rebuildRoadTopology/buildTopology`：补接道路反复重建路网；首轮拓扑重建包含时间约 1.8–2.0 秒。
- 以上调用有嵌套，不能相加成独立占比。`inside/visit/lower` 等多边形/距离查询占了大量 CPU 自耗时；采样亦有约 0.5 秒 GC。

Seed 是世界签名的一部分；换 Seed 会改变陆地、POI、地形、体量和网络。将工作按区组织不会使这些区域变成可复用的旧结果。“只重建一个区域”不等价于换世界布局。

## 局部更新能节省多少

百分比版本，同一次运行对离岛 6 连续改变密度：

| 路径 | 首次调用 | 后续调用 | 正确性 |
|---|---:|---:|---|
| 独立生态计算，全图候选 | 394.5 ms | 80.7 / 75.4 ms | 参考输出 |
| 独立生态计算，离岛包围范围 | 55.1 ms | 11.9 / 11.4 ms | 与全图输出逐对象相等 |
| 当前完整离岛编辑事务 | 556.6 ms | 537.7 / 548.5 ms | 正式 Session 路径 |

区域扫描将这部分热计算减少约 85%，约快 6.7 倍；只把这一环节接入事务，预计整次只减少约 65–75 ms（约 12%–14%），不是整体快 6.7 倍。这个整次节省是差值估算，尚未实现后实测。

当前局部事务仍存在：

1. `SpatialWorld` 对整个旧 plan 做 `withoutVisualGuidance` 和 `structuredClone`，准备/比较全图签名。
2. 纯密度编辑仍进入道路阶段（本轮 94–103 ms）、心理地图阶段（17–18 ms），尽管几何未改变。
3. `EnvironmentStages.ecologyInput` 将任意局部配置变化标成全局生态配置变化，传给景观生成时不携带该参数的所属区域。
4. 事务准备/提交、作者数据克隆比较、场景发布等外围工作约 195–208 ms；生成核心中还有未单独分段的复制/差异检查。不能全部归为渲染时间。

进一步按依赖跳过道路/心理地图，再缩小候选筛选，按当前样本可免去约 185–200 ms，即完整事务约三分之一；这是理想跳过成本估算，仍需包含必要的生态/引导冲突维护以及发布成本，不能承诺实际值。若再做局部数据发布，可将 100–200 ms 作为下一阶段实验目标，不是已达到的验收结论；30 ms 端到端目前没有证据。

## 应按参数职责区分

| 参数 | 可复用 | 必须更新 |
|---|---|---|
| 某 POI/离岛密度、衰减百分比 | 地形、体量、道路、候选几何 | 本区筛选、与引导的相关占地、实例差异 |
| 景观高度 | 候选位置与分布 | 本区域实例尺寸及实际依赖 |
| 体量数量、尺寸、间距 | 邻居、无关地形和道路 | 本组布局、受影响道路/生态 |
| 道路宽度/曲率 | 无关路段和体量 | 相关拓扑边、连接点、沿路引导与生态 |
| 全局生态基础配置 | 地形、体量、道路 | 所有受继承影响的区域；有覆盖的字段可排除 |
| Seed、海岸、全局地势 | 仅真正不变的独立资源 | 多数/全部空间数据 |

建议后续顺序：先参数→脏区域/依赖阶段的执行分流及局部发布；随后单独优化全新布局的接地查询与道路拓扑批次。保持输出一致、邻居不变和真实碰撞检测，用相同 Seed 做对照。不要将计算预算、百分比或取消碰撞当作性能修复。

## 本地首轮提速已实现（未 push）

- 布局候选先做区域/中心留白筛选，通过后才求完整底面接地；不降低采样精度。相同 footprint 在一次 solve 内复用精确接地结果。
- 道路拓扑中的来源/网络/节点宽度改为索引查找，消除逐节点全路段扫描；最终路面只构建一次，避免同一条路重复生成 ribbon。
- 已满足道路复用条件时跳过前置全局道路修复循环。该复用条件沿用既有逻辑，没有放宽道路失效判断。
- 单个 POI/离岛景观规则变更，将候选更新限制到对应管理区包围范围；全局配置、地形、体量或道路变化仍走各自依赖路径。

同进程顺序生成 Seed 1/2/3，新世界无 DB 覆盖、未开启 CPU profiler 的成对测量：

| Seed | 修改前 | 修改后 | 耗时减少 | 完整 plan 等价 |
|---|---:|---:|---:|---|
| 1 | 10003 ms | 6865 ms | 31.4% | SHA256 相等 |
| 2 | 12246 ms | 7572 ms | 38.2% | SHA256 相等 |
| 3 | 12004 ms | 6886 ms | 42.6% | SHA256 相等 |

比较的是完整序列化 plan（对象键排序，数组及数值保持），包含体量、道路拓扑、生态及规划检查。不是只比较数量；测试没有跳过接地/碰撞。基准是同一百分比规则版本，临时恢复本轮优化前的接地与拓扑计算执行后保存参考，再恢复优化代码逐 Seed 比较。测量不含浏览器重绘、Worker 通信和 DB 写入。

20 项相关回归通过，涵盖完整结果等价、接地/坡度、路网补接、离岛局部编辑/持久化、生态邻居稳定。一个旧拓扑测试夹具补齐空 volumes 字段；新增测试验证区域外候选不会触发地形采样。道路生成仍有数秒成本，批量拓扑管线重构尚未实现，不将本轮索引优化冒充管线重构。

最终 Session 复测：离岛局部密度事务 450/486/472 ms，小型 POI 546/454/448 ms；热生态阶段约 22–24 ms。相比此前同类事务有所改善，但整体仍受复制、检查和发布影响，未达到 100–200 ms。Chrome 页面已生成并实际提交离岛 6 的 200% 衰减，再恢复 100%；未用工具调用往返时间冒充交互计时。最终 typecheck、diff 检查、scope audit 通过。


## 第二轮本地提速：补接批处理与候选计算裁剪

道路补接先在工作图中收集连接，再统一构建交叉点与路面拓扑；新连接可作为后续连接目标。保留现有连接复用、失败回退和端点审计，缓存道路几何版本升级为 9。
体量候选的坡度检查发现超限即停止；不超限时仍检查完整 footprint。间距求解在单次调用内缓存 OBB 轮廓，用 AABB 距离下界排除已满足间距的远邻，近邻仍计算精确边缘间距。碰撞、坡度上限和完整底面接地未放宽。

未开启 CPU profiler 的 Seed 1/2/3 完整生成测得 4753/5809/4249 ms；体量阶段 1714/1604/1784 ms，道路阶段 1386/2802/1027 ms。相较上一轮完整生成 6865/7572/6886 ms，本次分别减少约 31%/23%/38%；不同运行存在机器负载与 JIT 波动，这不是稳定延迟保证，也不包括浏览器重绘或 DB 写入。

18 项相关回归通过。三个 Seed 的所有体量与优化前记录逐项相等，道路数量为 230/216/223，非内容入口断头路均为 0。新增回归验证多个补接只触发一次最终拓扑构建。类型检查、diff 检查和 scope audit 通过。外部基线对照 `BatchedRoadPlanning.spec.ts` 仅在 `PLANNING_PROFILE=1` 时运行，依赖事先记录的 `/tmp/layout-speed-before-{seed}.json`；普通测试不依赖该文件。

仍未达成毫秒级完整生成，也未消除所有候选搜索：体量初始化和间距协调保留确定性候选序列，道路仍有寻路/曲线编译成本。下一阶段若改成可行域驱动摆放，需要单独验证密度、数量与布局变化，不能将此次计算裁剪称为完成该架构。未 push；未修改 shader。


## 2026-09-24 首次生成与无几何存档重建

同一机器、独立测试进程、同顺序 Seed 1/2/3，无 DB 或旧 plan；未开 profiler 的整次核心生成：

| Seed | 本轮前 | 本轮后 | 降幅 | 完整 plan SHA256 |
|---|---:|---:|---:|---|
| 1 | 8938 ms | 4952 ms | 44.6% | 相同 |
| 2 | 8452 ms | 4641 ms | 45.1% | 相同 |
| 3 | 6742 ms | 4258 ms | 36.8% | 相同 |

Seed 1 最终体量约 1428 ms、道路 1714 ms、生态 1371 ms、区域 220 ms、引导 202 ms。此口径含生成核心，不含页面加载、Worker 传输和地图绘制，未达 1 秒。组合测试进程的已预热值较低，不能冒充冷启动。

CPU 采样发现河床纵向 profileHeight 线性扫描约 2 秒，以及跨河候选对每个河岸顶点重新建立同一道路轮廓查询。改为每个不可变地形查询实例持有精确最近线段索引、最近距离并列按原序号选取；道路轮廓查询每次候选只构建一次；射线包含测试细化行桶并跳过不可能的边。没有稀疏化采样、跳过碰撞或降低生成数量。

刷新一致性：组布局从 Seed/最终组参数生成基准，再稳定应用显式单体覆盖；旧组只有输入完全相符且占地仍合法时才复用。移除道路基于历史曲线修补的双路径：几何变更统一从最终入口/占地建立道路，无几何变化可复用整网。两项原失败的数量/尺寸重建回归现通过，覆盖实际岩石、建筑、水域、景观、花区、桥和出生点。几何编辑仍可能需要秒级道路重建，不能声称实时。

复现：用 `COLD_PROBE=baseline` 运行 ColdPlanningProbe.spec.ts 记录 /tmp/cold-baseline-{seed}.json；优化后用 `COLD_PROBE=verify` 同命令验证完整结果及耗时，`profile` 模式输出 CPU 采样。没有该环境变量时跳过，不影响常规测试。旧 WorldPlanningTerrainPerformance.spec.ts 在 generateSemanticWorld 夹具接受阶段失败；恢复本轮优化前地形代码复跑仍同样失败，未将其称为本轮通过。
