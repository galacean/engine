# 空间元素与空间关系框架

## 当前 POI 作者模型（2026-11-06）

当前没有大中小等级或等级参数页。`distribution.spacingM/minAreaM2` 配置统一候选分布，`poi.sizeWeight` 控制单点管理区偏好。候选的原始位置和身份是作者输入；当前中心、分区、面积与 active 是求解输出。UI 拖动只预览锚点和轮廓，松手使用原事务生成内容并保存。休眠候选仍能从列表选择恢复。

面积调整不改变 POI 用途；建筑、岩体等用途单独通过 `layout.elementProfile` 设置。`spacingM=210` 是初始布点间距，用于形成大致均匀的管理区域，不表示区域边长或精确面积，不决定用途、建筑尺寸或密度。

旧等级、policy、初始组合与生态覆盖只在 `migration/LegacyPoiAuthoring.ts` 等兼容导入模块读取，迁为稳定候选和具体 POI 的局部输入；当前运行时不解析旧 ID 中的等级。下文带日期的测量与验收属于历史记录，不代表本次变更已通过相同验证。

规划只负责点、线、面、体以及它们的关系。建筑、岩石是上层用途；它们在布局内核中都是 `Volume`，不根据名称决定碰撞。当前内置布局中，一个成员就是一个可独立调参的 OBB；底层 boxes 数组仅保留旧插件兼容，不生成隐藏子块。

当前实现入口是 `PlanningRuntime → layout/SpatialWorld`。旧村庄数量、容积率、楼层、最低建筑面积、峡谷专用参数已从当前 schema 和生成链移除。`WorldSettlementPlanner` 仅保留 recipe 入口兼容适配，不再运行旧村庄求解器。历史 study 和素材专用算法不构成当前框架契约。

以 POI 区域为生成/更新单元的速度架构与验证见 [生成性能](SUBSECOND_GENERATION.md)。本地已将道路样条与逐点路宽插值收敛到 `layout/RoadSpline.ts`，上层形状规则统一提供控制点；河流形状机制独立维护。寻路不再叠加 S 代价、弯曲噪声或岩体尺寸偏好；反向共享线段、路口邻域拟合、派生轮廓和沿路岩体占地检查减少重复工作。道路占地索引、局部景观候选及高度采样优化也已实现。全路网一次编排/编译与 Worker 差量发布仍待实施，完整核心仍是秒级，不能宣称毫秒/亚秒目标达成。

## 存档操作

“全局规划 → 清空存档”清除当前 Seed 的玩家视角记录，以及对应项目 `World/Editor.json` 中的 `settings.camera`（包括离地高度）；保留规划参数、场景、建筑、农场和其他编辑设置。项目清理通过 Runtime Project 的串行更新保存，成功后再删除玩家视角记录并刷新回规划页；失败显示错误并允许重试。清理期间禁止编辑和生成 3D，切换 Seed 后按当前 Seed 定位项目。

“重置规划参数”在后台初始化默认作者参数，通过现有工程事务保存并更新当前规划，不刷新整页；场景及其他资产保留。它与“清空存档”的范围不同。

## 参数和初始化配置

### 地形采样与 LOD

Planner 仅发布 1024×1024 的固定高度图，覆盖 1024 米世界，相邻采样约 1 米。CPU 接地与 Water 床面沿用 canonical Float32 三角采样，渲染消费其 R16 编码并允许 LOD 近似；地形使用原有 Clipmap 网格并随距离执行 LOD，不生成水岸或桥头局部精细网格、图集及替换面。局部精度开关和间距参数已删除，旧工程与 Seed 归档中的相关配置在作者数据边界清理。小于基础网格的地形细节允许近似，不再保证厘米级岸线还原。


### 默认出生区域

世界出生锚点优先选择有实际建筑和入口的村庄 POI，沿用最终路网中已连接的入口；没有已连接入口时使用该组现有入口。没有可用村庄的地图保留原来的 POI 入口回退。锚点随最终布局确定性派生，局部更新与冷重建使用同一选择规则，不存储固定坐标。`plan.spawn` 作为动物范围、首次农场选址及出生取景的共同村庄锚点；实际玩家站位由下述取景规则从该锚点派生。2026-10-26 用户反馈刷新后视角朝地面：刷新或首次进入 3D 使用当前出生取景，不自动恢复私人存档或编辑器存档中的相机；其余工程设置继续恢复，运行中的局部编辑保留当前视角。

默认首次视角与“回出生点”共同调用 `PlanningSpawnView`：朝向当前村庄已发布的建筑，复用 `subjectView` 的包络外接球、实际 FOV/宽高比和默认取景比例计算距离。入口已能完整取景时保留站位；过近或无法安全站立时，按拟合主体的角直径采样周围站位，保持地面/桥面加漫游眼高，不改变建筑或地形。站位按现有人物半径、高度和 traversal 坡度检查采样支撑、水域、碰撞 OBB，并要求有一个身体直径的出口；这是有限几何检查，不等于完整步行路线证明。

候选视角用发布 OBB、地形、水位与地面植被覆盖进行视口射线估计，先比较目标建筑可见比例，再按建筑、树、水、植被、岩石各类覆盖率从低到高比较，最后优先离村庄锚点近的位置。稳定建筑 ID 和角度顺序保证确定性；不会为配齐景物改场景。`data-spawn-view` 提供实际眼位、目标、`framing`（`fitted` 或预算内无可用候选的 `fallback`）、估计覆盖率与缺项；回退保留原锚点并不声称安全取景已通过。CPU 采样和树冠包络不等于真实像素或美术验收。显式 `subjectView` 仍优先于默认出生取景；私人相机持久化继续记录漫游状态，但不覆盖页面首次进入。

### 默认农场区域

世界 `farming` 组件选择管理 POI（`auto` 或已有稳定 ID）、起始耕地个数和是否预置初始容器。2026-10-16 起，先生成普通区域、道路及最终出生点，再在已有空地中寻找完整农场，不再预留整块 POI 或改变其他区域用途。`auto` 只搜索主陆地；显式 POI 只搜索指定管理区。

选址围绕最终 `plan.spawn` 按 16 米距离档向外检查；64 米内使用 4 米位置网格，外侧使用 8 米网格，避免近处密集采样提前耗尽预算。网格只决定候选覆盖，设施占地与容器支撑仍使用原有精度检查。同一档内只按坡度由小到大排序，坡度相同时按出生点距离和稳定坐标打破平局。每档最多完整检查 8 个候选，整个搜索最多检查 128 个设施、采样 2048 个位置；每个初始容器最多尝试 64 个位置/朝向。这个预算只用于规划预检查，不写入存档，不改变玩家后续新增容器的搜索规则。找到合法设施即停止，不遍历全图寻找最优解。河流、湖泊不参与距离评分；公共道路不再是农场启用条件，不新建农场接路、不因断路换址。水下、管理区覆盖、坡度、实体障碍、现有道路占用和容器底部支撑仍按完整占地检查。耕地最少 4 块，默认 2×2；关闭初始容器只影响首次生成，不删除库存。

搜索复用一份地形采样器和障碍索引，已证明越界或被占用的设施提前拒绝。农场占地继续屏蔽程序化景观装饰，冷启动与纯显隐更新消费同一排除规则；固定体量和引导岩体仍参与阻挡检查。容器重叠探测使用搜索内、精确坐标的高度缓存，最多 32768 个值，搜索结束释放。距离档只对当前范围采样，不预采样整张地图。搜索预算耗尽不代表全图无解。

起始点采用设施两侧入口中离出生点较近的一侧，字段为 `farming.entrance`；`access` 诊断表示内部操作通道可用，证据为 `FARM_OPERATION_CLEAR`，不表示公共道路连通或出生点至农场已验证步行可达。设施最终检查通过后显示起始点。已有世界出生点及其相机恢复规则不由农场修改。`roadWidthM` 与旧 `riverPreference` 作者字段在导入/升级时退役。

控制台 `[Planner][Farming] 初始化选址` 输出位置采样数、完整设施候选数、涉及 POI 数、入口至出生点距离以及选址/最终检查耗时。真实 Seed 继续使用共享 FarmingSystem、HUD/Agent 和 FarmSnapshot；开垦排除既有道路与操作通道，低草毯仅按耕地与操作通道屏蔽，马车和仓储篮子保留周围草株及底部草皮。其他自然植被和伴生石块按耕地、通道和容器各自占地及已有3米过渡带避让，使农场周围只保留草毯。容器仍参与放置净空与碰撞检查。未找到设施时保留诊断，世界仍可发布。

农场草毯与其他植被使用独立的运行时避让范围，不在自然植被候选或低草源密度中按初始设施外包围框整片清空。通道从当前快照的网格与占地按起始设施同一公式派生，新建与读档一致；新增、移动、删除容器同时更新草皮保留与其他植被避让。各占地分别扩展，远处分散容器之间不合并成全局外包围框。

运行时草毯排除使用稀疏位图页，只访问占地覆盖的密度样本并局部更新内容哈希，新增耕地无需复制或哈希整张密度场。密度采样、候选归属和音频共用投影读取；外部读取连续 `samples` 或导出时才按需生成数组，旧快照保持不变。占地发布可复用已接受作者源中同一高度数组的逐值校验，公共作者输入及水域更新仍完整校验。

草实例整理将固定草高／生态草高作为独立参数传递，保留密度字段引用，不通过对象展开修改高度元数据。整理任务、岩面草及入场批次在准备阶段解析密度采样器；普通字段直接读取原数组，稀疏字段按已有网格坐标读取位图并复用相邻点的不可变页，逐候选采样不重复查找投影元数据。

运行时占地变更按变化密度场的插值支持范围选择受影响的 32 米 patch，保留其他批次；候选沿原 ordinal 与 seed 整理，连续编辑合并尚未完成的脏 patch。普通草地 patch 发布优先复用 Mesh 和实例 Buffer，容量不足时只扩容 Buffer；带岩石接触附加属性的受影响 patch 按同一实例顺序准备全部属性后整体替换，保持旧批次直至准备成功。空 patch 保留禁用资源以便恢复。整理、分段合并／洗牌、包围盒／归属准备及发布共用同一 Engine 帧的截止时间，占地订阅回调不再同步消耗第二份预算。单次分配或驱动调用不能中断，预算不等于严格执行时限。作者编辑、水域准备和入场仍使用完整 Cell 的隐藏准备与发布事务。

农场存档在工程内按 Seed 的稳定 farmId 保存，每个 Seed 一份。“全局规划 → 农场起始区域 → 存档选择”默认使用已有存档，也可选择本次不使用；再次进入默认恢复存档。恢复使用玩家网格、全部扩建耕地、作物及容器坐标/库存，不受当前 POI、道路、水域、坡度或容器布局合理性限制；已提交设施在后续地面刷新中也继续有效，新放置仍查询实际地面。数据版本、规则签名、ID 引用、有限数值和库存一致性仍校验。版本不支持或数据损坏只让当前 Seed 降级为首次生成，新快照成功提交后才替换旧记录；读取或保存故障不触发重置，其他 Seed 不受影响。

[`layout/space-rules.json`](layout/space-rules.json) 定义：

- 所有 POI 共用的组织抽样、成员间距和米制尺寸区间；没有初始成员数量。
- 首次进入某 Seed 时地势、生态、道路参数的抽样区间。
- 内置规则的连接方式、互斥组。
- `elementProfiles` 声明元素默认尺寸与表现绑定，`defaults.rules` 引用规则 ID 和元素配置 ID。同一组织算法可以配建筑或岩体；表现接口不进入碰撞内核。

尺寸来源顺序：统一通用初值 → 元素配置的米制范围 → POI 的明确尺寸覆盖 → 单个体量覆盖。POI 权重改变管理区域，不缩放元素尺寸。改变组织规则时解析配置后叠加稀疏作者字段；旧等级的明确尺寸在导入时迁为局部输入，不能重新按名称推测。

### 初始化用途与实际占地

生成顺序为陆域与地势 → POI 管理分区 → 河流/湖泊及自然地面 → 区域用途分配 → 体量 → 道路与生态。
水域需要管理区来计算跨区范围，因此先划分空间，水域完成后才选择区域用途；不会为了放村庄移动 POI 锚点或改变邻区面积。

世界 `terrain.lengthM` 是米制隆起带长度，经过同一 schema/Session/作者配方读写；新工程默认 600 米，缺字段的旧配方也使用 600 米。数量、主方向、高度、过渡宽度各自独立。长度必须大于零，关闭隆起带用数量或高度 0。

建筑选址只按实际占地的坡度检查地形适用性，不以地形带位移量或海拔排除山地。建筑默认坡度上限为 12°；平坦的山上允许生成村庄，陆域、水域及显式占用检查仍有效。

新世界初始化按实际可生成的建筑选择村庄区域。世界组件 `population` 暴露 `villageMin/villageMax`（默认 1–10 个村庄）与 `buildingMin/buildingMax`（默认 0–20 栋建筑）两组指导范围，面板与 LLM 使用同一作者参数。各组仅要求非负整数且下限不超过上限；村庄下限超过建筑预算等组合不会被判为非法，实际数量按可用空间、坡度、布局和建筑预算决定。下限不足记录诊断，不强制添加建筑或村庄。候选选址与预算分配共享有限计算预算，完整通行及布局约束仍须通过。首次创建或显式修改范围时通过普通 `layout` 用途与成员数量范围实现规划：先为选中村庄分配可行的基础名额，再按容量分配剩余的全世界建筑预算；不为凑数改变尺寸或间距，范围与最终作者参数一起保存。之后局部成员范围修改与手动新增建筑可以超过该次全世界预算；刷新重放已有作者参数，不重新执行预算。旧目标/上限配置只在导入时迁移，不改变已有布局。

新建世界将初始化选定的用途保存为各 POI 的 `layout.elementProfile`，备用候选也保留明确用途；后续面积、地形和道路编辑不会重新挑选村庄或执行初始化预算。没有显式用途的作者输入仍按 Seed 与稳定身份确定性抽样。`layout.elementProfile` 独立于面积权重和组织，可通过 schema 声明的选项修改。修改组织、尺寸或间距不改变用途；实际成员数量仍由占地、坡度、水域和互斥条件决定。局部编辑与冷重建必须一致。


同一个规则仅形状分布不同，优先增加配置变体；有不同的空间组织行为，才新增算法插件。初始化区间不是硬约束。编辑器可调区间在字段 schema 中声明，用于有效数值与有限计算范围，不等于素材规格。

首次进入无存档的 Seed，经 `PlanningInitialization` 用命名随机流采样。工程保存在 IndexedDB 的 runtime 项目包中，规划文档映射为 `assets/World/Planning.json`；只保存 Seed、全局/局部作者参数、显式手动编辑和各 Seed 的参数归档，不保存生成道路、体量、轮廓、拓扑或缓存签名。`exportPlanningAuthoring` 是统一持久化边界。旧规划 IndexedDB/localStorage（含 packed:v4 和旧 JSON/v2/v3）仅作为首次迁移来源，读取时迁移参数并丢弃生成缓存。URL 仅保留 Seed 和 debug 标志。“重置规划参数”通过同一作者参数存储边界恢复当前 Seed 的默认规划，保留场景及其他资产；布局评估与生成在 Worker 中执行，临时生成结果只在内存复用，不写入 DB。

旧半径/数量在清理前迁移为间距范围，主动导出与载入迁移采用同一顺序，保留明确的间距覆盖及显式 0。

`placementState` 仅供旧格式迁移；新的 Session 文档、参数事务和 Seed 归档不携带生成快照。局部编辑基准由 Session.result / Worker 独立持有，发布后视为只读。事务复制可写容器，未变化的道路、区域与成员几何可共享；修改实例时必须创建新对象，不能回写候选缓存或上一版结果。生成算法版本改变时不保证旧版几何完全一致。

Worker 不再读取或保存完整生成结果的 IndexedDB 缓存；Storage 初始化及清空时非阻塞删除本应用退役的 `world-planning-draft` 数据库。唯一持久化内容仍为作者参数。同步生成中的过时任务通过终止 Worker 取消，迟到响应/错误被隔离；完成后正常编辑仍使用 Worker 内部的基准 ID。取消后会重新启动 Worker，并发送一次主线程已接受基准，这有启动与复制成本，尚不是分块调度器。

## 当前公开作用域

| 组件 | 作用域 | 实际消费者 |
| --- | --- | --- |
| `world`、`distribution` | 世界 | 陆域形态与 POI 分布/管理分区 |
| `terrain` | 世界 | 有方向、长度、宽度、数量及高度的平滑隆起带 |

| `layout` | 单 POI，可显式链接另一个基础组件 | 组织算法、成员数量范围、体量间距、尺寸区间、方向变化、通路宽度、中心留白；实际数量只读 |
| `solid` | 单体量、独立景观、引导体量 | 位置、米制尺寸和朝向；当前内置成员一对一对应 OBB |
| `network`、`roadWidth` | 世界/单全局道路、单内部通路 | 最终体量后的路网；局部宽度和曲折参数 |

| `plantMaterial`、`grassAppearance`、`lighting`、`postProcess` | 世界表现参数 | 原生植被材质、共享草地色场、光照与后处理，不重算空间布局 |

字段通过 `override / multiply / add` 明确合成。没有配置来源的字段不会因为 Hierarchy 父子关系自动相乘。显式 0 有效，reset 恢复来源/规则抽样；编辑一个字段不会把其他生成值永久冻结成本地覆盖。修改参数自然会改变依赖输出，但不能偷改其他作者参数。

`landscape.vegetation.grass` 同时控制低草实例与 Terrain 的草表面覆盖。草表面减少的权重转移到已有裸地层，四通道总量保持 255，水域和道路权重不变；其他植被层仍使用独立的群落比例，不因低草关闭而被隐式删除。明确要求无花草时，分别关闭花区人口、低草和高草等实际相关层，并检查有效局部覆盖。

## 空间可行性规则

**显式体量互斥，以及可配置的占地坡度上限。**

- `VolumeExclusion { id, a: volumeIds, b: volumeIds }` 表示两组体量互斥；默认没有关系就允许重叠。
- 当前内置成员与 OBB 一一对应。窄相使用真实 OBB 朝向和高度；保留底层数组签名只用于兼容已有插件。
- 树冠、POI 管理分区、中心留白、道路不是自动生成的互斥实体。
- 地面高度由同源 Terrain 采样自动适配；`maxGroundSlopeDegrees` 独立检查实际 OBB 占地内最大采样坡度。上层元素配置给默认值（habitable 12°，outcrop 90°），POI 和单体量均可覆盖；内核不判断素材名称。90° 放宽坡度检查。
- 发生几何变化的 POI 从 Seed 与最终组参数重建基准，再按稳定成员顺序应用显式单体覆盖，不将历史位置作为生成输入；未受影响的 POI 复用结果，没有可行候选时实际数量为 0。占地梯度目前按 2 米间隔及边缘采样，适用于当前平滑地势，不等同于任意精细 Terrain 网格的严格最大值。
- 接路失败、候选预算耗尽是诊断，不否决已经成立的体量。
- 非有限数值、负尺寸、坏引用、缺失插件是数据错误，与空间设计约束分开。

自动生成沿所属规则的有限候选检查一次。编辑既有体量时邻居只读；与显式互斥体量相交时，从原可行位置向请求结果做有限局部协调，只保存本次修改字段的实际值。不会全图反复重生成，不会搬走其他 POI，也不声称找到非凸空间的全局最近解。

体量由所属 POI 的实际管理区域、组织、尺寸和间距构造；`layout.spacingMinM / spacingMaxM` 是逐成员确定性抽样的边缘间距倾向，决定候选的中心节距，不是所有成员两两距离的上界；非负间距不会在回退中被缩小。`radiusM` 只留在求解上下文作为派生搜索尺度，不再是作者字段。组织参数变化从当前参数重新构造本 POI，不缩放旧几何；单成员编辑保留未受影响成员；所属区域、陆地/水域、坡度与显式互斥决定实际生成结果。旧工程中手动指定的半径转换为同等名义密度的间距，升级只做一次。

数值面板统一使用输入框；回车/失焦提交，百分比输入 30 表示 30%。schema 仅保留正尺寸、整数数量、0–100% 比例、有效坡角等语义边界，不把抽样区间当作编辑范围。数量、距离、路宽与高度不再使用滑杆时代的人为最大值。导演时间轴用于跳转，不属于参数编辑控件。

实际成员数量不是可提交的布局字段，`memberCount` 只显示结果；可编辑的数量指导范围为 `memberMin/memberMax`。显式创建世界时的村庄目标和建筑预算独立于运行时布局参数。极端尺寸或负间距耗尽计算预算时单独诊断，不修改参数，不将预算称为容量上限。

## 类别配置与组织规则

`world.layout → poi.layout → volume.solid` 分别控制全局覆盖、当前 POI 的生成规则、具体体量尺寸。未设置全局覆盖时按各 POI 的初始化参数生成；填写后只覆盖该字段，局部显式值优先。选中实体只显示它自己的组件。UI 不提供“恢复上级设置”按钮；底层 `reset/base` 命令继续供程序使用。

| 组织规则 | 专属参数 | 派生结果 |
| --- | --- | --- |
| 分支连接布局 | 连接骨架形状、内部道路模式、内部通道宽度；曲线的弯曲/方向/净空/横向错落/变化尺度，或径向错落 | 通道骨架与可选成员支线 |
| 围绕中心留白 | 内部道路模式、内部通道宽度、中心留白半径、径向错落 | 中心铺地、骨架与可选成员支线 |

`layout.memberMin/memberMax` 是通用自动成员数量范围，适用于所有元素用途；`memberCount` 只读。下限默认为 0，上限缺省表示不额外限制数量。上限约束本区域自动生成的成员，下限不足记录诊断，不缩小体量、放宽坡度或强塞对象。独立 runtime 手动新增不消费生成数量预算。

一个大型空间元素由 `memberMin=memberMax=1` 和宽深高范围表达。需要居中且无内部道路时，用现有 `connected + branchShape:radial + openRadiusM:0 + radialVariationM:0 + orientationVariation:0 + roadMode:none`；元素方向通过通用 `headingDegrees` 控制，外部道路仍接实际入口。参数和局部随机种子均沿用项目 DB 作者存储，刷新重建相同布局。旧 `single` 仅在导入迁移中识别，不再出现在空间组织 schema 或运行时规则中。迁移保留作者尺寸范围、种子和显式单体编辑；非恒定尺寸范围改用通用排列的随机流，可能在升级时重采样一次，此后刷新确定性复现。

空间组织下拉框只列注册的具体组织，不提供“按配置抽样”。初始化抽样由上层配置负责，单 POI 显示实际组织；全局尚未统一覆盖的字段显示“未统一设置”。旧 `pattern:auto` 在作者边界迁移为各 POI 原本抽中的具体组织，保留其它参数与归档；类别上的旧 auto 标记清除。

规则以 `parameterKeys` 声明专属字段；`centerClearing` 声明中心开放区域，`defaults` 提供该规则的初始化值。内核不通过“村庄”“岩石”名称判断组织方式。可用入口默认参加世界道路连接，作者面板不再有“接入全局道路”或 POI 类型切换。互斥由显式体量关系决定，组织形状不决定素材类型。

建筑表现配置初始高度为 4–8 米；初始间距根据普通配置和新世界建筑预算确定。这些是初始化参数，不是输入上限，也不保证受周围实体影响后的最近邻距离恰好等于抽样值。隆起带与海拔辅助层默认关闭。

接地统一由 `layout/VolumeTerrain.boxGroundBottom` 完成：旋转底面按不超过 1 米步距采样（包含边界），底面放在最低采样高度以下 5 厘米。各 OBB 独立处理；道路引导岩体、普通景观岩石也消费同一函数，树只按树干占地接地，树冠不贴地。此方法是有限采样，不是任意高频高度函数的解析最小值证明；白盒、碰撞和素材适配消费同一发布底高。

局部更新按真实道路轮廓和受影响体量确定失效范围；改变一个 POI 的表现绑定不触发全图生态重建。`FootprintLookup` 仅加速候选筛选，保留精确多边形测试。道路拓扑只在内存中复用；几何输入变化时，从最终入口和占地统一生成，不把旧弯曲或编译后的路口当作作者参数。性能测试分别记录完整提交与各派生阶段，不能用体量求解的几毫秒冒充完整调参耗时。

## 接入一个上层规则

注册模块必须由主线程和 Worker 共同导入。接口是受信代码扩展，并非网络下载插件或安全沙箱。修改实现语义时提升版本；主线程/Worker 签名不一致时明确报错。

```ts
import { registerLayoutRule } from "./layout/LayoutRules";

export const unregister = registerLayoutRule({
  id: "row-cluster",
  version: 1,
  label: "沿轴排列",
  exclusionGroup: "independent", // 可省略；是上层声明，不由素材名称决定
  connections: "tree",          // 内置 tree / none；也可用 connect 自定义拓扑
  sample({ center, index, parameters, random }) {
    return [{
      center: { x: center.x + (index % 5 - 2) * 18,
                z: center.z + Math.floor(index / 5) * 18 },
      elevation: 0,             // 框架随后自动接地
      width: parameters.widthMinM,
      depth: parameters.depthMinM,
      height: parameters.heightMinM + random("shape:height") *
        (parameters.heightMaxM - parameters.heightMinM),
      yaw: 0
    }];
  }
});
```

`sample` 对每个成员只调用一次，返回一个逻辑体量的 OBB 集合和偏好位置，不接触可变世界。`random(channel)` 用 Seed、owner、成员 ID 构成稳定流；`attempt` 仅为兼容字段，固定为 0。内核在共享位置集合内协调冲突，不重复调用插件改变形状。

需要额外参数时，通过 `registerPlanningComponent` 注册带 `kinds:["poi"]` 的 schema，规则从 `context.components` 读取解析后的值。参数变化只使所属 POI 规则失效。配置表的权重项引用注册 ID，即可参与 Seed 抽样，无需改内核的类型判断。

两个可选扩展口：

- `relations(owners)` 返回跨体量的显式互斥集合，不返回隐式“建筑不能碰岩石”判断。
- `connect({owner, center, parameters, volumes, random})` 读取已接受体量，返回 `ports` 和 `links`。port 声明是否接入全局道路；link 声明端点和宽度。框架负责寻找曲线，未找到不撤回体量。

`registerPlanningExtension` 仅作只读诊断，收到隔离快照；返回结果不能新增硬约束或篡改布局。旧的 beforeNetwork/afterLandscape 几何注入回调已退役，不要用它绕过规则接口。

## 素材、道路与测量

同事接入树、植被、岩石素材时消费稳定 ID、位置、朝向、尺寸和覆盖场；素材系统负责源单位、根点、bounds、LOD及释放。不能二次随机位置和整体缩放，也不能为布局修改共享 Shader、光照或物理逻辑。树和植被继续使用现有 `runtime/` 适配；岩石/建筑继续 OBB fallback。任意真实资产的通用 resolver 仍需单独实现，不能把规则注册说成已有模型加载器。

兼容边界：`IslandPlan` 的旧 `buildings/rocks` 数据结构仍被渲染与生态环境分类使用。因此 `LayoutPlanAdapter` 的两类映射目前不能视为任意可交换的纯材质配置；它不影响内核互斥声明，但更换映射仍需验证生态派生。接入具体模型优先放在素材适配层，保持规划 ID 与几何不变。

POI 内部连接与全局道路都在体量之后生成。生态和心理地图消费最终道路。道路选取、规划视图、白盒和导演仍读取同一 `IslandPlan`；诊断分类色不是 Push/Pull 的职责标签。视觉覆盖目标是测试指标，不是直接乘到岩群高度的隐藏倍率。

单条全局道路或 POI 内部道路通过 `roadPath.keypoints` 保存 `[{id,x,z}, ...]`，顺序即经过顺序，坐标单位为米；只存中间必经点，首尾仍来自实际入口。LLM 先查询真实道路 ID、inspect 取得版本，再通过 `world.parameters.apply` 提交。道路面板使用同一 records 参数。清空列表或 reset 字段恢复自动寻路，不将采样后的道路和导航图当作作者参数存储。

必经点必须保留在最终路面与导航路径中；不可行时保留作者输入和诊断，撤下不可通行路线，仍可编辑修正。关键点不用于移动或自动新增吊桥；更换过河位置需要另行规划有效桥梁支撑。项目 DB 保存作者点，刷新时重新求最终道路。

### 当前可接的素材

- **程序化植被**：在 Asset Assembly 的 `generated/procedural-trees/plant-species.json` 唯一登记参数、材质、LOD 与 `vegetation.layer`；所有种类及变体自动进入对应候选池，显式 `seedWorld: false` 除外。乔木尺寸由 `offline/sync-plant-species.mjs` 根据最终参数测量后写回同一索引，主线程与 Worker 共用。展场与自然植被运行时读取相同登记，骨架树、独立灌木通过各自原生编译器适配。无需再编辑自然植被配方的名单或 `units/landscape.tree.json` 的 species。旧 `TreeSpeciesCatalog` / `SeedWorldTreeSpecies` 仍服务旧 Population 与内部预览，不决定当前自然植被的候选名单。
- **草与花**：沿用 [SeedWorldDetailSpecies](../src/SeedWorldDetailSpecies.ts) 的 profile、[SeedWorldProductionAssetCatalog](../../asset-assembly/SeedWorldProductionAssetCatalog.ts) 的 prefab/material/shader 链。[PlanningPopulationData](runtime/PlanningPopulationData.ts) 只映射覆盖和密度；草当前使用原 `cluster` 资源及 `Terrain/Grass`。不得按物种名字推测 prefab。
- **建筑**：[PlanningSeedSolids](runtime/PlanningSeedSolids.ts) 仅显示空间规划发布的建筑白盒体量，尺寸、位置与朝向归 `solid`。按用户要求移除额外的房屋外壳生成器及参数能力；旧 `buildingAppearance` 作者参数在加载时退役，原建筑体量和其他参数保留。
- **岩石与围栏**：仍由 [PlanningSeedSolids](runtime/PlanningSeedSolids.ts) 显示 OBB，尚没有通用真实素材 resolver。以后应在适配层用稳定 profileKey→已注册素材配方，消费原规划体量，保留明确 OBB fallback；无需重写路网、POI 或心理地图。

隆起带预览由 `terrain/TerrainBandPreview` 绘制，和高度场共用 `ReliefField.reliefSection`：虚线范围表示地势影响区域，中心线和箭头表示沿带方向。辅助显示可切换，不参与拾取，也不改变地形。

道路几何统一经 `layout/RoadGeometry` 编译：在完整路宽可用的前提下，按米制容差去除寻路网格阶梯，再用连续切向生成曲线。一个弯道无法容纳原曲率时只缩短该段控制柄；渲染器不再次插值。搜索网格点不是导航路口，导航使用发布曲线和真实入口。曲线不能穿过实体或水域；坡度是寻路代价和实测诊断，不否决体量或强迫道路退回尖角。

内部连接先接通体量端口，再发布实际连入内部网络的接入入口；最近连接失败时继续尝试其他边。全局主网按周边连接需求选择可用入口，入口到主网可绕行，候选主干边失败时尝试其他分量间连接。局部更新保留仍可用的道路，失败连接允许再次搜索；不能把上一次漏接永久当作最终网络。相关预算和偏好放在 `planning-data/road-network.json`：`curveSimplifyM` 是网格形状简化容差，`turnPenalty`/`slopePenalty` 是路径代价，`anchorSearchCandidates` 是入口绕行搜索预算，均不是体量布局硬约束。`maxSlope` 在路网中是坡度偏好基准，超出值进入诊断。

`layout/RoadTopology` 将关键点走廊编译成共享物理路段和真实交叉节点，`RoadNetworkReduction` 再提取最短连接骨架，去除独立搜索造成的小环/重复走廊，按道路冗余预算保留有实际内部空间的回路。POI 内部的新支路优先投影接入已有通道，而不是全部连向门口；逻辑旅程在共享骨架上重新寻路，原始端点和参数归属保留。逻辑连接保留参数归属；`roadSurfaces(plan)` 是俯视图、白盒和地面材质的唯一铺路输入，导航沿相同路段行走，坡度诊断也在重接后的最终旅程上计算。共享路段携带完整 owners，2D / 白盒选中任一所属逻辑连接都能高亮。共享路段保留参与连接的宽度及端点宽度，最终 spline 按稳定 ID 生成沿线宽度噪声；旧路面逐采样点宽度不再锁定形状控制点。内部连接在净空不足时有限次收窄并报告请求/实际差异，不移动体量。未接入主网且不通向内容的候选入口短桩不发布；候选仍保留在求解缓存，供下次道路搜索。

生产生成在骨架和跨河处理后调用 `layout/RoadAttachments.pruneUnservedRoadTails`，普通无内容导引尾端直接裁剪。跨河拟合丢失已选全局入口时才调用原有有限补接；避免把修复有效入口与装饰性尾端补环混为一谈。有效成员入口、服务真实体量的骨架端点、留白中心和全局入口，以及最终连通、净空、桥梁、导航和末端检查均保留。道路几何派生版本为 21，旧缓存重建；这一策略替代下文历史记录中无条件补接全部尾端的流程。

跨河几何在最终支路补接前处理，桥面支撑与道路元数据最后发布，断头路检查消费最终图。跨河和补接重建只输入唯一物理路段，逻辑旅程通过引用同步，不能重新喂入多条重复旅程或再次做生成树裁剪。物理路段 ID 包含首条边，起终点相同的并行路径也保持独立归属。水中分支点先沿已有道路移动到干岸，入射路段共享原有接近段，避免发布只到水中节点的半座桥；同一直线被拓扑切分时合并桥面。岸上接近段沿样条衔接桥梁方向，水中段仍为两岸直线；短转弯段按方向变化补采样，不能因长度小于采样间隔而漏掉整段曲线。

汇入搜索配置为 `branchJoinSearchM`、`branchJoinCandidates`、`branchJoinMaxDetour`，分别表示局部搜索距离、候选预算、绕行偏好。局部编辑优先复用仍有净空且目标仍存在的已接受汇入曲线和路口，批量恢复独立连接；不因重新排序候选而移动无关路口。`auditRoadTermini` 检查最终物理图的度为 1 节点，缓存重载也执行；连通分量为 1 不能代替末端去向检查。

派生道路缓存记录 `ROAD_GEOMETRY_VERSION`，升级只使道路失效，保留作者参数、POI 和已接受体量；DB 重载会重新发布同源的道路高度剖面、关系和归属信息。

## 验证和当前限制

重点回归入口：`SpatialVolumes`、`SpatialLayoutSession`、`SpatialFramework`、`PlanningComponentBases`、`PlanningStorage`；另检查地图/道路/花区选中、白盒、栅格与导演导航。

至少验证：显式互斥/允许拼接、空间索引替换、独立体量编辑不移动邻居、参数来源及重置、统一 POI 权重与邻域中心响应、休眠恢复、各组织的区域/尺寸/间距响应、Seed 保存重放、插件注册/版本/销毁、主线程/Worker一致。命令接受、派生数量、几何正确与视觉验收是不同证据。

当前局部编辑保留其他 POI 的体量。只改变高度且二维占地、入口、通路未变时，复用最终道路、桥梁与生态位置，仍重新核对三维碰撞和受影响的视觉引导。局部景观密度修改不重新发布未变化的路面/元数据；生态几何改变时重新生成视觉引导，避免刷新不一致。水域复用以物理输入相同为前提：陆域、POI 归属、自然地形参数、作者 Terrain patch/feature、basin 几何及水位、河流/湖泊规则共同参与水文失效签名。Terrain 编辑必须先重解自动水域，再生成河床、体量和道路；纯 colorRgb 不进入水文或 Terrain 物理签名。增量、冷生成和作者存档重放消费同一输入。全局道路元数据在桥梁与补接完成后发布一次。

它不是通用依赖图求解器：占地/入口改变时仍可能重建整套路网，生态和心理地图也仍有全图准备，未达到所有调参毫秒级。界面显示真实 Worker 阶段；只在诊断页显示约束、请求/实际结果。

## 节点与参数归属（2026-09-23）

包含关系、参数继承和编辑目标是三件不同的事。Inspector 只投影 `inspectSpatialSelection` 返回的当前对象；不会枚举祖先并拼接祖先的组件，也不通过 parameterOwner 把别人的控件塞进当前对象。相同组件的显式 base 仍解析成当前对象的有效值，修改只写当前对象，reset 恢复继承。

| 选择对象 | 可编辑内容 | 不应出现 |
| --- | --- | --- |
| 世界 | 全局地势、分布、连接和生态基础 | 具体某个 POI 的实例参数 |
| 陆地区域 | 该区域的景观基础配置 | 任意单 POI 的实例覆盖 |
| 单个 POI | 成员生成规则、间距、尺寸分布、内部连接、区域生态 | 其他 POI 或世界的编辑控件 |
| 单个体量 | 自身位置、尺寸、朝向、坡度与周边生态影响 | 所属 POI 的派生数量、权重和组布局 |
| 道路、花区、景观实例 | 自己提供的组件及局部覆盖 | 包含它们的区域组件 |

节点树中的一个 POI 只出现一次，统一列在 POI 组中；管理分区是该 POI 的空间表现，不另造管理节点。休眠候选标记“未显示”，仍可选中并调整权重恢复。组标题不选择旧 policy 对象；折叠、可见性和对象选择分离。

景观倍率允许任意有限非负值，候选布点密度和高度允许有限正值；删除生成器里的 3/4 倍、80 处/1000㎡、120 米等历史编辑上限。保留概率 0–1、坡角 0–90、上下限顺序与有限数校验。密度倍率改变已有候选的保留概率，概率饱和后不承诺无限增加实例，候选布点密度另行控制采样分辨率。极端请求超过计算预算时仅降低实际候选采样精度，保留作者请求，并在诊断中同时报告请求/实际精度；不会因此拒绝整次布局编辑。

### 区域归属与道路连通验收

建筑成员的完整 OBB 仍要求位于所属管理区域和陆域内。2026-10-28 按用户要求，POI 岩组的候选区域改为全图锚点分区，不再裁到陆地，完整 OBB 可跨海岸和 POI 边界；引导岩石同样不要求完整占地位于陆地内。区域仍控制候选分布范围，不要求跨岛分别覆盖整图。河湖重叠、显式互斥、既有坡度和道路净空检查不变，不新增用户参数。跨边界岩体产生的互斥依赖按候选范围传播失效，包含被拒候选和旧候选范围，按冷生成顺序重算依赖组；不相关组复用，存活成员不被主动移动或缩放。显式单体编辑继续独立于自动生成边界。

树形组织的体量入口随 OBB 朝向检测，第一面无法接路时尝试其他面；无外围可用入口时，从已接通的内容入口接入世界网络。组合体量不凭空生成内部路，世界接入点贴近真实体量。中心开放区轮廓沿接入方向变化，不再固定为圆盘。

`RoadGeometry` 接受位置/切线及可选显式宽度控制点，以 Hermite spline 编译中心线和逐点宽度。自动宽度是独立弧长函数，不能增加位置拐点；先确定共享物理通道，再在净空允许的长段补充 S 控制点。同一入口的近乎平行接近段先共享入口干线再分支，避免狭窄回折。拓扑切分、共享路段和网络化简保留边及端点宽度条件，路面宽度采样在最终 spline 投影时发布。入口 ID 是连通关系，曲线控制点是形状，两者不能混用。测试从一个实际入口沿边遍历，逐个确认体量可达，并验证最终主岛路网连通，而非将全部入口预先标成可达。

素材尺寸初值统一来自 `elementProfiles.<id>`，显式局部尺寸优先。旧 `elementProfiles.<id>.tiers` 仅供兼容迁移复原既有作者输入，不参与当前生成。

### 汇入切线与可协调宽度

道路拓扑在多路口选择最接近贯通方向的两臂作为局部主线，支路以横向切线汇入，避免把近乎平行的两臂直接捏成折返尖头。此处主线由几何关系决定，不绑定 POI 素材。补接道路也使用目标路段方向。

`RoadGeometry` 对无显式宽度控制点的道路，以稳定 ID 和沿路距离生成低频宽度变化；全局道路两端消费实际内部通道宽度，向道路基准宽度渐变。拓扑切分在原曲线上插值采样宽度，不能退化成全段统一宽度。网络化简后，度二连续接头按可行较窄宽度在局部平滑过渡；分支可以不同宽度。局部路宽修改最多影响直接相接道路的邻近宽度，不移动其他中心线。作者请求宽度保留，发布的 `widths` / `maxWidth` 才是实际铺路轮廓；导航与渲染消费同一结果。

净空不足时，曲线编译和全局/补接走廊搜索有限次尝试收窄（当前比例 1、0.75、0.5、0.25、0.125）。这是协调预算，不是道路最小规格或体量编辑拒绝规则；全部尝试失败仍进入诊断，不宣称任何宽度都能穿过实体。已接受路面用实际轮廓判断可复用性，不再按请求宽度重验旧网格。无几何变化时复用完整路网；体量或入口变化时统一重建道路，消除历史修补曲线导致的刷新漂移。

outcrop 使用统一的米制尺寸范围，避免缺档时回退为装饰碎石。此配置不绑定心理地图，不修改素材或碰撞内核；POI 和体量的显式尺寸覆盖优先。

全局路网归属统一由 `RoadIdentity` 判定：主干与 `road-attachment:` 补接段都属于全局道路，不能进入独立空间元素。规划图、白盒路面、地形图层和心理地图高亮使用相同归属。心理地图直接消费已发布的全局道路中心线（包括补接段），仅沿路生成引导岩体，不创建另一套路面；隐藏全局道路会同时隐藏全部补接路面。

体量间距针对独立 OBB 成员。上下限确定沿排列的稳定随机间距，不是所有成员两两距离的上界。环形/散布按尺寸与间距构造逐圈排列，接受时检查实际水平占地与非负下限；曲线按同侧 OBB 沿主轴的投影边缘步进，两侧净空独立控制。正间距不因位置失败而降级，负间距允许搭接但仍服从上层互斥。独立体量编辑不搬动其他成员。

POI 使用通用 `memberMin/memberMax` 指导自动成员数量；每个有效管理区结合当前组织、尺寸与间距生成。旧强制数量字段及离岛专用高度策略迁移删除，通用 POI layout / 单体 solid 高度覆盖保留。主岛与离岛共用元素初值，世界环境→陆域→离岛仍可调整本岛景观参数。

离岛景观参数按全局、所属陆地区域、单个 POI 覆盖。树木占地/道路/岸线判定使用树干，树冠可跨岸线；生境坡度采样使用地形而不是相邻岩体顶面。密度不是数量保证，候选采样、生境与实际占地仍参与生成，没有离岛 1–2 棵的数量上限。

引导岩体碰撞策略：不同引导岩体即使属于同一道路也不得相交，取消同岸拼接豁免；候选碰到已有占地或实体碰撞盒时直接舍弃该岩体，不通过换位置/缩小继续尝试，也不让已有实体为碰撞让位。同一逻辑岩体内部的构造 OBB 仍可拼接。引导结果记录碰撞策略版本，旧缓存缺少版本时重新生成，防止旧重叠岩岸继续复用。

离岛低海拔生态修复：取消生境采样中隐藏的树木 1.5 m / 小石头 0.5 m 低海拔淘汰及其渐变抑制；干燥陆地能否摆放由岸线、水域与实际占地检测决定。树木和小石头均使用地形高度采样，不将相邻地标岩体顶面当作地面；生境缓存只依赖地形与采样步长，岩体变化仍独立重算占地检测。Seed 1 离岛 6 纳入回归：默认树木恢复、提高景观倍率可生成小石头、倍率零可清空。默认随机抽样不承诺每个岛必有每个物种，不为特定岛硬塞实例。

景观密度系数与各环境带系数允许超过 100%，UI 与生成校验均只要求有限非负数；远离中心的保留比例仍是 0–100% 的混合权重。候选布点密度为全局参数，单位处/1000㎡，无作者数值上限；计算预算与占地可能使实际数量低于请求，应查看诊断。局部提高密度保留其他 POI 的结果。

景观衰减改为 `falloffRatio`（面板“景观衰减范围”，百分比）：默认 100%，允许超过 100%，0 表示内容外立即降至残余密度。按内容边缘与管理区/海岸边界归一化，不以圆半径近似；200% 仅放缓所属区域内部的衰减，不向邻居播种。旧 `radialFalloffM` 不再暴露/消费，旧存档升级到 100%，新字段已存在则优先保留。区域本身变化时需重算其归一化尺度，布局修改不再用百分比冒充米制扩散距离。性能测量与未实现优化边界见 spatial/PERFORMANCE_ANALYSIS.md。

### 区域构造式体量生成（2026-10-12）

`LayoutRule.build` 接收 POI 与实际陆地相交的生成多边形、Seed 随机流和已解析参数，一次返回候选 OBB 与可选连接骨架。海岸锚点净空不足时，以可用区域中净空更大的质心作为组织原点，一次推导，不搜索平移、不移动 POI 锚点。内置规则不再使用 `sample/sampleAll`、`PlacementSlots` 或平移评分；区域长度、尺寸与间距直接决定候选，内核只作一次占地/坡度/互斥检查。

修改组织重新构造本 POI；显式成员覆盖在可重建基准上应用。旧数量字段迁移删除，持久化仍仅包含 Seed 与作者参数，禁止存储生成几何解决重放问题。

道路接入点必须使用干地判定；跨河通道只允许道路经过，不允许把 POI 入口或支路汇入点放进水域。支路寻路只求一次通道，宽度交给后续几何适配。物理重合路段共用交点切分结果，逻辑道路仍保留各自归属。完整道路管线仍含补接、曲线协调与桥面发布，尚未完成单一拓扑一次编译的整体重构。

### 通用 OBB 与曲线排列（2026-10-12）

一个空间成员对应一个独立 OBB，有自己的稳定 ID、尺寸、朝向、单体编辑及连接口。不再把一排岩群隐藏为一个复合体量；普通分布、曲线两侧排列及沿路引导均不隐式增加子块。`CompoundVolume.ts`、片段数、搭接比例、厚高比例及断口概率配置已删除，不增加另一套“片段间距”参数。底层旧 `boxes` 数组接口仍兼容既有插件/旧数据，当前内置生成器每成员只返回一个 OBB。

通用参数直接作用于可见成员：

| 参数 | 语义 |
| --- | --- |
| 实际成员数量 | 只读结果，由区域、组织、尺寸和间距决定 |
| 宽/深/高上下限 | 每个 OBB 的独立米制尺寸，宽度不再表示整排岩群的跨度 |
| 体量间距上下限 | 相邻 OBB 的目标边缘间距；曲线中沿线排列。正值留空、0 相接、负值允许搭接，极端负值最多使中心重合 |
| 朝向变化 | 每个 OBB 相对组织方向的扰动 |
| 弯曲幅度、曲线方向 | 控制共享 S 骨架 |
| 两侧参考间隔、横向错落幅度 | 两侧平均位置与独立近远变化，不是统一内沿退距 |

间距上下限须形成合法范围；上限不是所有成员两两距离的上界。曲线以旋转 OBB 在骨架主轴的实际投影半径累计排布。正间距在该轴留下不少于目标值的空隙，横向错落和道路退让不改变该主轴坐标；负间距用同一个公式允许交叠，不依靠隐藏搭接比例。空间尺寸与间距自然推导骨架长度，横向位置和高度不改写道路骨架。

曲线 `build` 批量构造共享骨架和两侧 OBB。骨架跨度来自管理区域，数量和存活比例不控制它；海岸上组织原点可能随所需净空而调整；体量朝向采样实际落点切线。通道碰到岸线/占地时仅沿原曲线内收接入口，不搬动体量。所有通道仍使用同一个 RoadSpline 编译器；`roadMode` 显式控制内部道路，主干分割不因开关改变。连接缓存记录所有障碍查询范围，增量和冷启动使用同一构造规则。

曲线初始间距为 -10～-3 米，数量由区域长度和 OBB 尺寸生成。横向错落在保留完整 OBB 与基础净空的可用区域内取最接近请求的值，不缩小尺寸或沿曲线重试站位。尺寸复用原元素 profile（当前 outcrop 宽 36–64 m、深 20–40 m、高 16–36 m），不再另设 60–90 m 的“整组宽度”。这些仅是首次配置分布，不限制作者输入；旧数量字段被清理，既存尺寸与间距保留，不设置隐藏数量目标。

是否允许交叠由上层配置声明 `exclusions: { group, against }`，编译为显式 VolumeExclusion 对；空间内核不识别素材名，也不会仅凭负间距撤销互斥。当前可搭接组合之间允许相交，独立实体仍与所有实体互斥。占地坡度、接地、水域检查沿用原规则。主岛与离岛共享高度范围，旧 offshoreContents 仍在作者边界移除。

### 骨架编辑与表现绑定

上层初始化组合决定默认元素 profile 与表现绑定；同一 Seed / POI 的绑定不随空间组织、branchShape 或面积权重重新选择。`layout.elementProfile` 单独控制区域用途，与空间组织和管理面积分离。同名 connected 配方保留原抽样组合。当前内置生成器一成员一个 OBB，表现层消费已有绑定。旧 `pattern=curve` 迁移为 `connected + branchShape=curve`；当前 `poiAuthoringVersion: 2` 保留明确的用途覆盖，显式作者参数、局部作用域和冷重建继续保留。

实际几何测试与浏览器视觉验收分开记录，完整生成速度没有因此达到毫秒级。


### 参数独立性与组织随机控制（2026-10-12）

- 初始化先按 Seed 选择一次上层配置，随后切换组织只切换空间算法及适用字段；不重新抽间距、尺寸、朝向变化或表现绑定；成员数随新组织派生。未改的作者参数保持原值。
- 间距上下限在面板并排成组，回车/失焦共同提交。下限超过上限时保留可见草稿并提示未生效；不取中点、不挤回旧上限，也不偷偷修改另一个参数。命令/API 的倒置区间给出明确错误，调用方须提交有效区间。
- `spacingMinM/spacingMaxM` 控制沿排列方向的目标间距。曲线只比较同侧 OBB；横向由 `curveGapM`（两侧基础净空）控制。环形沿圆周按实际尺寸的包围圆与随机间距构造，不再只读取间距上限。它们仍是空间偏好，非任意环境下保证实现的所有成员两两最小距离。
- `pathWidthM` 仅影响派生道路，不参与 OBB 构造或组织平移评分。曲线帧适配检查实际可保留成员及其骨架是否在陆地内；不拿被舍弃成员的海上延伸当作现有通道。道路在最终布局中适配路宽或报告连接缺口。

新增作者控制仅三项；默认值位于 `layout/space-rules.json.randomness`，旧文档缺省从该配置解析，不向存档写入派生几何：

| 控制 | 适用组织 | 只负责 |
| --- | --- | --- |
| `variationSeed` 局部随机种子 | 全部 | 本 POI 随机流；0 是明确值，支持基础继承/reset，不重选素材或参数范围 |
| `radialVariationM` 径向错落幅度 | 组合、分支展开、中心留白 | 从基础环向外 0～该值的错落；不改尺寸、朝向及中心留白半径 |
| `curveVariationScaleM` 曲线变化尺度 | 分支连接的曲线两侧 | 相邻平滑极值的米制距离；同一随机种子下确定，不由数量或路宽设置 |

曲线弯曲幅度、方向、两侧基础净空、横向错落沿用既有字段。横向错落在基础净空之外变化（0～两倍幅度），左右两侧独立；0 恢复基础排列。骨架以 C2 平滑插值连接带随机幅度的交替极值，OBB 与道路意图共用同一骨架，道路仍由既有单一样条编译器发布。中心留白保持正半径，尺寸/朝向区间仍控制单个 OBB。模板不使用的控制在 Inspector 隐藏，存储值保留，重新切回模板可复用。

这是参数职责和确定性修复；区域内没有符合尺寸、净空、坡度与显式碰撞关系的位置时，实际数量可以为零。接受命令、实际数量/连接满足情况、浏览器视觉验收分别判断。当前全事务仍包含道路/生态，性能证据见最新实施记录，不将体量阶段耗时当作完整响应时间。

## 内部道路与局部生成（2026-10-12）

`layout.roadMode` 是 POI/类别共用的枚举参数：`none`（无）、`backbone`（仅骨架）、`members`（骨架＋成员支路）。各组织独立选择铺路方式；设为无时仍保留全局道路接入口，曲线骨架仍用于排布 OBB，中心留白仍是开放区域。无道路时隐藏通道宽度，保留控制 OBB 排列的曲线/留白字段。

删除了 `scatter`／“组合体量分布”注册项；原来的独立散布能力由“分支展开＋无内部道路”表达。上层配置保留原抽样顺序、权重和 Seed，切换组织不改变道路模式或表现绑定。旧 `scatter` 迁移为 `connected + radial + none`，旧 `memberBranches` 的 true/false 分别迁移为 members/backbone；旧 scatter 下该布尔值原本无效，仍迁移为 none。作者边界兼容类别继承及 Seed 归档，`layoutVersion: 2` 标记已处理旧默认值；不保存生成结果。

曲线骨架链接带 `backbone` 派生标记，避免未选中的世界接入口裁剪时连骨架一起删除；最终路网阶段继续处理其接入。 分支展开的体量周边骨架点通过派生 `servesVolumeId` 声明服务对象；即使关闭成员支路，它仍是有效通道端点，不参与回接或废弃支梢裁剪。该引用必须指向实际接受的体量；不能靠空标记保留废弃道路。中心留白的中间导引点及未选用的外部入口仍是候选，最终只保留通往留白中心、成员入口或已用世界入口的路径。仅显式贯通曲线保留 `backbone`，避免末端补接把导引支梢接回自身形成重叠回路。补接曲线在第一次遇到已有道路时结束，并立即在本批次的轻量工作图中切分路口，后续补接消费已更新的连通关系；完整路面拓扑仍只在批次末编译。补接不允许沿原路制造狭窄回环，也不把无目的地的末端接回同一组织内部形成自回接。预算内找不到有效接入的非目的地支梢逐级裁短，真实成员入口、有效骨架服务端点、留白中心和已选全局入口保留；逻辑旅程、导航、路宽及规划归属同步消费裁剪后的物理路段。已选全局入口即使该 POI 实际体量为 0，仍是有效目的地。该标记不是作者参数，不增加存档几何。道路模式只影响连接生成与下游道路/生态，不重采样 OBB、移动 POI 或改写其他作者参数。

旧回退协调已删除。候选失败不再缩短间距、改尺寸、消耗其它成员的槽位或扩大分布范围。实际数量只来自成功放入当前区域的成员；负间距仍可搭接，并服从显式互斥。

### 全组织道路回归

历史道路回归覆盖有限 Seed 的多种 POI 组织及 none/backbone/members；当前统一候选模型需继续检查邻居体量稳定、作者冷重放、最终道路自交/回环/端点/连通和导航接缝。历史测试数量不自动构成本轮模型变更的验收，真实页面与当前测试结果另行记录。

程序化植被参数直接由原模块暴露：`ProceduralPlantStructure` 描述形体，`PlantInstanceVariation` 描述叶色、树皮色、叶片大小/密度等实例参数，`ProceduralPlantLibraryRuntime.load` 消费原始参数与 `colorForSlot` 材质槽颜色。上层直接提供这些参数；生态发布分布及共享物种目录派生的 `appearance`，包含独立的 foliage/bark 曝光和色度目标。`plant-species.json` 的 `foliageVariation` / `barkVariation` 以 Seed、物种组、片区身份与单株身份定址采样；叶色覆盖蓝绿到黄绿，并允许片区内部色相差异。素材纹理明暗保留，邻区边缘平滑衔接，各 LOD 使用同一结果。真实材质角色决定应用位置，花瓣/菌类不被叶色染色。季节继续拥有整体调色；显式 `plantMaterial` 通道在生成色之后覆盖（含 0），reset 恢复生成来源。`data-vegetation.foliageColors/barkColors` 统计真实 renderer 输入的亮度和归一化 RGB 色度范围，不能替代最终屏幕视觉验收。Seed 适配器保留源 renderer 的部件参数，原生 Terrain/Grass 继续使用原 `SeedWorldGrassColorFieldTuning` 及同源 RG8 渐变。地被从同一目录的 `groundCoverVariation.brightness` 继承 0.8–1.2 倍明度，仅 leaf/shrub 槽使用当前位置的草地色场，花瓣不变。Seed + 物种 ID 采样固定偏差，六种地被无需逐一登记；同物种和所有 LOD 共用偏差，空间颜色由草地 RG8 场连续变化。材质跟随草地配色实时重绑，季节共用 Grass 规则；地被只启用 `MATERIAL_VEGETATION_SHARED_GRASS_COLOR` 颜色继承，保留本身的法线、纹理、透光和天气响应，不使用低草的贴地法线/根部融合；两端点统一缩放并整体限制色域，避免改变色相。±20% 指基础配色，最终像素仍含光照和遮挡。

原生 recipe 素材在 `PlantSpeciesSources` 的适配层提取有效部位颜色，白 RGB 叶片 Mask 的颜色载体归一化，保留明暗梯度；统一进入 renderer 配色规则，避免原生绿色再乘新色。原始资源保持不变，旧 recipe 的显式颜色倍率仍兼容。

世界表现组件 `grassAppearance` 通过既有 `setSurfaceColorTuning` 提交该渐变的两个线性 RGB 端点与饱和度，草地、低草及自然植被库的草类槽共享同一份颜色；草类的显式 `plantMaterial` 通道仍可覆盖，reset 清除覆盖后恢复色场继承。树冠、树皮和花仍由 `plantMaterial` 的原生材质槽负责。

树木/既有岩石周围的伴生组合由共享 `VegetationCompanionPatches` 生成有限椭圆斑块，尺寸随实际锚点半径缩放。各林下层共用斑块，但继续自己的物种、尺寸、密度和花区配额；道路/水体/实体占地仍不可进入。按解析支持范围筛选流式分块锚点，`companionGroups` 诊断真实驻留群落。未新增岩石模型、未改变已发布岩石的位置；本分支仍显示岩石 OBB。

### 主体展示相机

`subjectView` 是世界表现组件，通过稳定主体体量 ID、垂直 FOV、主体包络取景比例、相对入口观察角及可选米制距离设置相机。建筑与岩石共用实际 OBB 包络；复合体量由所有部件的水平旋转角点与垂直端点求包络，不把分类或一个主盒当作整个对象。距离根据包络外接球与实际视口解析计算，不修改布局或出生点，不进行构图搜索，也不保证遮挡结果。原生 `PlanningSubjectView` Script 与 Scene Asset 编解码同步作者数据。首次进入 3D 时优先于默认出生取景；参数改变时重新应用，随后仍可自由漫游。明确选择“沿用当前漫游视角”会清除作者主体，相机保留当前视角，下次进入回到默认出生取景。省略显式距离会 reset 旧距离并重新按包络计算。

### 花的分布场与一次采样（2026-10-28）

用户授权花作为点缀，取消精确面积与补足配额。`flowers.coverage` 控制连续噪声分布场的覆盖倾向，0 关闭、1 覆盖可用预览区域，不再用面积积分二分求阈值。道路/广场影响直接改变局部分布，不把别处的缺口补回来。预览用 12 米美术网格一次裁切并合并轮廓，`areaM2` 和 `eligibleAreaM2` 仅描述预览；删除 `requestedAreaM2`。POI 边界混合、花区局部覆盖、set/reset/base 和保存重放继续保留；旧 coverage 数值按新的美术语义消费。

原生 3D 消费同一发布分布场：每个驻留分块只有一条世界坐标寻址的候选流，按所在区域查询密度、品种权重及坡度上限。花不再按每个区域重复扫描整个分块，也不做第二轮沿路倍率采样；沿路花效由 `flowerInfluence` 决定。`densityPerM2` 是候选率，自然植被野花比例进一步筛选候选，淘汰后留空。实际植株的完整包围占地继续避让道路、水域、实体、广场与农场，并检查实际地面坡度、接地和可见性。诊断只报告 attempts/placed/rejected，没有目标数量或 shortfall。

相机只控制驻留与既有显示距离，驻留花丛数不等于屏幕可见花头或全世界数量。草地、程序化形体、Shader、LOD 和 Engine 的表现策略保持既有实现。通用 Asset Assembly 的 `populationAreas` 契约供其它调用方继续使用；Seed 原生花已不走该路径。

### 关键点路网与 spline 投影（2026-10-28）

路网先在入口与避障走廊关键点上构造共享连接图，合并公共段并选择有价值的物理边，再确定桥头和直线跨河段。`RoadGraphSplines` 最后对各条物理边生成一次 spline，桥头不得被简化，水上段保持直线，路宽噪声继续使用稳定 ID。逻辑旅程引用已选物理边，不再从曲线的密集采样点全图重建拓扑。

曲线候选仍通过完整路宽占地校验，并用邻边索引拒绝未声明的曲线交叉；受阻弯曲仅收缩该边的控制柄，保留经过相同校验的原走廊。缓存以控制走廊、相关邻边、实体和水域输入为键，命中仍验证当前几何。此轮没有把所有作者编辑都变成增量组图：入口或路网意图变化仍重新构造稀疏连接图，只有曲线投影可以复用未受影响的边。岸上引道中位于另一车道内的中心线共享支撑高度，桥面、坡度和真实步行校验继续保留。

### 路边伴生与低草高度关系（2026-09-23）

按用户参考图，生态层维护“低草铺底、花灌木显露、路边成簇并留通路”的关系。`landscape` 的世界作用域开放低草相对花灌木高度、高度变化、路边低草相对高度，以及道路／岩石墙脚伴生带的宽度与倍率。默认配置在 `natural-vegetation.json`，没有固定米数的低草高度配置。旧工程缺省读取配方；显式 0 适用于带宽／伴生倍率，高度比例为正，个体高度变化可为 0。字段经 Session set/reset 及保存重放，在景观增量阶段发布 `naturalVegetation.settings`；不重建道路。

已加载的程序化素材 LOD0 实测高度 × 现有配方生长比例给出各层尺寸。低草以当前区域启用的最矮灌木、花区内启用的最矮花为参照，乘相对高度；没有花灌木时使用草本自身的素材尺度。道路边缘再按距离平滑压低，离开伴生带恢复群落比例。这是区域物种规则，不声称逐株寻找最近的花。求解结果以米制高度区间场进入原有 Population 数据，原生草在实例生成时消费；草的位置、叶宽、密度和颜色参数不被高度规则改写。高度编辑沿用原候选 seed，支持高度场复制与 Worker buffer 转移。原生调试面板手动设置绝对草高时属于显式临时覆盖。

伴生带沿已发布的实际道路轮廓以及岩石、建筑轮廓布置；道路闭合带的双桥连接通过现有地表三角化表达，不改道路形状。灌木和地被沿固定候选采样边缘富集与平滑带外衰减，高草不随伴生倍率增密。花使用上节的独立分布场，沿路影响由 flowerInfluence 提供，不再叠加此伴生倍率。道路及实体保持实际足迹净空；候选被拒绝后留空，花只报告实际采样与发布数量。

## 固定底图与局部编辑（2026-10-15）

`PlanningDocument` 保留轻量作者数据；`IslandPlan.spatialLayout` 保存可重建的底图和当前投影。全局/局部生成参数分为 `replan` 和 `reveal`，单体几何字段标记 `instance`。分类由字段 schema 提供给面板与 LLM，快路径不靠工具名字猜测影响范围。单体变换同步成员入口、关联道路的物理路段与导航引用；无法满足陆域、水体或体量净空的连接暂不发布并返回诊断，体量编辑仍保留。桥梁拟合或引道失败同样只撤去不可用连接，不拒绝整次作者修改。

林下伴生使用当前树木/岩石锚点和占地；单体编辑重算新旧锚点支持范围内的驻留分块，未加载分块随后读取同一新规划器。冷重放使用相同最终锚点，不固定在未编辑前的位置。

`reveal` 只在固定候选中选择，不重新布点、不补位、不触发约束搜索。2026-10-27 起，候选与物理发布对象分开：树在首次显露时才检查生境和完整底面接地；岩石为花区提前提供生境合格的占地，接地同样按需执行。降低密度或重复显露可复用已计算结果，提高密度可能新增地形采样，不能再承诺所有显露都是零采样。原生植被只预建可见实体，新实例经已有事务暂存、提交或取消；潜在树冠候选仍为伴生分布提供稳定参考，不作为已通过物理校验的树发布。`instance` 在投影末端覆盖目标对象，可重叠且不改生成占用。主岛、POI、道路、水域等输入变化走规划。单株增删与区域显露是不同原子能力，由调用者决定组合策略。

`planningGroundSurface(plan)` 提供与实际 Float32 三角网格一致的局部接地查询；只有需要完整贴图/几何的发布消费者调用 `planningHeightmap(plan)`。禁止为了一个对象或作者查询预先分配整图。完整图、Water、建筑 worker、农田和运行时均消费同一高度表示。


### 2026-10-19 水体简单编辑（#78 A）

`PlanningSession.dispatchParameters(commands, expectedRevision?, { water?: { mode?, rebuildShoreVegetation?, affectTerrain? } })`
与 `water.create/update` 的顶层 `edit` 使用同一策略。颜色/固定床面水位默认 simple，两个布尔项 false；创建、删盆、深度/形态默认 complex。simple 请求改床明确 `TERRAIN_CHANGE_REQUIRED`；显式 simple+true 拒绝。省略 mode、显式 true 选择 complex。A 的 complex 暂用全量发布，无法遵守 false 的请求明确拒绝。

简单通道只更新一个水体的外观，或水面/岸线/HF/SDF/查询，保留 Terrain、植被（含水掩膜/资格/贴地）、农场区域/服务/存档与其它场景 owner。按 2026-10-19 A3 补充要求，水位原子发布后轻量刷新农场水体 grounding 和 ground revision；物理地面与占地检查延后到下一次查询，不通知表现层同步重算全部格子，颜色-only 不刷新。既有设施的保留政策不变，新扩建仍检查最新物理水域。颜色不做水盆闭合采样；fill 保留严格最终 Float32 床面的实际岸线校验；自然湖仍拒绝漫岸/空水域，作者湖可在 minimum 干涸。独立 `waterUpdate` 由完整前后作者值分类，未知/多水体/混合编辑记录 `waterFallbackReason` 并回退全量；不改变 `contentUpdate` 契约。

作者草稿只校验/求解，不准备空 live publication；外层项目只准备一次最终投影。undo/redo 从当前与历史文档重新分类；显式 complex 选项随会话历史保留，不写入作者存档。`PlanningSeedScenePublication.prepareWater` 同步接受 Water Host batch 与水体 plan，失败/取消保持旧场景，simple 不暂停引擎。

D4 已确认覆盖层在规划结果之上、旧档先比对有差异走旧流程；覆盖层及复杂局部 Terrain/植被发布留在 B/C，A 不修改 Worker 求解语义。2s 目标仅指真实 Chrome WebGL2 无探针 p95 max(resolve,首个正确帧)，自动化 CPU/Host 测试不等于该性能验收。

### 2026-10-19 作者水体覆盖层与 Worker 窄结果（#78 B）

新建 Seed 文档带 `waterAuthoringVersion: 1`，只保存作者语义版本和作者输入，不保存全局 base 或高度数组。全局 base 从同一 Seed 和非作者水体输入生成；作者 `water-body` / `river` 在其上切削，保留自然水文、道路、桥头/桥面、建筑、岩石、guidance 和农场选址。桥头 grading 先完成，作者切削后施加，不自动修路、搭桥或搬建筑。自然湖参数仍属于全局输入；简单 fill/颜色继续走 A 的独立通道。

`PlanningWaterOverlay` 缓存最多两个完整非水输入基准。作者湖以全部当前盆地 support 加一个格网 halo 重算最终 canonical Float32，并从独立 base 恢复删除/缩小区域。景观用有限 source/物种/采样/thinning halo 的 scoped basemap，保留完整候选权重、固定 guidance 成员和实例作者覆盖；花区按受影响 owner 重算，包括尚未显露花区的显式 owner。作者河流沿用现有无界 grade limiter，因此保守全世界 support 并记录原因。全图 Float32 复制、min/max 与 R16 重编码仍存在，单独计时，不降低精度。

未带版本的旧档比较 legacy 与 overlay 的输出和 canonical 床面；已发现差异就保留 legacy，并记录 `legacy-difference:*`。兼容比较不改存档。无作者水体的旧档可等价启用；资源工具首次实际编辑才写入新版本。未知版本（含 Seed 归档）拒绝读取。版本 1 的混合/非水编辑或基准丢失走 full overlay 重建，不能换回 legacy。

`PlanningWorkerRuntime` 每个 Worker 生命周期保留调用者基准及最新快照。`water` 响应仅含作者水体、profile、景观/花区及相关诊断字段，保留主线程未变道路/实体/农场数组；高度只传旧/新 support 对应的格网 tiles，不 transfer accepted buffers。请求/响应验证运行时、请求基准、全局输入及 canonical 字节 token，主线程在私有复制验证完后才 adopt。Session 拷贝继承 owner/generation/requestId 元数据；取消终止旧 Worker，重启回传完整基准。2D-only 基准没有完整高度图时返回完整高度结果，不为单次查询强制构建全图。

B 的复杂编辑仍走现有完整原生 Raster/Terrain/植被/场景准备和原子发布；局部原生发布属于 C。CPU 求解与 structured-clone 协议测试不能替代真实 WebGL2 浏览器全链性能验收。

## #78 C：复杂水编辑的局部原生发布（2026-10-19）

`PlanningWaterPublication` 在全量候选及 pause 之前验证仅水作者意图、overlay 语义、格网和不变固体/道路/农场 owner。未知、混合、旧档差异、活动高度动画及新增 river-bed residency 记录 reason 并走完整路径；simple 继续 A/A3。创建/删盆/深度/半径和 complex 水位准备新数值快照，复用道路距离和外观，局部 GPU height/alpha 上传；R16 decode 改变必须完整 Region 重编码。通用 `TerrainClipmap.prepareRegionUpdate` 准备独立 normal/puddle 候选，保留 canonical Float32、全图 normal 与跨 Region priority-flood 正确性，直到领域接受后才退休旧纹理。

受影响域包含前后水岸、实际变动高度顶点以及材质/生态/密度 texel 和 halo。native grass 只准备受影响驻留 cell 的完整隐藏 GPU buffer，自然植被只替换变化树株和受影响驻留/可见 understory cell；范围外 root、GPU owner、共享物种资源保持。准备过程分批让出事件循环，引擎继续运行；驻留变化导致候选 stale 拒绝，未显示 cell 以后按新快照生成。

Terrain、植被、后续建筑编辑的地形支撑快照、固体 plan 元数据、navigation/audio 和 publication revision 同步可回滚提交，Water Host batch 为最终边界；失败/取消/过时丢弃候选。岩石、桥梁与建筑已有几何保持，不调用 RockFormation 全量重建、Masonry initialize 或完整场景 publish，不自动移动固体。农场保留 service、存档和 presentation，接受后更新同版 Terrain/Water 懒查询并通知接地，随后简单水编辑仍保持 A3 契约。`canvas.dataset.waterImpact` 记录 local-native/fallback 和 Raster、数值准备、Terrain atlas/relief、ground population、自然植被分段耗时。复杂模式没有 2 秒 SLA；CPU/Host/GPU stub 回归不等于浏览器画面或帧时间验收。

C 的 masonry 每个已接受 entry 固定自己的 Terrain 支撑快照，后续细 LOD 流入仍使用该快照，避免水编辑后切 LOD 改变现有建筑；只有显式建筑编辑才切换到最新 Terrain。准备中的建筑编辑使局部水候选 gate/full fallback 或 stale 拒绝。

### C2：生产密度下的准备调度与诊断

复杂编辑的 Detail compaction 以原有 64 候选为取消检查/计算 chunk，在既有 2ms CPU slice 内连续推进，只有 slice 用尽才让出事件循环。不能对每个 chunk 单独 `setTimeout(0)`：浏览器嵌套 timer clamp 会在生产密度下累计到外层 Agent 150s 超时。候选数、密度、GPU buffer 完整准备与原子接受边界保持；取消仍释放隐藏候选并保留 live。

`waterImpact` 在当前 local/full 准备开始就写入 `mode`、`phase:preparing` 和当前 fallback reason，成功后写 `phase:published`。初次生成时的 `no-current-native-water-base` 不能证明后续编辑走了 full；投影失同步单独记作 `projection-out-of-sync`。无头真实回归使用 `e2e/seed-world-water-publication.playwright.config.ts`，复用显式启动的 18765 服务，不启动或停止服务；完整生产格网/草密度验证首次 Agent create、混合 full fallback 与 undo/redo。复杂编辑耗时不等于简单模式 2s SLA。

### C3：复杂编辑的草地范围与重复投影

初次和后续 native population 都使用同一物理水面查询，避免首次作者池塘将全图从材质阈值掩膜切换为物理掩膜。草地候选 seed 由世界 seed 与 prototype 决定，局部密度变化不重播其它 cell。粗 dirty bounds 仍覆盖真实生态变化；草地逐 cell 比较实际 canonical 顶点/normal halo、材质/水、密度与高度区间采样，只准备真实变化及精确水体前后 footprint 相交的驻留 cell。互不相连区域之间的空隙不再重建；水面 profile 变化及 river-bed 层变化也包含在支撑中。

局部准备使用8ms CPU slice、原64候选 chunk 和 MessageChannel task，成功/失败均关闭端口；无 MessageChannel 的环境才回退 timer。完整草地投影按行和64KiB hash块协作执行，采用12ms时间片。最多保留两个完整投影；生态/管理区/道路/农场/素材/格网/候选依赖一致时，私有复制旧输出，仅重算变化的草/花 texel。花区高度域改变仅影响存在花覆盖的 texel；min/max和hash完整重算。道路高度因子以 Float64 复用，保留原 JS 浮点运算结果。冷准备或依赖变化仍用同一完整算法，不把缓存当作者数据保存。

测试覆盖生产1024格网的dirty cell/完整候选数、采样halo、范围外owner、task端口生命周期、取消、完整/增量投影字节一致及依赖失效。当前性能验收增加与B的对照：两个池塘不得慢于16.1s/11.9s，最长long task不高于约2.4s；指定脚本的最终实测、河流分段及限制见 `/tmp/timi/78a/result-c3.md`。单次开发版无头结果不等于无探针p95或移动端验收。

### 地势与水域数量范围

全局 `terrain`、`rivers`、`lakes` 公开 `countMin/countMax`，上下限共同提交。生成时按各自 Seed 流稳定采样候选数；河流、湖泊仍经过实际空间筛选，少于下限只报告结果，不补造。旧 `count` 在导入时迁移为相同上下限，不改变原布局；手工添加的水域独立于自动候选范围。最终数量由已生成布局统计，不把范围端点当成实际数量。
