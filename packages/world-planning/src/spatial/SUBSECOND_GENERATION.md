### 实际删除的工作与保留的约束

`LandscapeCandidate` 明确表示未完成接地的候选；候选不进入 `plan.landscapes`。先用密度、来源、径向衰减拒绝不可见候选，树仅对将显露的实例执行生境和完整底面接地。岩石为花区提供原有生境合格占地，完整底面接地同样按需执行。发布前仍执行原坡度、海拔、适生性、占地/道路/水域碰撞与精确接地，不降低网格精度。新出现的对象经原生植被既有事务准备、提交或取消，初始不再创建整张底图的隐藏树 Entity。

沿路引导先决定自己的有效占地，环境候选再避让；不再把几千个未发布候选当作物理对象反复处理。潜在树冠仍作为稳定的伴生分布参考，不等于已通过生境检查的物理树，陡坡周围的伴生分布可能因此变化。花区只对遮罩合格单元求高度和归属权重，原 6m 网格、精确面积校准和坡度约束保留。沿海衰减用空间索引筛选可能相交的海岸段，最终仍用精确射线相交。

农场尝试过按距离优先、首个可行结果提前停止；Seed 2 产生更多失败设施检查并明显变慢，已完整撤回，最终六轮不含该实验。不能将距离近当作农场设施可行性的替代条件。

### 道路为什么优化后仍然贵：完整链路

第一轮删除的是匿名尾端反复寻路补接，并保留真正失联入口的有限修复。该工作已经生效；它没有覆盖下面全部阶段。道路耗时高也不等于路网功能不合理。

| 顺序与职责 | 当前处理及必要性 |
| --- | --- |
| POI 内部道路、选入口 | 保留服务端点与内部通行，不随意删除有目的地道路 |
| 全局连接选择、障碍栅格、走廊寻路 | 仍需跨区连接及完整路宽净空；本轮仅在原始走廊已经通过完整校验时延后逐旅程样条 |
| 共享骨架、交点、物理链、样条 | 将重叠旅程合并成实际物理路段；仍需处理曲线、宽度、平滑失败回退 |
| 曲线后的交点重切分 | 样条能产生新交点，不能直接删；本轮改为输入唯一物理路段，避免再次展开重复旅程 |
| 岸边连接、过河桥头拟合 | 会移动接点与路段；发生变化后必须更新物理图，不能沿用旧交点 |
| 入口补接、尾端裁剪 | 已只修复必要失联入口；普通无服务尾端不再反复补环 |
| 桥梁结构、支撑、坡度与最终发布 | 保留桥梁、接近段和物理支撑；最终成员归属、旅程、终点及坡度检查仍执行 |

当前底层已使用三次 Hermite 样条，但上层叠加了网格 S 偏好、弯曲噪声、两端点补 S、样条控制柄调整与多轮几何反推拓扑。上层允许不同规则生成节点与控制柄，底层最终几何只由一个 spline 编译器生成；不再叠加多套道路采样算法。文首记录了本轮已移除的重复控制，完整拓扑编排仍是后续工作。

- 路网节点拥有稳定 ID、位置和连接关系；入口、汇流点、桥头是拓扑节点。中间形状控制点不是路口，采样点不是作者参数。每条边引用共享端点及自己的形状点；每个端点的方向/控制柄按入射边保存，允许同一分支节点存在多条不同切线。
- 形状点使用位置、切线方向/控制柄长度、逐点路宽；样条插值和宽度插值统一。自动 S 形只是一种生成这些控制点的规则，统一用横向摆幅与沿程弯曲尺度表达；不再同时用寻路偏好和另一套补 S 逻辑重复控制同一形状。
- 连接规则选择拓扑，局部避障负责取得安全通道并生成/调整该边的形状点。spline 只表达曲线，不替代连接和避障；通道内构造、最终真实路面验收保留。障碍索引与邻接数据共用，禁止遇到局部问题便反推并重建整图。
- 路口共用同一节点，交叉需要连接时显式切分相交边，共用路段只保留一条物理边。桥边约束为两岸直连，分支位于岸上。最终拓扑确定后生成路面和路口，调整只重编译受影响边及其相邻路口。
- 先生成最终道路，再按道路生成紫色引导岩体。引导体量的厚度与引导通道参数不再隐式改变道路寻路偏好；沿路放不下时协调/舍弃引导体量，不反向重建道路。心理地图与物理道路共用一份路网。

用户参数与自动初始化、内部采样精度分开；旧 `bend` / `sBend` 等作者值的迁移需单独规定并验证，不能静默丢弃存档。上述新参数与替换管线尚未实现，不能将当前样条底层当作新架构已完成，也不能未经原型测量承诺毫秒耗时。

### 一条生成路径

`作者参数 + Seed → POI 区域/邻接与地势水域 → 区域体量及连接意图 → 唯一道路拓扑/共享渡口 → 平滑曲线及可变路宽 → 引导体量与生态 → 精确验收 → 原子差量发布`

1. 区域与环境查询只编译一次。生成阶段共用真实轮廓、地形采样和水域数据。低分辨率格子只提供保守排除与寻路代价；不以“中心格没占用”证明完整 OBB 或曲线无碰撞。规划与真实 3D 继续消费同源高度，1024² 输出不降级。
2. 每个 POI 的规则一次给出成员形状、偏好排列、端口与连接意图。共享可行位置集合按尺寸类别和空间邻域索引，避免每个成员重新遍历/排序整套位置。先用边界/净空的保守下界快速排除，再对接受候选做真实 OBB、可配置坡度及完整底面接地检查。复杂区域可以有局部协调，但不增加全图重试；找不到时报告请求/实际缺口，不能靠少生成内容宣称提速成功。
3. 道路使用 POI 邻接图选择稀疏连接；不强制道路沿 POI 边界走。每个管理区的自由空间连接图供内部通路和世界道路共用。粗图只选择经过区域，局部在最终体量之间求通道；不可行时扩展真实邻接候选，不能因为粗图漏连便宣称无路。共享路段、交叉与近邻渡口先变成明确的节点/边，逻辑旅程只引用物理 edge ID。
4. 每条最终物理边正常路径只做一次几何编译。入口、汇流点和岸边桥端固定；中间用 spline 控制点表达 S 形，局部净空决定宽度。编译器内部可自适应细分、缩控制柄、缩宽或沿同一通道调整，不能再将曲线展开成多份逻辑路线重新拼图。新交点只切分受影响物理边。桥面两岸直连，分支在干岸。
5. 引导岩体在最终道路后放置，避开实体与已发布路面；不足的视觉覆盖明确诊断，不触发道路—岩石全图循环。再筛选普通景观，保持引导优先级。生态候选按 Seed、空间块、候选编号稳定生成；密度参数阈值筛选，衰减只改所属区域权重。花区可采用连续噪声场，但形状改变需单独验收。局部稀疏化只读取有限邻域及候选优先级，不通过全图贪心接受顺序传播。
6. Worker 拥有权威生成状态，主线程接收变化 ID/范围与紧凑数据；UI 和 3D 适配器消费同一发布版本。需传输的发布缓冲独立持有，不转移 Worker 仍需使用的索引原数组；TypedArray 本身不是 transferable，其 ArrayBuffer 才可转移。取消在短批次边界发生，发布前复查 revision；不显示混合版本的半成品。

### 碰撞语义不能混在一起

| 对象关系 | 验收及协调方式 |
| --- | --- |
| 两个声明互斥的逻辑体量 | 空间索引粗筛 + 朝向/高度精确 OBB 检查；只协调本次修改对象。同体量内部 OBB 继续允许拼接 |
| 道路与阻挡体量 | 检查完整变宽路面边界，不只查中心线；先收宽/减曲率/局部绕行，不能发布穿透实体的路面 |
| 道路与道路 | 允许连接，交叉/共享段必须成为真实拓扑节点/边；不是互相绕开的障碍物 |
| 道路与河流 | 普通路面避水；跨水段必须对应两岸桥面与通行高度，不把整个水域当绝对禁区 |
| 树木与景观 | 使用真实阻挡部分（如树干/岩体），不把树冠或花区变成所有对象的碰撞墙 |

曲线平滑后仍需验证最终路面。稀疏采样点不提供连续无穿透保证；对发布折线带/多边形进行精确验收，若消费连续 spline，则用曲线包围与自适应细分的保守误差界。保持已授权的可配置坡度规则及接地行为，不顺带增加最低面积、广场或密度硬约束。

### 局部更新与确定性

维护“组件/环境块 → 消费它的 POI、候选与物理边”依赖，不仅记录最终占用，也记录候选查询范围；移除障碍时，原先被阻挡的候选同样可能失效。变化范围是旧占地与新占地的并集，加道路/景观真实查询所需邻域；远隔修改用集合表示，不合成覆盖半张地图的大矩形。

| 编辑 | 允许失效的范围 |
| --- | --- |
| 单体高度 | 本体接地/三维互斥、实际受影响视觉引导；二维占地不变则路网不变 |
| 某 POI 数量/间距/尺寸 | 本 POI 成员、与变更占地相交的物理道路、相关景观/引导块 |
| 某 POI 景观密度/衰减 | 所属候选块及稀疏化邻域；不枚举全图，不重建道路 |
| 单条道路宽度/曲折 | 本边及连接点相邻边、沿路生态/引导；不全图重新寻路 |
| 局部河形/地势 | 实际相交区域、接地体量、桥/路段及环境块 |
| Seed、全局 POI 分布 | 确实重建全图，不能伪装成局部更新 |

邻居体量默认只读；默认采样归属是 POI 管理区，不把区域边界新增为实体墙。跨区对象必须登记真实占地依赖，不能因为 owner 不同而漏碰撞。全局字段实际影响全图时不能承诺只算一个 POI。

随机性只由 Seed、最终参数、生成器版本及稳定对象/候选 ID 决定，线程顺序与 revision 不参与随机。局部修改与冷重建必须对照；尤其要测试增大→缩小、删除障碍、改变先前被拒候选的情况。跨区顺序依赖若导致重放变化，必须修正候选/依赖设计或记录必要的显式作者坐标协调，不能用旧几何存档掩盖；不能未经验证承诺“所有跨区变化都严格只算一个 POI”与“所有邻居完全不变”同时成立。

### 落地顺序与删除边界

1. 先替换道路：内外连接只产出意图，共用唯一物理图；将 `GlobalRoadNetwork`、`RoadTopology`、`RoadAttachments` 与 `RiverCrossings` 中的重复几何重建收拢到最终编译器。保留桥面/导航/曲线正确性函数，迁移消费者后再删除旧重建路径。用计数证明最终物理边只编译一次，测道路阶段能否进入 150–250 ms 原型预算。
2. 生态候选按区域空间块惰性生成，移除 `createSlots` 的全图枚举和全图排序；高度图批量化与共享环境查询一起测量，不能把构建成本移出计时冒充收益。
3. 体量候选池改为索引选择，减少当前每世界约 1.8 万次检查；保留实际数量与碰撞/坡度，不预设每成员固定尝试次数作为内容容量。
4. 接入统一依赖及 Worker 差量，消除整图对象视图与序列化；先用单 Worker 建立正确性，再决定独立块是否值得并行。

### 推荐架构与优先级

保留现有 `PlanningDocument`、`LayoutGroup`、`RoadGraph` 和规则插件契约，收拢数据所有权与派生责任，不另造一套素材 ECS。模板只提供通用体量、端口和连接意图。

| 优先级 | 改造 | 可验证的停止条件 |
| --- | --- | --- |
| P0 | 作者数据与快照分离；按组件实际输出建立失效依赖 | 单体高度/局部密度修改不调用全局寻路；事务准备不克隆生成几何；保存重放一致 |
| P0 | 最终物理道路图一次编译 | 入口、汇流和共享桥先落拓扑；正常路径每条最终物理边只编译一次；交叉修正仅修改相关边 |
| P0 | 共享区域环境查询、物理路段索引和分块生态候选 | 冷生成复用准备数据；局部编辑不枚举全图；边界、水域、接地及稳定候选规则不退化 |
| P1 | 标准高度图批量计算 | 保留 1024² 与量化规则，减少逐样本重复对象/轮廓计算，独立测准备成本与全图收益 |
| P1 | Worker 可取消任务、结果差量发布 | 新输入能在批次边界接管；旧任务不覆盖新结果；进度为已完成批次，未完成不能冒称成功 |
| P2 | 仅并行无依赖的空间块 | 先验证单线程结构；稳定 ID 与合并次序不依赖线程完成先后，再测并行收益及传输成本 |

选型比较：继续给旧对象管线增加缓存，改动小、可缓解部分热编辑，但不能消除首次生成的多轮道路处理；直接增加 Worker，仍保留重复运算与大对象传输。推荐先完成上述数据与编译架构，再按实测决定是否并行。`scheduler.yield()` 可用于分块调度但并非所有浏览器可用，应做能力检测并提供任务调度回退；让出执行不会自动让总计算变少。[MDN 调度说明](https://developer.mozilla.org/en-US/docs/Web/API/Scheduler/yield)。

完整生成顺序：

`作者配置 → 地势/河流/POI 区域查询 → 最终体量及入口 → 世界连接/内部连接/共享渡口拓扑 → spline 与逐点宽度 → 引导占地/生态协调 → 一次差量发布`

心理地图可以提供道路曲折策略；其实体引导占地必须在对应道路定型后协调。生态仍可在道路前预计算稳定候选和地形/归属字段，最终占用筛选依赖道路/引导，避免先完整种植再全量删除。不擅自反转现有引导与生态偏好的处理顺序。

局部更新按实际影响区块集合处理，不能将多个远隔的改动并成一个大矩形而重算中间所有区域。粗查询只用于排除或选候选，边界与显式碰撞仍做精确验收。邻居只读，局部求解不搬动其他 POI。缓存失效版本是运行时数据，不得参与随机采样或改变刷新结果。

目标是核心计算压到 700–800 ms，并为启动、传输、页面发布预留 200–300 ms；这是后续原型的验收预算，**尚无新架构实测收益，不能承诺当前已经或必然达到**。必须分别验证首次完整生成、单 POI 数量/尺寸、单体高度与局部生态；热编辑达标不能替代首次生成达标。

## 验收口径

- 默认 1024×1024 米世界，Seed 1/2/3，完整 POI、体量、道路、河流、桥与生态。
- 从用户启动布局到最终规划图可交互，目标小于 1000 ms；记录模块加载、Worker 初始化、计算、传输、UI 发布各项。不能以热缓存、后台补生成、减少数量或提前结束进度替代完整完成。
- 单独报告计算时间和浏览器端到端时间，多次冷进程测试报告中位数及 P95，记录硬件与浏览器。任意作者输入规模不能承诺固定上限，压力参数另报，不静默修改数量。
- localStorage 仅参数。相同生成器版本、Seed、最终参数必须得到相同内容；编辑顺序、缓存命中、任务完成顺序不能成为随机输入。新架构可能改变旧版本布局，不能宣称跨算法版本几何完全不变。

## 现状与预算

历史 `b44107cc6` Seed 1：区域 220 ms、体量 1428 ms、道路 1714 ms、生态 1371 ms、引导 202 ms。当时仍有每成员最多 256 次候选、最多 6×256 次间距改善。该体量试错已由第二轮构造式实现替代；多轮道路几何编译仍存在，当前数据以上方 2026-10-08 调研为准。

以下是目标预算，不是实测承诺：共享世界查询数据 150 ms、POI 体量 150 ms、道路与跨河 250 ms、生态与引导 150 ms、传输与页面发布 150 ms，共 850 ms，剩余 150 ms 给启动波动。仅把当前串行工作搬进 Worker 无法满足该预算。

## 1. 共享世界查询数据

新增单次生成上下文，统一持有地形高度/坡度、陆域和 POI 归属、水域/岸线、实体占地索引。所有阶段消费同一个上下文，取消各阶段独立构造相同地形和多边形索引。

用连续 TypedArray 管理分块数据；候选位置在区域块内批量查询。区域掩码和距离下界用于廉价排除，边界不确定时仍走精确轮廓检测。不能把稀疏角点采样当成严格无碰撞证明。

高度场有两个需实验比较的路径：精确解析查询的分块缓存；统一编译高度场并由布局、预览和最终地形共同消费。后者必须明确插值与坡度误差、浅河岸及 OBB 接地规则，不能只有规划器用近似地形而真实 3D 继续用另一套高度。先比较构建成本与查询收益，不能预先承诺哪个分辨率满足 1 秒。

## 2. POI 直接构造与局部缓存

保留点、线、面、体和可插拔布局规则。规则输出候选排列及连接意图，不直接创建道路面片。

对每个 POI 先形成按尺寸、坡度、水域过滤的可行候选集合，再按稳定 ID 排序选择；数量、间距、尺寸共同决定排列，不再为每个成员从头反复尝试整套流程。使用空间哈希做精确 OBB 近邻检查，间距属于协调目标。

单体覆盖从同一最终参数基准协调，避免依赖编辑历史。跨 POI 的互斥通过边界冲突图建立依赖；独立分量可并行，有依赖的分量稳定排序处理，不通过抢占时序决定结果。不擅自把管理区边界变成新的硬约束。

局部缓存按区域输入和实际空间依赖标记失效；未改变的区域直接复用。Worker 并行放在数据与确定性边界稳定之后，以免重复传送整张 plan。

## 3. 道路只编译一次

管线顺序：地势/水域 → 最终体量与入口 → 道路拓扑 → 共享渡口 → spline/宽度 → 路面发布。

内部路网、世界连接和补接首先操作节点/边；相交、合流、共享桥在拓扑层解决，避免先生成多份曲线，再反复拆分和修补。每条最终物理边只采样、生成轮廓一次；逻辑旅程引用 edge ID，不复制几何。

寻路消费共享可通行数据，精确实体/水域检查用于候选边验收；窄路宽度协调保留。桥仍是两岸直连，分支位于岸上。无几何变化时复用最终路网；局部变化只重编实际受影响边及交汇邻域。

## 4. 景观候选场与一次发布

以 Seed、区域和候选编号定义稳定随机序列；树木、小石头、花区共享批量环境查询结果。参数改变只调整对应区域筛选与属性，不重新执行全图几何分析。花区连续形状可以走噪声场，但这是生成规则更替，应独立验收形状，不冒充输出无损优化。

生成阶段只写紧凑数组与 ID 关系，最后按消费端需要生成对象视图。Worker 传输采用 transferable buffers；UI 只重建变化节点，不把完整 plan 多次 structuredClone/JSON.stringify。

## 实施顺序与停止条件

1. 建立共享查询上下文原型；固定相同候选集，测准备成本、每阶段查询耗时与精度。原型不接生产默认入口，达不到预算则调整设计。
2. 将 POI 求解分为候选生成、可行筛选、稳定选择和显式覆盖；保留数量/尺寸/刷新/邻居稳定回归。
3. 道路改为单一拓扑图和一次几何编译；测试每个体量入口、断头路、共享边、桥及行走高度。
4. 生态批处理和传输/发布去重，必要时才并行独立区域。
5. 真实浏览器冷启动验证完整场景，报告 P95。达到核心计算预算但浏览器仍超过 1 秒时，不能称任务完成。

本方案不包含 shader、材质、草渲染或运行时 LOD 改动，也不恢复生成结果持久化。
