# 河溪、湖泊与跨河连接

管线：基础地势/POI 分区 → 水域/河床 → 体量 → 道路与跨河 → 景观。河流是跨 POI 的线/面关系，不新增河流 POI。

| 模块                        | 权威职责                                                          |
| --------------------------- | ----------------------------------------------------------------- |
| `RiverRegions`              | 自然走廊、区域河流规则、作者锚点、逐段水位/宽深及河床剖面         |
| `LakeRegions`               | 自然选址、闭合湖岸/岛洞、固定参考湖盆与水位偏移                   |
| `RiverCrossings`            | 共享物理路段、干岸路口协调和完整跨河跨度                          |
| `PlanningSuspensionBridges` | 有序物理承载路段上的桥面/引道拟合，检查真实结构、干岸、坡度与净空 |

## 参数与生成

参数经注册 schema 和 PlanningSession 进入求解。世界数量、水位模式与目标长度只属于世界/明确声明的单河作用域；POI 河宽、弯曲、深度、岸坡与经过倾向只影响其管理区区段。继承、局部覆盖、显式 0 和 reset/base 沿用统一组件语义。预算不足或数量/长度未达请求进入诊断，不等同空间没有容量，不改作者请求兜底。

自动河流先寻找低地走廊，再生成连续曲线及米制轮廓；多河使用种子化偏好与既有河流距离代价。当前河流支持逐段高程/作者控制点，旧统一平面 waterY 记录不是当前全部河流的契约。普通段、瀑布、阶梯解析使用共享 Watercourse；陡降不冒充普通斜坡，雕刻必须明确授权且只挖低。

`depthMinM/depthMaxM` 是水面至床面中心的水下深度，自动默认 0.35–0.85 米；显式深度及锚点深度保留。旧 depthM 迁移成等值范围，不覆盖显式设置。实际水深以最终 Terrain 为准，作者 depth 只提供挖床意图。

普通河岸由 `PlanningRiverBank` 生成同源横断面，以有限坡度和五次 Hermite 过渡连接床面、水边和原坡；bankWidthM 为基础过渡尺度，岸顶高差决定真实包络。Terrain 不抬高低洼地或改水位掩盖漫水；湖泊及真实落水断崖保留自己的分支。剖面版本与路肩几何/影响权重进入高度缓存，最近线段查询复用空间索引。

`PlanningRiverEndCaps` 在 Water 描述适配时补齐已有圆弧端部：水面沿规划轮廓收窄，深度继续读取同一最终 Terrain。原始作者锚点和内部瀑布边界保留，派生端部不写入存档；完整圆弧占地通过岸线包含检查后才补齐，显式平截或急弯裁剪掉的端部不外扩。末端用不超过 2 厘米的正宽截面避免退化三角形，固定 1 米地形采样仍允许岸线近似。共享 River 的普通平截网格语义保留，已解析路径允许正的亚米截面，作者河宽及零/负数、非有限值和退化几何校验继续执行。

湖泊默认数量为 1，可显式为 0；无合适地点报告缺口。水位偏移不重复挖盆；移动/删除/湖盆编辑从自然地形和有效作者修改重派生，岛洞不隐式填土。空水域、外泄或不合法岸线明确拒绝。

作者地形位移先叠加到基础地面，再按世界坐标中的河床剖面与湖盆基准水位切挖；不能在切挖之后再给湖底或河床加一次位移。湖盆深度相对创建时保存的 `canonicalWaterLevelMetres`，当前填水高度只决定水面，不改变湖底；保存重放沿用相同计算顺序。

## 桥、通行与重建

桥位优先沿河流局部法线确定：从当前渡口附近固定数量的断面候选中，按实际水域轮廓求两岸点，选择可避障的短连接。岸上引道单独用样条接入桥头，水中桥段保持直线；邻近道路仍共用渡口，分支保留在干岸。两点河流同样适用。若附近法线断面全部被实体或地界阻挡，才保留原本可通行的斜向直连，不以强制正交造成断路。该处理只调整桥附近的道路，不移动 POI 或体量。

道路同时求解陆地绕行和跨河；只发布实际被道路使用的连接。跨河段两岸直连，岸上过渡由 roadApproaches 提供；物理 section ID 按岸到岸顺序保存，不能用逻辑道路 ID 覆盖同属无关路段。

自动桥头沿既有承载道路寻找最近可行干岸；显式长度围绕确定性自动参考中心求解。实际柱 OBB、护绳与角色走廊、全宽桥口、障碍、坡度和净空通过同一发布检查，不能关闭碰撞或抬河床替代桥。短引道仍验证末端支撑/台阶，桥面、模型、白盒和导航消费同一发布结果。具体曲面/素材契约见 [共享吊桥](../../../../../shared/bridges/README.md)。

`bridgeGround` 只在实际木桥范围内返回桥面支撑，岸上返回调用方提供的 Terrain 高度；不再查询已删除的独立引道平面或把曲面桥高外延到岸边。桥体查询仍保留保守包围盒和线段分块，底层地面每次调用只采样一次。新规划发布后重建查询器。桥头按固定地形网格的承接范围检查干岸与障碍，整地场进入地形缓存身份；不增加分辨率或独立渲染面。

水域重建先清除旧派生引道，湖泊选址只读自然地形，避免旧整平改变新河形或冷/热存档重放。附近影响经依赖协调，无关 POI 不全图移动。

必要行为验证：`SpatialRivers.spec.ts` 的实际 PlanningWalk 双向过桥与组合物理路段，`PlanningRiverAuthoring` / `PlanningLakes` 的编辑/拒绝/重放，以及 `PlanningHeightmapIncremental` / `PlanningWaterTerrainSnapshot` 的固定高度图采样与 R16 范围。历史运行与验收边界见 [实施记录](../../V2_IMPLEMENTATION.md)，旧计数不证明当前全量通过。

## 外部地形的一次生成

`generation/terrain/TerrainHydrology.generateTerrainHydrology` 在调用方提供的米制高度场与陆地轮廓上复用本目录河湖规划与岸坡/湖盆采样，不创建 World、实体或资源。输入范围是 `[0,width] × [0,depth]`，省略河湖配置表示数量为零；数量范围必须同时给出上下限。返回浮点最终高度、河湖几何/剖面、数量与缺口诊断。调用方先完成 RG16 量化，再从解码节点生成局部一米 native Terrain snapshot，并依据其实际采样重算 River depth，所有 native carve 均为 false。

`ocean: true` 将河道延至零水位的真实海侧断面，返回 `mouth` 供调用方建立原生连接；无法得到有效河口时明确失败。连接双方必须共用接受后的床面与世界坐标，Ocean/connected 实体采用 identity transform。粗 Ocean 采样可附同源局部 refinement；不能将其近岸图集精度误称为一米物理精度。生成入口不规划道路，宿主在最终水域确定后处理道路避让与一次事务提交。
