## 当前接入

- 草地、道路／干燥矿物地面、水面和积雪脚步：每种 4 个独立接触片段，累计实际通过导航碰撞的移动距离触发；不因转头、传送、切换相机或飞行触发。当前导航速度达 30 m/s，步距按导航速度缩放，最多每秒 3 次接触。
- 风与阵风：同一风场采样；树叶、灌木、草丛读取已发布的植被布局／密度和局部风速。积雪压低草声。
- 河流：投影到已发布的连续折线；湖、海：局部水体归属、实时水位与最终地形求岸线，不在水体中心放一个声源。支持已发布的用户河流、盆地修改。
- 小雨和大雨平滑交接；不将雷电、雨和风捆绑为一个状态。
- 闪电在视觉选定世界位置后发布同一个事件；雷声按三维距离 / 343 m/s 延迟，以引擎音频时钟计时，避免受渲染帧率影响，使用近雷／远雷素材。目前天空闪电约在数公里外，通常需要等十几至二十多秒。
- 雷声采用独立的公里级传播曲线：已含远处轰鸣的素材按 6 km 尺度校准响度，14 km 听距末端平滑淡出；户外实体遮挡保留 75% 的低频主体并降低高频。避免远雷重复套用近处草木的强衰减、被雨声淹没。此处是混音模型，不是声学衍射模拟。
- 相机 Entity 上的引擎 `AudioListener` 驱动 HRTF，声音由世界中的 Entity + `AudioSource` 播放。距离同时降低响度、高频细节；地形高度射线与已发布岩石 OBB 遮挡声音。树叶、草丛不当成实体墙。
- 每类最多两个空间声源，最多 16 个持续声源、8 个短声，总计最多 24 个播放中的 `AudioSource`；以声源数量归一化，避免沿岸素材叠加变响。声源更换、远近滤波和静音平滑过渡。
- 首次真实操作调用 `AudioManager.resume()`；引擎统一管理播放上下文及前后台恢复。素材通过 `ResourceManager.load<AudioClip>` 和 `AudioLoader` 解码、缓存；项目组件按引擎资源引用契约持有素材，销毁时释放引用，异步加载的迟到结果留给资源管理器，不销毁共享资源。录音时环境声降至 13%，暂停脚步。隐藏 Debug Controller 的 Audio / 声音分类提供自然声音开关和音量，设置保存在本机。

## 引擎与项目的边界

- Engine overlay 扩展 `AudioSource`：HRTF 空间定位、`distanceRolloff` / `minDistance` / `maxDistance`、低通截止频率、平滑音量和滤波、循环起播位置，以及保留原音量 0–1 契约的素材校准 `gainDecibels`。
- `AudioListener` 挂在相机 Entity；引擎在所有 late update 完成后同步监听器和正在播放的空间声源世界变换。一个共享上下文由最后启用的有效监听器控制，禁用后恢复前一个监听器。
- `AudioManager.state/currentTime` 提供不触发上下文初始化的公开状态和时钟。`AudioLoader` 继续使用引擎既有的离线解码路径。
- World 只负责素材选择、混音比例、发声几何、遮挡判断、脚步和雷声事件；不再创建 Web Audio 节点、上下文或调用解码、暂停和关闭接口。
- 自定义距离曲线由 World 计算一次，对应 `AudioSource.distanceRolloff = 0`，防止被引擎再次衰减。草声的固定校准转成 `gainDecibels`，保持已验收文件不变。
- `EnvironmentAudioAssets.ts` 的 `ENVIRONMENT_AUDIO_MIX_TRIM_DB` 保存独立的场景混音补偿：树叶 +8 dB、草丛 +8 dB、灌木 +14 dB；与原文件校准、用户总音量分开。水体使用连续声源的距离曲线，草木和脚步继续使用局部声源曲线。
- 扩展源码位于 `world/engine/overlay/packages/core/src/audio/`，引擎主循环只有一个更新接入点；通用能力后续应提取为上游 PR，未改外层 `packages/`。

## 资产与构建

`manifest.json` 记录 28 个运行时 WAV、16 类来源、模型／历史 ID、源文件哈希、用户确认出处、裁切区间和固定增益。素材约 17.93 MiB；PCM WAV 避免有损压缩引入循环填充间隙。Vite 将 `EnvironmentAudioAssets.ts` 中的 URL 编入带哈希的生产资源。

`../../scripts/audio/prepare-approved-audio.py REVIEW_ROOT` 从外部验收原件重建运行文件，需要 Python + numpy + ffmpeg。此命令校验源哈希；不调用生成服务、不消耗额度。草声按原文件复制，其余持续声做 0.35 秒等功率交叠；单步和雷声加短首尾淡变。固定电平校准与场景混音分开，未采用动态响度归一化。

生成溯源不等于商用发行授权。发布到商业渠道前，应结合生成时账户套餐核对 ElevenLabs／Stability AI 授权；本次为本地项目接入。

## 实现边界与后续听感验收

这是户外场景的首版空间音效，不包含 BGM。遮挡采用有限地形采样和岩石包围盒，未模拟网格衍射、声波反射或室内混响；岸线用固定 8m 网格局部追踪并二分到约 0.5m，极窄水边特征可能需要更细采样。没有额外生成石板、岩石等新脚步材料，干燥非草表面暂用已验收的道路素材。画面中的云端闪电当前主要使用远雷素材。

程序测试和真实浏览器解码能确认接线、时序和播放状态，不能替代耳机听感验收。重点听：停步后的安静、转头时河流留在原方向、绕到山／大石后变闷、沿岸移动的连续性，以及雨和植被叠加时是否舒适。

## 其他音效的衰减与混音排查（2026-09-08）

覆盖全部 28 个 WAV 的电平和哈希，并在独立 Chromium 的实际引擎组件中测量近处、远处、实体遮挡、16 个脚步变体和多声源叠加。测试混音只接测量节点，不向扬声器输出；不是对用户设备听感的替代。

| 类别 | 发现与处理 |
| --- | --- |
| 树叶、灌木 | 素材受少量高尖峰限制，持续沙沙声电平偏低；叠加场景衰减后，在和风中偏弱。分别增加 8、14 dB 场景补偿。 |
| 草随风 | 原文件校准已正确保留，但场景比例仍偏轻；增加 8 dB 场景补偿，未改动已验收的 5.24 秒循环。 |
| 河流、湖岸、海岸 | 连续水体的代表声源误用局部点声源的快速衰减，中距离主体不足。改用较缓的连续声源响度曲线；高频随距离消失、遮挡系数和听距末端静音仍保留。 |
| 草地、道路、水面、积雪脚步 | 16 个变体均有实际输出，测得接触峰值约 −21 至 −32 dBFS；未发现同类电平或加载问题。保留原比例。 |
| 风、阵风、小雨、大雨 | 弥散背景不经过空间距离与实体遮挡衰减；未发现同类错误。仍按实际风场与降雨强度混合。 |

- 5 米、4 m/s 风、65% 总音量、每类双代表声源归一化条件下，单个树叶／草丛／灌木代表的输出 RMS 分别从约 −62／−63／−73 dBFS 提升到 −54／−55／−59 dBFS。这里测量的是单独输出，不要求所有细节始终高于雨声。

### 岸线重建预算（2026-09-09）

岸线缓存每个活跃渲染帧最多遍历 256 个网格单元，包含缺失接触采样、交点二分和线段复制；40×40 窗口分 7 帧完成。两套预分配的线段缓冲区分别用于发布和构建，只有完整结果才在水体发现阶段交换。播放端不引用滚动缓存或构建中的线段。首次生成在 30 FPS 连续编辑用例中按 500 ms 验证，已发布岸线在普通重建期间继续播放。

每轮固定水位及窗口，连续水位变化合并到下一轮，避免反复取消导致无法完成。地形仍按实时高度采样：构建期间的编辑合并为下一轮局部失效，保证最终收敛；完整发布表示完整空间覆盖，不表示复制整个高度场的事务快照。隐藏水体或替换已发布水体目录会取消待发布结果并撤下旧候选，防止阶段间重新发布已失效声音。

该预算约束网格工作量，不保证硬实时毫秒上限，也不涵盖水体目录重建、河流索引查询、候选选择和浏览器 DSP。不增加稳态构建对象分配；原有目录发布与浏览器原生音频节点的分配边界仍然存在。
