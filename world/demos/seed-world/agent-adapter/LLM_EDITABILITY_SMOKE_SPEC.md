# Seed World LLM 可改性 Smoke Spec

## 1. 文档状态

- Spec 版本：`v1`
- 建立日期：`2026-09-02`
- 适用入口：Seed World Planner 的真实 AI Chat 用户链路
- 用途：作为时间、空间、天象和 25 种公开资产可改性的固定 Smoke 基准
- 指令数量：114 条，其中 14 条时间、空间和天象指令，100 条资产 CRUD 指令

本文件定义固定测试输入和验收口径，不记录某一次运行结果。
每次运行产生的 Trace、通过率和问题分析应写入独立报告，不能反向修改本 Spec 的指令来迁就当前模型表现。

## 2. 测试原则

1. 所有指令必须以玩家自然语言逐条发送，不得补充 API 名称、字段名、脚本、调用顺序或预期返回结构。
2. 所有指令必须在同一会话中按本文件顺序执行，以验证“那里”“刚才那个”等跨轮指代是否持续绑定同一资产。
3. 每条指令都必须经过真实 LLM、APISearch、Agent Script、Runtime 和世界状态链路，不得直接调用 Runtime 代替 LLM。
4. `completed` 只表示 Agent Loop 收敛，不代表用户意图已经完成。
5. 支持的修改必须以 Tool 结果和实际世界状态为准。
6. 不支持的操作必须明确拒绝，不得用其他资产类型冒充，也不得只凭最终文案声称成功。
7. 创建或修改返回的稳定 Ref/ID 是后续读取、更新和删除目标的最高优先级身份依据。
8. 如果目标资产在当前世界中不存在，模型必须如实说明未找到，不得虚构资产或结果。

## 3. 前置条件

1. 使用固定世界种子和一份新世界开始测试。
2. 启用 AI Chat 与 Agent Trace。
3. 记录当前代码提交、发布产物、ASAP 版本、模型名称和有效模型参数。
4. 测试开始前玩家可以正常移动，世界加载完成，Worker 和地景 Runtime 已就绪。
5. 除本 Spec 明确要求保留的池塘外，每种玩家创建的资产在完成 CRUD 后立即删除，避免污染后续用例。
6. 水草区依赖池塘，因此 `A11-D` 必须在 `A20-D` 之后执行。

## 4. 结果状态

- `PASS_SUPPORTED`：支持的能力真实完成，目标、参数、Tool 结果和世界状态一致。
- `PASS_BOUNDARY`：不支持或目标不存在，模型准确说明边界，且没有错误替代或虚假成功。
- `FAIL`：选错目标、调用错误能力、脚本失败未恢复、结果与世界状态不一致，或虚假宣称成功。
- `BLOCKED`：基础环境不可用，导致当前指令无法进入被测链路；必须记录阻断原因，不能计为通过。

每条结果至少记录：用例 ID、原始指令、interactionId、实际模型、Agent 决策序列、APISearch 符号、脚本、Tool 结果、稳定 Ref/ID、世界状态证据、最终文案和结论。

## 7. 固定执行顺序

本文中 114 个四级用例标题的物理顺序就是唯一执行顺序，运行器不得按 ID 重新排序。
池塘与水草因此采用以下依赖顺序：

1. `A11-C`
2. `A11-R`
3. `A11-U`
4. `A20-C`
5. `A20-R`
6. `A20-U`
7. `A20-D`
8. `A11-D`

其余资产按 `C → R → U → D` 顺序执行。

## 8. 总体验收门槛

1. 114 条指令均产生可追溯结果，不允许静默跳过。
2. 所有支持操作必须真实修改或读取世界状态。
3. 所有能力边界用例必须准确拒绝或报告未找到，不能通过替换资产类型制造虚假成功。
4. 每组 CRUD 中的 R、U、D 必须持续作用于 C 返回的同一稳定 Ref/ID，除非用户明确要求重新选择目标。
5. 任何 `FAIL` 都必须给出模型、APISearch、协议、脚本、Runtime 或渲染层中的确定归因。
6. 只有全部支持用例为 `PASS_SUPPORTED`、全部边界用例为 `PASS_BOUNDARY`、且没有 `FAIL` 或 `BLOCKED` 时，整套 Smoke 才通过。


## 8. 当前空间规划器的植被组件接入

本节单独用于当前 `PlanningSession` 入口；上面 114 条旧笔刷 CRUD 基准不作为新规划器通过证据。
在真实 AI Chat 中逐条发送以下原文，不附带 API 名称；记录模型、Trace、返回的稳定 ID、组件版本和实际发布结果。测试颜色修改后必须恢复。

| 用例 | 自然语言指令 | 验收 |
| --- | --- | --- |
| P01 | 查一下这个世界有多少棵树，选一棵告诉我它用的是什么植物资源。 | 查询数量等于已发布的完整乔木集合；inspect 的资源 ID 与实际渲染来源一致。 |
| P02 | 把所有白桦树的树干改成暗红色，叶子保持原样。 | 发现真实物种/树干槽，原子修改线性 RGB；叶片槽无新增覆盖；回执等待保存与发布。 |
| P03 | 恢复刚才修改的树干，让它们使用素材原来的颜色。 | reset 同一组树干槽；保留修改前已有的其他参数。 |
| P04 | 只把这一棵树的花瓣改成蓝色，不要改其他植物。 | 目标没有花瓣或当前仅有全局物种色时明确报告边界，不偷改全局材质。 |
