# 场景视觉意图：首次生成

入口：`/demos/terrain/scene-visual-intent/index.html`，Gallery 路由 `#terrain/scene-visual-intent`。

用户在生成前用一个自然语言输入框描述或讨论场景。原文与连续对话直接送给 ASAP；不先拆成题材、风格、情绪等表单字段。这个页面验证首次画面的匹配度与视觉效果，不预加载旧场景测试修改能力。

## 执行链路

`完整描述与对话 → ASAP 一次表达生成计划 → 原生范围展开与参数事务 → 布局发布 → 几何取景 → Runtime 首次生成`

- `SceneVisualIntentPage` 保留单一输入、进度、停止、错误与重新描述。讨论时文字回复，不创建 3D；生成后默认收起对话，避免遮挡首屏。
- `SceneVisualIntentController` 懒加载同一生成会话，保留完整原文，阻止并发和生成后的重复提交。
- `loadPlanningWorldSource` 使用空的初始存储端口 建立新的原生作者计划，不读旧存档、不创建 Engine、不覆盖原世界。
- `createSceneGenerationSession` 使用本 Demo 的 `SceneVisualIntentTransport`：显式配置本地服务时直接发送 HTTP 请求，未配置时复用现有 ASAP transport。每次提交只请求一次模型：讨论可直接回复；生成调用一个 `scene_generate`。不注册 `execute/read_tool`，不读 Markdown 生成指南或各系统美术指导，不运行 AI 编写的 JavaScript，也不在生成后再调用模型编写成功回复。
- 模型看到的执行契约从原生 schema 生成，包含可写字段、类型、单位、范围、枚举、作用域、字段说明，以及当前接受计划的事实。未知组件、字段、作用域或不完整响应直接失败，不通过脚本修复循环或关键词规则兜底。通用 System Prompt 不包含业务配方。

用户在本入口提交的场景、氛围或用途描述就是首次生成请求，简短或模糊描述无需额外确认。首次生成 API 契约要求模型保留明确条件，依据完整语义和原生能力自行补全未指定的地形、水系、布局、配色与取景，选择一种一致且可实现的方案后直接调用 `scene_generate`；存在多种合理方案不构成追问理由。用户明确只讨论或暂不生成、仅询问知识或能力且未要求生成，或关键目标存在无法协调的矛盾及能力缺口时才文字回复；真正阻塞时仅说明关键缺口或提出最小必要问题。没有场景关键词分类、固定情绪配方或强制所有输入调用工具。

生成前上下文的 `baselinePublication` 只表示供本次创作调整的初始默认规划，尚未按用户描述生成或交付画面；`revision` 是内部作者版本。一次提交是本会话的执行约束，不是不可逆的外部发布或额外授权要求。默认对象数量不成为必须保留的创作条件，默认存在的对象也不自动成为取景主体。面向用户的文字回复保留目标相关结论，仅在用户询问实现时展开版本、对象统计、颜色编码和参数等技术细节。

## 整体范围与颜色

`palette.layers` 使用“真实生态层 → 真实部位 → RGB”的两级结构，例如 `{layers:{trees:{leaves:[r,g,b],bark:[r,g,b]},flowers:{petals:[r,g,b],stem:[r,g,b]},grass:{blades:[r,g,b]}}`。可用的层/部位组合从实际材质 manifest 与当前公开 schema 派生，`paletteLayers.parts` 同时提供各部位的当前参数颜色范围。每个部位独立配色，未指定部位保留原有颜色与继承；树叶配色不再覆盖树皮，花瓣配色不再覆盖茎叶。旧的 `palette.color` 和 `layers[层]=RGB` 被拒绝，不隐式迁移为全层染色。生态层用于分类，不决定部位必须共用色相。

输入沿用现有 sRGB 编码（通道0–1），生成入口不追加 sRGB→线性转换；原生算法在现有RGB编码下保持所选部位各素材和草地暗/亮端点的加权RGB亮度层次（信号指标，不是物理线性亮度），超出RGB色域时对整个向量等比缩放，黑色目标的RGB为零。显式作者颜色在季节调色之后优先，reset 恢复继承。`paletteSharedScopes` 明确真实共享绑定的 `layers` 与 `part`，共享影响限定于同一部位；矛盾重叠在整个参数事务之前拒绝。`grass.blades` 对应低草与地表共用的原生 `grassAppearance` 色场。无需枚举素材编号或逐个 RGB 通道。

连续成片、具有主导色的景观需要同时协调覆盖、密度、铺底植被配色和其他植被的数量与遮挡。用户指定草地、地被也参与主色时，模型通过这些层的真实部位表达独立颜色；没有颜色名称或“花海”关键词触发的固定配方。参数接受和几何取景不能证明最终像素占比或视觉连续性，仍需查看实际画面。

首次生成接口向 Agent 声明 `paletteConstraints`：所选有彩配色的 HSV 饱和度下限分别为植被50%、天空30%（用户指定），S=(maxRGB-minRGB)/maxRGB。参数展开前使用 `minimumRgbSaturation`，低于下限才沿原色相增加色度差，保留HSV亮度V；原本更高的饱和度保持。植被后续整向量亮度缩放保持该饱和度，仅覆盖明确选定部位的真实素材RGB和所选草地两个端点；黑白灰没有色相，保持无彩。约束由生成接口及原生参数编译落实，没有增加模型回合、Skill读取、引擎修改或颜色空间转换，不影响未选中部位及建筑。它约束作者配色，不宣称光照、纹理和后处理后的每个像素都达到对应下限；原生 `postProcess.saturation` 是全画面相对调节量，不能用全屏饱和度调整替代此约束。

天空使用与植被 `layers` 平级的 `palette.sky={zenith:[r,g,b],horizon:[r,g,b]}`，两个端点成对提供，独立选择颜色。输入是原生天空渐变的线性RGB乘数，支持HDR，不使用植被的sRGB编码或素材亮度映射。编译器按最大通道整体归一化后落实天空30%的饱和度下限，再恢复原始HDR亮度，不逐通道裁切；接管完整两端及混合权重1，使有效渐变不再被中性白色混合稀释。未提供天空配色时保留现有来源；提供后不改变时刻、日照资源、大气底色、太阳或曝光。这些物理控制仍通过 `lighting` 参数表达；`skyTintR/G/B` 控制散射波长，不把其HSV冒充天空像素饱和度。生成入口不再重复开放渐变端点与混合权重字段，schema及编译器均拒绝旧入口绕过；其他原生编辑入口保持。

生成契约要求首次创作同时设计天空：普通白天以蓝色天空为常规方向，协调时刻、大气底色及渐变；黄昏、夜晚、阴天和明确的特殊天空按场景处理，没有固定蓝色RGB或时刻规则。用户明确保留天空时可省略天空配色；精确端点/权重要求与生成约束冲突时说明冲突，不擅自替换。天空的散射结果、云层和后处理仍需实际画面验收，渐变端点达到30%不等于屏幕天空每像素达到30%。

颜色绑定拥有的逐通道字段不在本入口的通用参数目录中重复暴露，避免同一配色既写 palette 又写草色通道而冲突。其他编辑入口仍保留原生逐槽编辑能力。这里没有粉色、金黄色等预设，也没有从情绪、风格或自然语言关键词到数值的分支。

`parameters` 只表达落实用户目标需要改变的原生字段，不枚举无关字段或重写所有默认值。`PlanningSession.describe` 从原生作者绑定派生字段级 `worldWritable`，不公开内部绑定路径；生成 schema、模型上下文和公开参数工具使用同一声明。上下文同时保留字段的 `kinds`、整数约束、默认值和关联开关条件。

`scope=world` 只接受世界可写字段并沿用局部来源；`scope=all` 逐字段展开：世界可写字段覆盖世界及适用的实际局部作者覆盖，仅实例字段覆盖真实适用对象。字段 `kinds` 与原生 `query` 的对象组件共同决定范围，不用组件种类列表排除真实的 policy 或 relief 作者对象。`scope.ids` 精确限定真实作者对象，每个字段必须适用于每个目标。未知字段、非法作用域、空集合与矛盾重叠在写入前拒绝。整个计划展开为一个既有 `PlanningSession.dispatchParameters` 事务，保留原生验证、版本、继承、显式 0、保存和重放。规划数组不由模型直接修改。

`excludeCategories` 表达全场排除的真实素材类别。类别与生成源来自当前生态配方、素材库及独立花区目录；程序对所有包含该类别的原生人口来源展开零密度和局部覆盖事务。一个类别可以分布于多个层，一个层也可以包含多个类别；混合类别的层作为完整作者作用域关闭，其他层保持。它不是题材识别或固定场景配方，不修改几何算法。显式参数重新启用同一个已排除来源时，整个矛盾计划在写入前拒绝。

生成前模型上下文提供原生 `baselinePublication`，生成成功结果提供本次执行后的 `publication`：全局与区域有效密度范围、花区几何面积与密度、体量数量和高度范围。未发布为 null，全场关闭须核对最大有效密度。花区几何存在不等于实际长花，零密度可保留种植区域但不产生实例；Runtime 诊断和真实画面仍需独立验证。公共布局说明如实区分完整实心 OBB、水平朝向与实际断裂/坍塌能力。

## 布局、取景与交付

参数接受后才求首次视角。模型根据完整描述识别首次主体，`focus=building/volume` 使用已发布的全部 OBB 部件，`flowers` 从实际花区多边形内以人的眼高观察，`environment` 保留环境视角；可用真实稳定 ID 限定主体或所属区域。明确主体而未指定 ID 时，`scope.ids` 限定的修改优先展示实际受影响范围；原生参数来源与空间父子关系分别解析，配置节点的修改通过实际字段消费者关联到发布主体。`world/all` 的集合展开不产生单个取景主体，环境视角也不因改动某个配置节点而自动对准建筑。空目标明确失败，不切到其他区域冒充完成。

取景沿用原生 `selectSubjectView/selectFlowerView` 与 `subjectView` 参数事务。体量取景消费 OBB/地形可见性；花区取景按实际连续种植面积和密度选择前景。花区和体量都会将同一初始视角交给植被构图求解器：花区从实际种植片裁出视口内地面三角面，建立视线保护体积，保留孔洞和间隙；花区没有实心占地包围盒，只有该区域自己的花丛人口免于其自身的遮挡排除。其他动态植被继续按真实尺寸避让。Runtime 的 `composition` 报告主体 ID、目标数量和候选遮挡拒绝次数。

这些是有限几何约束，不是花瓣像素覆盖或审美评分；种植面高度取自实际地形采样，尚不表示逐花瓣或逐地形三角形遮挡。已发布乔木、建筑、岩石与原生低草不由该动态植被入口重排，仍可能影响最终构图。花区作为主体不等于自动通过“花海”连续性与整屏粉色的验收。

只有接受的作者数据与规划结果可以 handoff 给 `mountSeedWorldDemo`。首次视角在初始植物驻留前应用；生成后数据只读，新描述重新建立计划。建筑与岩石当前仍是 OBB，占屏与取景不产生屋顶、门窗等造型。

Runtime 就绪后由宿主报告画面已交付，不声称视觉匹配通过。参数颜色受纹理、真实光照、季节颜色与后处理影响，RGB 不等于最终像素。天空使用独立原生大气和渐变控制；不能用全场暖色代替物体固有色。

## 本地与验证

沿用 `SEED_WORLD_MODEL`，本地显式连接既有 ASAP `http://127.0.0.1:8082`，模型单轮预算 60 秒，HTTP 截止时间 65 秒。显式地址仅接受 loopback 页面和 loopback HTTP(S) origin，直接用于本次请求，不读取、安装或替换全局 CandyJar。未配置本地地址时，沿用共享 transport 原有的原生/Wrapper 通道和 25 秒模型、30 秒通道预算。

调试选项和 HTTP 实现仅由本 Demo 导入，普通 Seed World 的 AgentLoop、协议、结果裁剪、重复检测和回复长度限制保持既有行为。共享模块只额外导出既有的 4 KiB 预算常量供原生参数工具引用，常量值和执行行为不变。本入口发送文本、原生能力与作者计划事实，不发送截图，不使用参考模板或视觉反馈循环。

`SceneVisualIntentController.spec.ts` 覆盖原文、生成前连续对话、单次模型调用、停止、失败、未知计划拒绝、原生集合展开、范围、主体取景及一次 3D handoff。真实 ASAP 和浏览器首屏另行记录于 `V2_IMPLEMENTATION.md`。测试、事务接受与 Runtime ready 均不代替用户视觉验收。

旧 `brief.theme/style/mood/description`、逐维 coverage、独立 Interpreter/Compiler 与脚本发现流程已退出本入口；历史存档保留，不参与本次执行。其他 Generator 和普通 Seed 入口不作交互改写。
