## 1. 背景、目标与改造方向

### 1.1 背景

我们正在构建可以随机生成、可以由 AI 局部编辑的大世界。未来，一句话或一张图片会被解析为语义化的地形、空间关系和参数；局部编辑则修改同一份语义数据。

项目具备基础地形、生态、岩石、程序化树、河流和湖泊等内容。本阶段以真实地形、水域及白盒体量表达其空间作用，不接入真实岩石、树木等素材替换。当前不承担完整开放世界游戏的任务、战斗、经济、叙事和探索奖励系统，也不依赖丰富建筑素材才能工作。

地形规划器需要借鉴场景与关卡设计中适用的原理：空间构成、实体与负空间、物理动线、视线、遮挡与揭示、Pull／Push、兴趣点和到达后的空间回报。它们必须落实为可以编辑和检查的对象与关系。

程序化的价值是将设计意图转成可重复、可变化、可局部维护的空间结构。论文、设计术语和几何指标提供方法与诊断依据，不能直接证明结果具有美感。

### 1.2 产品目标

1. **能规划**：在同一个世界里组织地势、山群、水域、道路、可用空间、POI 和视觉关系。
2. **能调节**：关键因素具有明确语义、单位、作用范围和可观察结果。
3. **能随机**：随机选择受约束的自由度，保持确定性与可复现性。
4. **能局部编辑**：修改一个对象后，相关对象自动协调；无关对象不重新随机。
5. **能检查**：2D 规划的平面／45°视角用于主要调参，3D 预览的 Orbit／Free 用于最后白盒体验；均读取同一份已解析世界。
6. **能积累视觉经验**：保存用户认可的具体布局、参数范围和组合条件，逐步形成可复用配置。
7. **能演进**：未来建筑和玩法 POI 可以参与已有空间关系，不要求重建地形规划模型。

### 1.3 当前范围与边界

| 属于本设计的范围 | 边界 |
| --- | --- |
| 地形、山峰、山脊、山口、峡谷、盆地、台地、岸线等布局 | 负责空间语义和最终几何关系，不模拟完整地质演化 |
| 河流与湖泊的形状、宽度、连接、河床及岸边关系 | 负责静态布局与地形协调；不要求完整流体动力学模拟 |
| 道路、物理动线、可停留空间、自然 POI | 当前回报可以是视野、位置、空间变化，不必是道具或任务 |
| 视线、视觉目标、框景、遮挡、揭示、留白 | 维护明确指定的关系，不承诺任意视点都具有同等构图质量 |
| OBB 与白盒体量规划 | 表达尺寸、轮廓、接地与空间占用；本阶段不实现真实素材映射 |
| 树林、植被对空间边界和视线的影响 | 用占位范围与明确的遮挡属性表达，不接入真实树木或展开生态系统内部设计 |
| 语义数据的生成、修改、保存和重放 | 为未来文本／图片／AI 输入提供统一入口；本设计不实现识别模型 |

季节、气候、昼夜、任务、战斗、建筑生产工具、真实岩石与树木等素材替换不属于当前范围。

点、线、面、体是几何表达工具；高度、坡度等连续场和连接、遮挡等关系同样需要显式表达。四种几何形式本身并不能替代完整的数据模型。

基础地表使用高度场，额外边界与遮挡使用白盒体量。完整洞穴、多层地表和天然悬挑需要额外的体几何能力，不能因为数据里存在“体”，就宣称当前表示已经支持它们。

世界尺寸、出生位置、初始朝向和地貌分布均应作为显式配置。某种海岛尺寸、出生点见湖、环形山带等可以是预设，不是所有世界必须遵守的规则。

## 3. 宏观设计

### 3.1 先约束构造范围，再生成几何；运行时消费确定结果


本设计采用“构造时尽量维持已知约束，最后独立检查”的方向。不能先任意生成完整布局，再把失败送回同一个随机生成器。给这种循环加一个重试上限，只能保证停止，不能保证获得有效布局。

上图是本项目提出的工程组合，不是某篇论文已经证明成立的完整算法。其依据与未覆盖问题在 3.4 中分别列明。

**生成成功率需要通过构造方法提高，而非依靠重试次数提高：**

1. **先检查约束前提与资源需求。**在生成详细地形前，检查连接能力、允许宽度、地面需求和被锁定的观察关系。可以确定不成立的配置直接结束，不先生成大量注定要丢弃的几何。
2. **传播可行范围。**从已知几何和约束推导允许的位置、尺寸和方向；能用确定公式或集合运算得到的范围直接计算。复杂关系可以使用保守的可行子域，但必须说明它可能遗漏其他解。
3. **构造并保护必要结构。**为需要通行的连接、停留区和必须保持的视线保留空间；后续地貌和体量只能在满足这些保留条件的自由度内变化。它们是依赖驱动的临时构造安排，不是固定“水先于山”的全局顺序。
4. **保存可行依据。**构造结果携带可走连接、保留通廊、选定观察区等依据。后续操作明确检查自己会否破坏这些依据；粗几何依据不能代替最终几何验收。
5. **只搜索未解决的局部分歧。**对确实需要选择连接或调整多个参数的问题，在一个作业内以固定候选顺序、冲突剪枝和共享预算进行搜索。已经证明不适用的分支不重复尝试，不重抽世界 Seed。

例如，简化河岸横截面的可用总宽为 C，河宽为 w，需保留的步行净宽为 p，两侧总余量为 2m。构造时直接要求 w ≤ C − p − 2m，再从允许区间取值。若该区间为空，就处理加宽可用横截面、改变局部连接或保留原状态，不反复随机摆放河与路碰运气。这个约束只证明该横截面上的宽度关系；急弯、纵坡和其他连接仍要分别处理。

这里的范围是**有条件、相互关联的候选集合**，不是每个滑块各自独立的最小／最大值。选定河宽后，需要重新收缩道路和岸边体量的允许范围。各参数单独有值、两两检查通过，都不证明所有条件存在共同解。

每种构造方法应说明自己实际维护什么：

| 对象 | 在生成中维护的条件 | 仍需解决或检查的部分 |
| --- | --- | --- |
| 可通行连接 | 先选择连接，再保留包含角色宽度与余量的连续通廊；后续体量不得侵入 | 通廊是否找得到、最终地面的坡度／断坎／净空，不能只检查中心线 |
| 必须可见的目标 | 在确定的观察位置与目标采样上，保留达到阈值所需的视线通道；参与对象变化后重算 | 未采样位置、目标投影与遮挡揭示序列；预留整个视锥通常过强，不作为默认做法 |
| 河流与岸边空间 | 宽度和岸边净宽联动取值，连接口共享边界与高程条件 | 全河岸线、急弯、交汇区和上下游是否共同有效 |

这些是本项目需要实现并逐项验证的构造约定。关系之间出现冲突时，只搜索尚未确定的选择及其依赖；没有通用方法能靠把所有约束塞进一个传播循环就自动解决全部问题。

**运行时边界：**

- 初次生成和用户编辑可以在应用运行期间触发异步求解作业；不强制只在离线阶段生成。
- 正常帧更新、相机移动、进入区块、白盒实例化只读取已发布 Snapshot，不因“当前布局不够好”触发求解。
- 连续拖动合并或取消旧作业；旧作业的结果不得覆盖较新的输入。
- 一次事务共享候选、搜索展开和迭代预算，不能由子模块各自重置重试次数。
- 作业结束后保持静止，等待下一次明确输入。移到 Worker 并不能使无限重试变得合理。

全局生成和局部编辑使用同一套对象与关系语义。二者的区别是变化范围、允许调整的对象和需要计算的区域。

### 3.2 全局组织与局部空间

全局负责区域之间的联系：哪些地方可以进入、主要目的地在哪里、哪些区域相互可见、哪些方向形成连续行进机会，以及空间疏密和开合的分布。

局部负责具体效果：某个山口保持通行、某段河岸引导前进、某处山肩遮住湖湾、某个台地提供新的视野。

出生点确定玩家最初的观察与进入关系。世界可以继续出现分支、环路、多向地标和其他观察中心，不应把所有空间强行围绕出生点排列。

主要空间承担明确设计意图，其他区域保留更自由的自然变化。不要求每棵树、每块碎石独立承担“导演”职责。

### 3.3 求解方式的选择

| 方式 | 判断 |
| --- | --- |
| 把地形、道路、河网、视线、白盒体量全部交给一个通用优化器 | 暂不采用。离散连接与连续几何混合，难以解释失败与限制修改范围 |
| 整图随机生成后以视觉评分挑选 | 不作为主机制。难以维护局部编辑，也缺少可信的自动审美裁判 |
| 可行范围传播、保持约束的构造方法、必要的局部搜索与独立检查 | 采用。优先让构造步骤维持已知条件，并明确哪些关系尚需搜索；不能只给不同生成器包上一层重试循环 |

求解器的内部执行顺序不应成为模块职责的依据。自然生成可以参考水系与地势的因果关系；用户主动修改河流、道路或山体时，则依据本次编辑意图协调其他对象，不能只允许固定的单向生成顺序。

### 3.4 文献到底支持什么

| 来源与核对位置 | 可以采用的依据 | 不能据此承诺的能力 |
| --- | --- | --- |
| [PCG Book，第 3 章](https://www.pcgbook.com/chapter03.pdf)，3.1—3.2 | 区分构造式生成与输出失败后重生成；空间分割与连接方法展示了如何在构造中维持特定性质 | 地牢方法不直接解决开放地形、任意视觉关系或高自由度编辑；“构造式”名称本身不证明我们的全部约束成立 |
| [Terrain Modelling from Feature Primitives，2015](https://www.cs.purdue.edu/homes/bbenes/papers/Genevaux15CGF.pdf)，第 3—5 节及 8.4、9 节 | 特征基元与组合树、有限影响域、混合／裁切／形变等操作，适合可编辑的地形表达 | 论文明确未解决自动生成和放置规则，不内生保证水文正确，也不支持悬挑地表 |
| [Feature-Based Terrain Generation Using Diffusion Equation，2010](https://perso.liris.cnrs.fr/eric.galin/Articles/2010-terrain.pdf)，第 3—4 节 | 由曲线上的高度、坡度与粗糙度约束生成地形 | 扩散求解不等于固定半径的局部更新，也不是 POI 和动线导演 |
| [Procedural Generation of Roads，2010](https://perso.liris.cnrs.fr/egalin/Articles/2010-roads.pdf)，第 3、5、6 节 | 在离散图上搜索考虑地势和障碍的路线，之后形成连续几何并调整地面 | 路径搜索存在前提和计算成本；任意截断后不保证找到路径，平滑后仍需检查 |
| [Hydrology-Based Terrain，2013](https://perso.liris.cnrs.fr/eric.galin/Articles/2013-river-networks.pdf)，第 8 节 Limitations | 从水系结构构造相关地形的思路 | 文中河网不能表达三角洲或牛轭湖，不能拿来证明任意河网已解决 |
| [D* Lite，2005](https://www.cs.cmu.edu/~maxim/files/dlite_tro05.pdf) | 复用已有路径搜索信息处理边代价变化 | 不保证所有更新都很便宜，也不解决山体、视线和 POI 的联合编辑 |

因此，本项目目前能确定的是方法的职责与证据边界。任意输入在固定预算内的求解成功率没有现成证明，必须按支持的参数域与关系组合进行测试。不能把“有界终止”“输出仍有效”“原意得到满足”当成同一个保证。

## 4. 数据层

以下是需要稳定的概念职责，不强制对应相同数量的类、文件或服务。

### 4.1 核心数据

| 数据 | 必须包含的信息 | 作用 |
| --- | --- | --- |
| WorldRecipe | 数据与算法版本、单位和坐标约定、世界范围、命名随机种子、空间对象、关系、局部覆盖、配置引用 | 保存用户想要什么，支持编辑、重放与版本迁移 |
| SpatialFeature | 稳定 ID、开放语义标签、几何描述、组成节点、参数、作用域、允许修改的自由度 | 表达可组合的地形与体量；语义标签不决定一个固定生成分支 |
| SpatialSpace | 稳定 ID、空间范围或构造表达、地面／净空、边界来源、开口、连接、观察区域、用途 | 表达开放或围合空间；不要求先选中一个枚举名称 |
| SpatialConstruction | 基元引用、变换、组合操作、参数绑定和能力要求 | 构造几何与区域；与允许引用、回路和多对多连接的关系图分别管理 |
| SpatialRelation | 参与对象、关系类型、成立范围、阈值、优先级、允许修复方式 | 表达连接、沿随、跨越、容纳、观察、遮挡、揭示等 |
| WorldSnapshot | 输入与算法身份、最终几何、最终场、确定的变换和连接、实际参数、生成来源 | 表达此次真正生成了什么，作为预览和运行时的权威结果 |
| ValidationReport | 检查版本、几何版本、条件、测量值、容差、证据位置、未覆盖内容、调整记录 | 解释结果是否满足已声明的要求 |
| RandomProfile | 可兼容版本、适用场景、采样范围、分布、联动条件、锁定项、用户反馈与状态 | 约束随机变化，不代替具体布局快照 |
| EditTransaction | 编辑前后版本、用户请求、实际变化、影响对象、修复记录、撤销数据 | 维护局部编辑的原子性与可追溯性 |

几何表达应覆盖点、带宽度的线、带边界的面、定向体量，以及连续场。组合空间引用这些表达，不复制另一套不可同步的几何。

地形构造树用于计算几何，空间关系图用于描述连接与约束，二者不合并为一棵树。河流或动线存在分支、回接时，不能因为几何按树求值就丢掉这些关系。

### 4.2 实体与空间

实体描述“占据哪里”，空间描述“希望保留什么用途”。

例如，河边观景空间可以引用地面区域作为停留面，引用岩壁和林缘作为边界，并引用湖湾作为观察目标。其通行、停留和观察范围可能不同。

必须区分：

- 可行走空间：由地面、坡度、碰撞和净空共同决定。
- 可见空间：视线可以经过的范围，可能包含不可行走的水面或悬空区域。
- 可辨认入口：在指定观察条件下具备可观察的开口和延续线索；其引导效果仍需人判断。

### 4.3 身份、随机与版本

- 对象通过稳定语义 ID 引用，不通过数组下标引用。
- 随机来源至少能按领域、对象和用途独立寻址。增加一个无关对象不应消耗公共随机流，导致其他对象整体变化。
- 随机种子、实际参数、局部修改和算法版本必须一起保存。
- 单独保存 Seed 不足以冻结视觉结果；已认可布局必须保存可重放输入和解析结果。
- 固定 Recipe 的几何重算不等于重新随机。算法版本改变时，必须说明旧输入是否能精确重放。
- 旧版本读取需要显式迁移，不能悄悄套用新默认值。
- 原始请求值与求解后实际值分别记录，不能只保存被自动修正后的值。

### 4.4 单位与几何约定

- 世界长度采用米，Y 轴向上，地面规划使用 XZ 平面。持久化角度字段必须明确标注角度或弧度。
- 绝对海拔、相对地面抬升、相对水面深度分别命名，不通过上下文猜测。
- 道路和河流的宽度默认指局部中心线法向上的水平全宽；半宽必须显式命名。交汇处另按实际水域或通行区域检查。
- OBB 的完整尺寸和半尺寸不得混用。几何方向使用世界语义；未来素材的局部轴转换留在独立映射边界，本阶段不实现。
- 路线、观察位置和地形采样明确采用的几何版本与精度。对象位置不应通过预览像素反向成为另一份权威数据。

## 5. 参数与用户手动验收

### 5.1 三种范围必须分开

| 范围 | 含义 | 由谁决定 |
| --- | --- | --- |
| 技术允许范围 | 当前几何、精度、数据结构和资源预算可以表达的范围 | 实现能力与验证结果 |
| 随机配置范围 | 当前希望随机生成落入的范围，以及适用条件 | 初始可用默认值，之后由用户反馈修订 |
| 当前可行范围 | 当前地形、邻居、锁定项和硬约束共同允许的结果 | 约束求解 |

随机候选应落在三者的交集中。手动编辑可以超出当前随机配置范围，但仍需满足技术能力与物理约束。

当前可行范围不承诺总能精确求出。界面必须区分已证明的范围、保守可行子域和需要进一步检查的候选范围；多个参数的联动不能压扁成互相独立的滑块上下限。

技术上不支持、当前场景放不下和用户觉得不好看是三种不同情况，不能统一处理成一个最大／最小值。

### 5.2 用户参数的颗粒度

用户控制具有空间含义的参数；内部采样点、迭代步长和求解权重放在开发诊断层。

| 控制层级 | 典型内容 |
| --- | --- |
| 世界或区域 | 地势起伏、地貌密度、区域疏密、POI 数量、路线分支、河网结构、方向偏好 |
| 语义对象 | 峡谷宽度／深度／走向、河流中心线／沿程宽度、湖泊轮廓、台地面积、山群体量与朝向 |
| 空间关系 | 通道净宽、目标显露位置、遮挡程度、视廊开角、停留区范围、到达后的视野变化 |
| 组内结构 | 主次体量比例、峰间间隔、轮廓变化、OBB 长宽高及旋转 |
| 内部派生 | 几何采样、网格细分、空间索引、求解步长、实际控制点数量 |

“简洁参数”不能成为禁止精确编辑的理由。常用面板提供语义控制，展开后允许查看和修改必要的几何自由度。

### 5.3 随机配置的积累方式

1. 用户调节参数、局部编辑或切换 Seed，查看同一个世界。
2. 可以保存具体布局，也可以记录某些参数的范围建议；两种操作分开。
3. 用户认为某种组合好看时，记录适用条件、关联参数和反馈，而不只是各参数的独立最大／最小值。
4. 将认可范围应用于后续随机生成，技术约束仍然参与求解。
5. 新随机结果由用户继续验收，逐步收窄或扩展配置。

例如，“较宽河流配较大的河湾和较低的近岸体量”应保存为有条件的组合。不能将分别好看的参数拼成任意组合后，就默认仍然好看。

配置可以有“初始默认”“待验收”“用户认可”“停用”等状态。初始默认只是功能入口，不声称具有已验收的美感。

认可某个参数区间不等于认可该区间的所有随机结果；认可某个 Seed 也不自动推出一整段 Seed 或参数范围有效。

## 6. 地势与自然空间

### 6.1 地势表达

整体高低变化、局部地貌结构和表面细节分别表达：

- 整体变化形成区域海拔、宽缓高地与低地。
- 局部结构形成峰、脊、山口、峡谷、台地、盆地、河床和湖盆。
- 细节提供表面起伏，不应破坏已明确要求的通道、停留面和水岸关系。

山峰与山脊、峡谷与水系、岸线与坡面应能够共享结构依据。自然参考用于确定可解释的形态家族和参数联系，不要求以长时间侵蚀模拟作为所有生成和编辑的前置步骤。

局部地貌可以用具有有限影响域的曲线、区域和高度影响函数实现。多个合法影响叠加后仍可能出现过陡坡面，因此必须检查最终地势，不能只检查每个局部函数。

山群分布、留白、远中近层次和动线先确定空间意图，再由这些意图决定必要的基底高低与过渡。全局方向、海拔幅度、起伏尺度和盆地范围是主要语义；不能通过几个独立椭圆帽或双重 cos 山丘冒充整体地势。局部调整可以使用平滑影响域，但不取代整体结构。

有限范围的五次平滑过渡可用于使边缘高度变化的一阶、二阶导数接回零。它只说明接合的连续性；相同高度和过渡距离下，中段坡度仍可能较大。多个区域融合、细节噪声与河床修改之后，必须检查最终坡度，不能把单个函数的性质当成整体保证。保留有限影响范围，以便局部编辑能够明确失效区域。

### 6.2 开放的空间组合表达

本设计不建立“山口、峡谷、空地、台地……”这样的封闭空间枚举。名称用于表达用户意图和检索配置；底层根据几何、边界、开口、连接与场的组合工作。一个没有地貌名称的空间，也必须能够被编辑、保存和检查。

表达分为四个部分：

| 部分 | 数据含义 | 可变化内容 |
| --- | --- | --- |
| 几何与场 | 锚点、可分段曲线、区域边界、高度函数、白盒体量与占用范围 | 位置、数量、尺度、截面、连续函数和局部细分 |
| 组合操作 | 变换、组合／分割区域、连接曲线、混合高度、局部下切／抬升、形变 | 操作树、层级、局部影响范围、参数绑定 |
| 空间关系 | 包含、相邻、通行连接、观察、遮挡、显露等 | 参与者、数量、连接结构、成立范围 |
| 语义描述 | 用户名称、用途、参考与参数预设 | 新增名称和组合配置，不要求改变底层对象类型 |

以上是可扩展的表达机制，不是“这几个操作已覆盖所有自然形态”的数学证明。对不满足现有几何前提的新需求，需要增加基元或操作及其检查，而不是强行归入某个旧名称。

其地形表达依据是特征基元与组合操作的研究。2015 年论文给出了可组合的表示，也明确指出新增地貌可能需要新的节点定义；该论文没有证明自动识别或自动生成任意自然空间。这里采用组合思想，空间开口、关系图和用户语义的组织则是本项目的设计。

### 6.3 组合实例，不作为类型清单

例如“河流在两片高地之间分开，绕过中央低台地后重新汇合，两侧各有一条岸边通道”，可以表达为：

- 一组带宽度和纵断面的河段，具有分流与汇合的连接关系。
- 一个受水域边界限定的中央地面区域。
- 两组由曲线、截面和高度影响构成的高地。
- 两条带净宽的通行区域，与可达空间连接。
- 需要时再附加局部观察关系。

这个组合不必先被认定为“峡谷”“河岛”或“盆地”，也不需要新增一个专用空间枚举。以后修改其中一条河段，影响的是引用它的区域和关系。

同样，曲线的数量、区域边界的形状、开口的数量、连续起伏和关系连接都可以变化。不能将“组合”实现成若干固定样板的缩放和旋转。

### 6.4 表达能力、语义映射与有效生成分别验证

“能表达”“能从描述映射”“能在约束下生成”是三个不同问题：

1. **几何表达。**本阶段目标是高度场地表及白盒体量。在每个水平位置只有一个地表高度、细节复杂度受限的范围内，可以通过分段曲线、区域和高度采样作有限精度近似；精度和资源预算限制实际细节。精确垂直壁、天然洞穴、岩拱和多层表面超出高度场本身的完整表达能力，不能用一个包围盒声称已实现对应地形。
2. **语义映射。**新的自然空间描述应拆成上述组合；名称未知但组合能力足够时，保留名称并使用组合表达，不退化成“最相近的预设”。本阶段以手动参数和编辑验证这种表达，未来 AI 映射的正确性另行验证。
3. **有效生成。**能描述一个分流绕岛结构，不意味着当前河网编译器已经支持它，也不意味着指定场地一定容得下。必须核对几何操作、连接能力和空间约束。

覆盖性测试应选择未参与预设编写的参考形态，将其拆成几何与关系，再记录是否需要修改底层代码、近似误差、丢失的连接和无法表达的部分。测试对象应包含不规则边界、多开口、多分支、多尺度起伏和复合空间，不只检查已命名预设。

目标是持续扩大可表达与可生成的范围，不承诺有限基元、固定精度和有限预算已经覆盖“大自然任意类型”。尚不支持的部分必须显式记录，不能通过改名或静默替换声称覆盖。

## 7. 河流与湖泊

### 7.1 河流是核心布局对象

河流必须具有独立身份、形状编辑、参数调节、全局联动和局部编辑能力，不能只作为峡谷示意线或装饰贴图。

一条河段至少表达：

- 与上游、下游、湖泊或出口的连接。
- 平面中心线及可编辑控制点。
- 沿程宽度，而非只能全河使用一个宽度。
- 纵向水面高程、河床深度与横截面。
- 河岸过渡、形状影响域和附近空间约束。

用户能够通过参数或控制点获得直河、舒展弯流、紧凑弯流、不对称河湾和宽窄变化。不能仅提供几个固定模板名称。

### 7.2 形状与结构的能力范围

| 能力 | 目标要求 |
| --- | --- |
| 宽度 | 支持整体宽度与沿程宽度曲线；实际结果可测量 |
| 平面形状 | 支持弯曲尺度、弯曲程度、方向和控制点编辑 |
| 纵断面 | 支持高程和下切意图，并与最终地形协调 |
| 汇流 | 河段通过真实连接关系汇入主河或湖泊 |
| 分岔、分流再汇合 | 属于需要明确实现与验证的河网能力，不能以重复重叠水面代替 |
| 湖泊连接 | 河口、湖面和相邻河床在同一高程与边界约定下求解 |

“任意宽度与形状”是控制目标，受到世界边界、表示精度和连接有效性的限制。不能把无限宽度、任意自交或水流闭环默认视为都能实现。

普通重力河流的方向与纵断面应协调。分流再汇合可以形成平面环绕空间，不等于水流沿有向闭环无限循环。人工逆坡输水等特殊行为不属于默认河流语义。

在宽河急弯中，简单地将中心线向两侧平移可能导致内岸自交。实现必须处理偏移边界、交汇区与水域拓扑；必要时调整局部弯曲、截面或表示方式，并记录实际调整。不能只让水面网格遮住错误。

### 7.3 河流与地形的双向协调

自然生成时可以由地势与水系共同决定初始结构。用户明确编辑河流时，河形成为本次主要意图，允许的地形、道路和岸边对象随之协调。

必须支持以下联动检查：

1. 全局增加河宽：观察所有相关河段、沿岸通道、跨越点和停留区的变化。
2. 全局改变弯曲程度或尺度：检查岸线、局部曲率、道路避让和地貌影响。
3. 局部拖动河段：检查新旧范围内的河床、道路、POI 和遮挡关系。
4. 改变附近山体：检查水流纵断面和上、下游连接是否受到影响。
5. 改变河网连接：显式更新相关河段与跨越关系，不沿用失效的旧拓扑。

### 7.4 湖泊

湖泊具有独立边界、水面高程、湖盆深度、岸坡与连接。编辑可以包含位置、面积、长宽比、方向、轮廓控制点和局部岸线。

面积或轮廓变化后，沿岸道路、停留空间、入出水口与观察关系必须重新检查。湖面、湖盆和岸线不能分别生成后依靠视觉重叠维持表面一致。

## 8. 道路、物理动线与 POI

### 8.1 物理动线与道路的区别

物理动线描述玩家可以如何穿行：道路、河岸、山口、林间开口、峡谷和山脊都可以承载动线。

道路是具有中心线、宽度、纵坡和地面表达的一类对象。不能因为地图上画了一条线，就认定物理动线已经成立。

### 8.2 生成依据

先确定需要连接的空间与允许的连接方式，再在地势、障碍和空间意图下选择可行路线。路线可以具有分支和环路，数量与结构受配置控制。

连续道路可以参考包含坡度、障碍和方向变化的路径搜索，再生成连续曲线。曲线平滑必须受可行通廊约束，且平滑之后重新检查道路全宽。相关技术见 [Procedural Generation of Roads](https://perso.liris.cnrs.fr/egalin/Articles/2010-roads.pdf)。

随机变化可以作用于途经区域、备选连接、转向尺度和允许的曲率变化。道路不应依靠逐点独立扰动制造变化。

无论使用样条还是其他曲线，数学连续性只证明没有相应的几何突变，不证明道路具有自然感。是否舒展、重复或突兀由用户在预览中判断。

### 8.3 关键参数与检查

| 参数 | 依据 | 检查 |
| --- | --- | --- |
| 净宽与净空 | 角色尺寸及安全余量 | 最终几何上的整段有效通行范围 |
| 最大坡度与跨阶 | 角色控制器实际能力 | 最终地表与碰撞的坡面、断坎 |
| 转弯半径与变化尺度 | 道路类型与用户调节 | 曲率、连续性、道路边界是否折叠 |
| 分支与环路 | 空间连接意图 | 真实连接与可达性 |
| 路线时长 | 路径长度、坡度与行走速度 | 使用实际可走路径估算，不能以直线距离代替 |
| 临水间距 | 河岸边界与安全空间 | 水域变化后重新计算净空 |

路线需要改变地形时，应形成显式的道路地形影响，并复查其对水域、台地和附近坡面的影响。

### 8.4 POI 的空间职责

当前 POI 至少包含身份、空间范围、进入关系、可停留位置、观察或到达意图，以及所关联的地标或对象。

当前支持的回报可以包括：

- 到达后看到新的湖湾、远峰或谷地。
- 从狭窄空间进入明显开阔的空间。
- 获得新的观察高度与方向。
- 发现另一条可达空间或回路。

远处用于定位的岩峰可以只承担地标职责。观景 POI 则必须具有有效的到达与观察关系；放置一个观景台模型本身不能代替这些条件。

POI 的数量与间隔由可用空间、角色移动尺度、行走时间和用户配置共同决定。课程或游戏里的固定秒数、固定距离不能直接当作本项目的通用规律。

未来建筑可以向同一 POI 提供占地、入口、体量和观察对象，再重新检查关系。不能承诺任意建筑替换都保持既有布局不变。

## 9. 视觉关系与空间构图

### 9.1 可计算关系与体验判断

| 意图 | 可编程表达 | 不能直接推出的结论 |
| --- | --- | --- |
| 看见目标 | 观察范围、方向、目标投影、遮挡比例 | 玩家一定会注意或喜欢 |
| 遮挡后揭示 | 沿路可见度曲线与显露位置 | 一定产生惊喜 |
| 框景 | 左右边界、目标、视廊和空隙 | 构图一定优美 |
| Pull | 目标或开口可辨认，存在连贯的前往线索 | 玩家一定按指定方向行走 |
| Push | 可理解的边界、阻力或方向限制，并保留可行选择 | 玩家不会感到困惑 |
| 近中远 | 指定观察条件下的深度分组、投影尺度和遮挡顺序 | 三层齐全就具有层次美感 |
| 剪影与留白 | 体量投影、轮廓重叠、天空或地面空隙 | 指标越大越好 |
| POI 回报 | 到达前后的可见范围、目标和空间开合变化 | 主观奖励感达到某个固定值 |

### 9.2 关系成立的范围

每条视觉关系必须说明：

- 从哪个观察区域或路线段判断。
- 使用什么眼高、视场角和允许朝向。
- 观察哪个目标区域，而非只射向一个中心点。
- 哪些对象可以承担遮挡或框景。
- 条件在哪个区间成立，允许什么误差。
- 违反时可以调整什么，哪些对象被锁定。

近中远由当前观察关系定义，不要求地理上存在固定同心环。

观察点小范围移动后关系也应保持合理余量。恰好在单个坐标成立的视线，不应冒充整个观景空间有效。

## 10. 体量与 OBB：本阶段止于白盒

### 10.1 当前表达职责

布局体量描述希望形成的边界、轮廓与占用范围。本阶段用 OBB 或组合白盒几何直接表达，调节尺度、比例、朝向、接地和相互间距，并检查它们与通道、空间和视线的关系。

一个体量组可以由多个占位体形成轮廓，但不能默认每个 OBB 都对应未来的一块岩石。当前无需素材目录、模型加载或素材适配器才能使用这些控制。

### 10.2 占位几何的检查含义

占位体必须显式说明是否参与碰撞、是否遮挡视线，以及表示的是实心边界还是轮廓范围。例如，树林范围不能未经定义就同时当作不可穿行的实墙。

检查使用本阶段实际显示的地形与占位几何。对白盒实心体成立的遮挡，只作为白盒阶段结论，不推断未来真实岩石或树木也会产生相同结果。

### 10.3 只保留未来的数据边界

保存世界单位、方向、支撑依据、轮廓职责和允许占用范围，使未来素材映射能够读取这些信息。真实素材的选择、缩放、组合、加载与替换后的复验均留到后续阶段，本阶段不实现对应功能，也不把它列为交付条件。

## 11. 约束与局部编辑

### 11.1 关系的统一描述

每种关系必须具备：

| 项目 | 内容 |
| --- | --- |
| 参与者 | 对象、空间、观察区或路线段 |
| 读取内容 | 需要哪些几何、场与参数 |
| 生成前提 | 哪些输入条件下能构造；如何收缩候选范围或预留必要空间 |
| 成立条件 | 可计算的判断、单位、范围与容差 |
| 保持方式 | 构造过程中维护什么性质，保留什么检查证据；哪些仍需最终复查 |
| 修改权限 | 允许改动的对象、参数和最大幅度 |
| 优先级 | 必须保留、尽量满足、仅诊断 |
| 依赖范围 | 几何影响域及可能跨距离传播的关系 |
| 修复方法 | 可实际执行的局部调整或结构替代，及其预算消耗 |
| 终止与退路 | 预算、替代结果与发布规则 |

新增关系需要注册其数据、前提、检查、依赖和修复语义。不能在生成前维护的条件，应明确标为需要候选检查或局部搜索，不能声称已获得构造保证。仅增加配置名称，不代表程序已经支持该关系。

### 11.2 优先级

先维护已声明的物理与数据有效性，再在可行范围内优先保留本次明确编辑和用户锁定项，然后尽量保留其他关系与布局。

两条不可同时成立的硬要求不能靠权重平均消失。系统需要给出实际采用的方案，并将未满足意图记录为调整或未应用。

审美偏好默认属于随机配置和人工反馈。用户明确要求“这条视廊必须保留”时，可以将相应几何关系升级为硬要求；“好看”本身不能升级为一个可计算的硬谓词。

### 11.3 局部求解流程

1. 保存编辑前的有效版本，解析本次修改对象、锁定项与用户意图，创建带输入版本和总预算的编辑任务。
2. 根据新旧几何范围、空间索引、关系依赖，以及新增的通道／视廊相交关系，确定受影响内容。
3. 固定未受影响对象的身份、随机结果和解析数据；在受影响范围内传播约束、缩小候选范围，不重新抽取全局 Seed。
4. 对具备构造方法的结构维护通行余量、岸线间距等已知条件；仅对尚未解决的局部关系组进行有界搜索或连续参数协调。
5. 所有候选检查、回退分支和局部修复共用本次任务预算。已排除的同一候选不重复试探，调整过的几何必须重新检查。
6. 任务结束后，独立发布检查器检验最终候选。通过才一次性提交地形、几何、导航与对应视图版本；检查失败不自动创建下一轮生成任务。
7. 本次任务内没有得到合格方案时，保留上一个有效版本。记录是明确冲突、预算内未找到，还是能力尚不支持，并记录原始意图是否满足。

改变全局河宽等全局参数，允许影响整个河网及其依赖对象。改变一小段河岸，不能顺便重抽其他山体和 POI。

### 11.4 “局部”的正确含义

局部由依赖范围决定，不等于一个固定半径：

- 河段变化可能沿连接影响上游或下游。
- 山体抬高可能遮住远处 POI。
- 新增岩体可能进入原本没有登记该岩体的视廊。

因此需要同时查询既有依赖和新旧变化范围与视廊、通道的相交关系。只更新原先已经关联的对象会漏检新产生的冲突。

具有连续循环依赖的一组对象需要一起求解，并检测不收敛或来回震荡。扩大影响范围也要消耗同一任务预算，不能通过反复拆分子任务重置预算。不能声称任意编辑都能固定成本、固定半径完成。

### 11.5 兜底与用户反馈

在同一次有预算的任务内，可以使用保留当前意图的局部协调、允许的替代几何或连接、明确允许的参数调整。替代方案同样需要满足发布条件；不能临时放松物理硬条件来制造成功。白盒是本阶段正常表达，不作为求解失败后的降级理由。

候选仍不满足发布条件时，保留已发布的有效世界，结束任务。下一次求解由新的编辑或明确的生成操作触发，不由后台计时器自动换 Seed 重试。

首次生成没有旧世界时，需要有随版本验证的基础安全配置作为恢复入口。采用该配置必须说明原始请求未完整实现，不能将其计为原意满足。

面向用户不能出现崩溃、白屏、破损世界或要求用户处理堆栈错误。可以清楚提示“已调整哪些内容”或“当前修改未应用，保留原状态”。内部保留完整诊断用于修复。

用户端不报错不等于任意互相矛盾的请求都能精确实现。

### 11.6 有限预算能保证什么

有限预算用于约束计算消耗，不能单独保证找到可行布局。需要分别说明：

| 承诺 | 成立依据与限制 |
| --- | --- |
| 任务有界结束 | 对候选分支、图搜索展开、连续迭代、影响规模和内存设上限，并设置可取消的时间期限；包括所有子任务和最终检查 |
| 已发布结果满足已声明条件 | 构造时保留已知性质，最终检查在约定精度内独立验证；未覆盖的条件不计为通过 |
| 某类输入可以直接构造 | 必须列出输入前提及构造方法维持的性质；局部截面或粗网格成立不能代替整个世界成立 |
| 支持范围内具有可接受的产出率 | 需要以固定配置、边界组合和未见种子实测；当前没有实测结果，不填写成功率承诺 |
| 任意输入都在固定次数内满足全部意图 | 本设计不作此保证。表示得出来，也可能因锁定项、空间不足或求解能力而无法实现 |

预算参数是工具配置的一部分。具体数值应在明确世界规模、精度、硬件与可取消粒度后确定，不能凭空指定“重试三次即可”。只设墙钟时间而允许一个不可中断的巨大计算，也不构成可靠的响应上限。

正常求解用确定的操作预算和稳定选择顺序，便于重放。墙钟超时用于取消并保留旧版本，不按机器快慢选择不同随机布局发布。拖动产生的新版本可以取消旧任务；已取消或过期的结果不得提交。

结束原因至少区分：

- **原意满足**：在用户允许误差内满足此次请求和必要条件。
- **调整后满足**：发布了有效方案，但改变了允许调整的意图参数，列出实际差异。
- **已证明的冲突**：具有可核查依据，并说明证明覆盖的参数或结构范围；只排除某种构造方式不能写成全局无解。
- **预算内未找到**：搜索停止，不推断不存在可行解。使用保守候选范围而未找到结果，也可能只是方法覆盖不足。
- **能力未支持**：表达、构造或检查能力缺失，不冒充空间本身不可能。

后面三类的显示结果可以都是保留旧版本，但不能混为同一种原因，也不能计入原意满足率。首次生成采用基础安全配置，同样单独记录。

## 12. 编辑与预览

### 12.1 一个世界，多种视图

| 视图 | 必须展示的内容 | 主要用途 |
| --- | --- | --- |
| 2D 规划 · 平面 | 高程与纹理区域、河湖岸线、全图道路、POI、体量、出生朝向、视线扇区及近中远分层 | 主要调参和局部选点编辑 |
| 2D 规划 · 45° | 同一快照的高度投影、体量、岸坡、空间开口及规划标注，仍可选中编辑 | 直观调节整体地势和空间层次 |
| 3D 预览 · Orbit | 真实地形和白盒，从完整地图开始观察 | 白盒全局检查 |
| 3D 预览 · Free | 复用现有 Seed demo 自由相机，在出生点进入真实尺度场景 | 白盒空间体验与视线检查 |

界面为左侧语义参数、右侧完整预览。左侧按构图、地势、水系、道路、POI／视线、山群组织；选中对象后在左侧直接调整局部参数。取消独立右侧几何检查栏与通用“添加空间表达”入口。检查数据保留为开发测试证据，不占主要调参界面。

预览顶层只有“2D 规划”和“3D 预览”；平面／45°归属 2D，Orbit／Free 归属 3D。物理动线、视觉关系和近中远标注可分别开关。进入时必须看到完整 1024 m 结构，不能以局部取景掩盖布局缺失。

### 12.2 交互要求

- 全局参数面板支持数值调节、恢复值、范围显示和明确单位。
- 选择点、线、面、体或空间关系后，显示相应语义参数与参与对象。
- 线支持控制点和沿程宽度，面支持轮廓与范围，体支持位置、旋转和尺度。
- 峡谷等组合对象支持整体调节，同时允许进入必要的组成结构。
- 编辑对象、观察位置和实际玩家位置分别管理。选中一个对象不应隐式移动玩家。
- 局部编辑和全局调节都显示受影响对象、实际参数及调整原因。
- 支持撤销／重做、保存／导入布局和随机配置、恢复已认可布局。
- 随机 Seed、随机参数和随机结构应有明确操作语义；改变 Seed 不应偷偷覆盖锁定参数。

### 12.3 一致性与更新

预览必须显示当前输入对应的解析版本。候选尚未完成时，保持旧的有效画面并说明正在更新，不能把旧地形与新标注混在一起后声称已经一致。

2D 平面／45°与 3D Orbit／Free 读取同一份已发布布局。切换视图、移动相机、漫游与分块显示都不重新选择山体、河流、道路和 POI，不触发布局求解。

功能调试信息用于规划器界面；普通漫游画面保持空间可读性，诊断图层由用户主动开启。

## 13. 验收手段

### 13.1 分开记录三种结论

| 结论 | 负责方式 | 通过意味着什么 |
| --- | --- | --- |
| 功能与数据正确 | 自动化测试、类型检查、几何与状态检查 | 参数、生成、编辑和保存行为符合定义 |
| 指定空间条件成立 | 最终几何上的通行、视线、体量等检查 | 在指定精度与观察条件下满足约定 |
| 白盒空间效果认可 | 用户手动查看、调节与漫游 | 用户认可当前体量、空间与观察体验，或提出范围建议；不包含真实素材的最终美术效果 |

前两类通过不能代替第三类。用户尚未验收时，明确记录“视觉待验收”。

不设置由 AI 主观打分决定是否允许用户看到结果的默认机制，也不要求先得到一份审美正例才能开始功能实现。

### 13.2 量化指标

| 检查对象 | 必须测量的内容 | 判定依据 |
| --- | --- | --- |
| 关键 POI | 可达数量、停留面积、地面坡度、与入口的连接 | 必须到达的 POI 全部具备有效路径与停留区 |
| 物理动线 | 连通分量、最窄处、净空、最大坡度、断坎、路径长度 | 角色配置与路线约定 |
| 道路 | 全宽有效性、曲率、曲率变化、边界交叠、水域冲突 | 道路类型和参数阈值 |
| 河湖 | 宽度误差、边界有效性、连接、纵断面、地形接合 | 实际水域几何与水系语义 |
| 视线 | 目标可见比例、投影视角、观察区域覆盖率 | 指定观察条件和关系阈值 |
| 遮挡揭示 | 沿路可见度、显露位置、变化区间 | 约定的先遮后显关系 |
| 轮廓／留白 | 投影重叠、空隙宽度、天空或地面留白比例 | 可调诊断目标，不能直接作为美感结论 |
| OBB／白盒体量 | 支撑、侵入通道、穿插、轮廓与占用范围 | 体量职责、接地、碰撞／遮挡属性与净空约束 |
| 局部编辑 | 实际影响对象、无关变化量、失效关系、撤销一致性 | 稳定身份和依赖维护要求 |
| 生成效率 | 构造后直接有效比例、局部搜索展开量、剪枝量、预算耗尽比例 | 固定输入范围与总预算，分别统计初次生成和局部编辑 |
| 性能与调度 | 耗时中位数、P95、最大值、连续迭代量、影响规模、求解触发来源 | 指定硬件、世界尺寸、精度与预算；无生成／编辑操作时不新增求解任务 |

阈值必须带单位、适用范围和来源。角色身高、半径、坡度和跨阶与真实控制器一致；几何容差与采样精度一致；视觉偏好由用户调节。

例如，通道净宽下限可以写成“角色直径 + 两侧安全余量”。这是物理尺度关系。POI 间隔则可以使用实际路径的行走时间范围，它属于可调体验配置。

可见关系可以定义为“指定观察区域中至少 q 的采样位置，其目标可见比例达到 v”。q、v、观察范围和采样精度必须作为检查配置保存。抽样通过不等于证明所有连续位置都成立；边界附近需要加密检查和安全余量。

未提供有效检查条件、目标为空或相关能力尚未实现时，应记录未覆盖或未满足，不能因为没有测量到失败就记为通过。

### 13.3 独立检查与回归

检查器应从最终几何读取证据，不能直接相信生成器写下的“已连通”“已可见”标记。

测试至少覆盖：

1. **明确正例、反例和边界例**：堵塞通道、抬高遮挡、移动目标、急弯宽河等必须改变相应检查结果。
2. **固定回归集**：保存曾经成立的功能组合及修复过的失败场景。
3. **参数边界与组合**：覆盖极值和互相冲突的组合，不只测试各滑块默认值。
4. **随机种子集**：记录配置、全部样本与失败原因，包含未参与调参的种子。
5. **编辑序列**：包含全局河形变化、局部移动、连续编辑、撤销和重新导入。
6. **局部与全量检查对照**：局部更新后，测试环境全量检查一次最终世界，发现远距离漏检；不重新随机整张世界。
7. **运行时触发边界**：无生成／编辑操作时，相机移动、漫游、显示分块和切换视图不新增求解任务；超时或失败后没有自动循环重试。
8. **未见空间组合**：使用没有专门预设名的几何、拓扑与关系组合，检查能否表达、调参、编译和独立验证；分别记录失败在哪一层。
9. **预算与中断**：预算耗尽、连续拖动、取消、过期任务返回、发布检查失败时，仍显示一致的有效版本；不把这些路径算作请求成功。

报告分别记录构造后直接满足、局部搜索后原意满足、调整后满足、保留原状和首次安全配置恢复，并附上第 11.6 节的结束原因。前两类可以汇总为原意满足率，其余情况不得混入。

分母必须包含对应测试输入集的全部请求；初次生成和编辑分别报告。明确输入分布、支持能力、预算、样本量和未见种子。不能通过静默缩窄随机范围、排除困难输入或把预算耗尽记为无解来美化产出率。只有这些数据才能检验“构造优先”是否确实减少搜索，而不是换了措辞。

对固定输入、精度和算法的增量计算，可以与相同已确定输入的完整重算作对照；不得在对照中重新抽取随机参数。存在多解的求解器应先规定稳定选择规则，再决定哪些结果要求数值一致。

### 13.4 用户视觉验收

用户可以通过任意预览和漫游方式提出反馈，不要求为每次反馈填写复杂报告。

工具应能够记录：

- 对应 Recipe、Snapshot、Seed、版本、白盒表示与检查配置。
- 用户观察的位置与朝向，或涉及的对象。
- 认可／不认可的现象。
- 建议调整的参数、范围和组合条件。
- 修改前后的布局，便于恢复和比较。

用户反馈“这类结果好看，限制某些参数在这个范围”后，更新随机配置并保留原始布局。不得从一张截图自动推导出未经用户确认的全局审美规则。

AI 可以整理反馈、解释参数影响和定位几何缺陷；不得自行宣布用户视觉验收通过。其视觉分析不是功能交付的必要前置关卡。

## 14. 可行性与后续实现顺序

阶段用于控制未知范围，不是按固定日期安排的执行清单。当前已获实现授权。初始 Demo 将数据、空间构造、联动编辑和白盒验证组成最小完整流程，尽早检验联合约束，再逐步扩大覆盖范围；不将联动问题推迟到所有单项功能完成之后。

| 阶段 | 交付重点 | 功能进入下一阶段的依据 |
| --- | --- | --- |
| A：共同数据与可观察结果 | Recipe／Snapshot、稳定 ID、参数元数据、基本保存重放、同一世界的预览入口 | 参数变化可追踪，各视图能够核对同一几何 |
| B：空间表达与构造 | 地势、河湖、道路、POI、空间、视觉关系、体量的可调表达，开放组合与单项检查 | 各参数有实际效果，构造前提明确，正反例可以判定；不要求视觉已认可 |
| C：联动与编辑 | 全局调节、局部选择编辑、范围传播、受约束构造、必要的有界搜索、撤销与事务 | 组合条件得到检查，无关内容稳定，预算不重置，失败后不自动重试 |
| D：完整验收工具 | 完整 2D／俯瞰／45 度、玩家白盒漫游、诊断与版本一致性 | 用户能够在一个 Demo 内完成参数调节和空间体验检查 |
| E：随机配置校准 | 用户反馈保存、范围和组合条件、配置管理、未见种子反馈 | 用户认可的范围可复用，具体认可布局可重放 |

白盒应在前面阶段随功能逐步接入，D 阶段表示工具完整，不表示到最后才第一次检查 3D 表达。以上阶段均不包含真实岩石、树木等素材替换。

随机参数变化与随机拓扑变化分别验证。可变河宽通过，不代表分岔已通过；单个 POI 通过，不代表多个 POI 的路线组合已通过。

功能开发不因视觉尚未调好而停在原地。若出现参数不生效、图层与地形脱节、修复反复震荡、无关对象漂移，或只能通过放松硬阈值维持表面成功，则必须先修正对应方法，不能以增加更多语义名称继续掩盖。

## 17. 当前实现验收边界（2026-09-08 用户修订）

本节记录用户否决上一版 Demo 后的明确方向，优先于旧草稿的界面与预设阈值。

- 中心区域为 1024 × 1024 m，513 × 513 Heightmap 存储高度，512 × 512 Alphamap 存储实际 Terrain texture layer 权重；3D 使用项目既有 Terrain 系统。
- 1024 m 以外延续边缘高度，通过受 Seed 控制的岸形与平滑过渡落到海底；参照 dev/2.0 的海岸实现，不显示悬空方形地板。
- 默认布局即包含全局自然地势、多个上游分支汇入同一区域的河湖网络、贯穿地图的道路、分布式 POI 和有近中远关系的白盒体量。Integrated World 只作为海拔平缓提升方式与空间组织的参考，不复制其 Heightmap 或先造独立随机山丘再摆体量。当前 Heightmap 可以平坦，主要高差由山群白盒表达；不能退化为散点摆放。
- 水面高于河床只是必要条件。必须额外检查岸边接合、河湖交汇水位和连续水床，且在实际视图中检查悬空、断裂与穿插。

- 上一版 44 项测试与 38 个种子结果仅属于旧版内部检查；不构成当前 Demo 已达标的证据。审美继续由用户验收。

### 17.1 空间布局优先于基底起伏（同日补充）

山群、留白、远中近层次、POI 和动线是地势设计依据。Heightmap 负责连续基底、水床与必要的平缓过渡，不是空间布局的导演。当前阶段即使基底高度为零也可接受；不得以独立噪声山丘的丰富度代替空间结构。

主要海拔可以来自岩石山群。白盒应表达高台、山肩、开口及接续关系；未来接入岩石后，玩家可以在岩石支撑面上行走。通行的数据含义是连接可用支撑面，不能把所有未来动线锁死为 Heightmap 上的二维路径。当前 Free 相机用于观察，不得把自由飞行宣称为已验证岩石攀行或支撑面连通。

### 17.2 当前阶段收敛（同日补充）

以 dev/2.0 Seed demo 已有能力为基础，当前主要改造是取消由局部地形山丘承担的山体表达，改为山群分布与多种 OBB 白盒体量；Heightmap 保留可调的全局海拔提高和缓和起伏。

本阶段不投入通用底层约束求解器、完整物理证明或大规模规则系统。基础水域、道路和 POI 应可用、可调、可见，开发优先级是语义参数、山群组织、留白与远中近、2D 平面／45°编辑，其后才是 3D 白盒体验。文档早先的约束体系是后续方向，不作为本阶段新增求解实现的任务清单。正常参数编辑不等待完整几何约束审计；只保留实际运行所需的数据有效性保护。

### 17.3 地貌与关卡语义覆盖（同日补充）

地形、山峰、山脊、山口、峡谷、盆地、台地、岸线继续属于核心范围。弱化 Heightmap 山丘和底层求解投入，不取消这些地貌语义，也不取消 POI、Pull／Push、视线遮挡、到达观景、留白及近中远组织。当前允许使用可编辑的组合白盒表达；数据与界面应区分已有组合能力和未实现的专门形态控制，不以名称齐全代替功能齐全。

### 17.4 中心全图、连续体量与共用场景（2026-09-08 第二轮反馈）

- 默认出生点固定为世界 (0,0,0)，不将出生坐标与朝向作为主要调参；全图 360° 均布局地貌、POI 和动线。近中远仍是观察关系，不再把整个世界压缩到出生朝向前方。
- 白盒使用能容纳未来真实岩石组合的 outer OBB。占地与连续剖面必须体现山肩、台地、壁体、裙部、主峰及鞍部负空间，不能仅有几根高柱。主峰形态由体量表达，Heightmap 只提供轻缓基底与水床，局部抬升须被体量覆盖。
- 山高、山群分布、视觉反馈与物理动线共同驱动地基海拔；取消互不关联的地势主控制。恢复山脊上山、山口、峡谷、沿岸、跨越等物理动线，不能都编译成道路纹理。山上路线须携带支撑体和纵向高度。
- 支持 1～3 个独立河流系统及各自支流／接收湖区；河源、河湖交汇、水面、水床与岸线来自相同发布几何。水域合成不能因处理顺序相互填平。海洋使用核心边缘向外延续后逐渐降至海面的同一高度来源。
- 默认进入 3D 编辑场景，保留 2D 平面和 45°规划。Editor 与以后 Play 共用实际 Terrain／Water 场景构建入口，以图层控制白盒、真实地表等展示。尚未接入的生态、真实岩石不冒充有效开关。
- 选中局部对象时，Orbit 自动以其为旋转中心；Free 移动至对应 XZ。对象聚焦依据已发布变换后的包围范围，不能读取未提交的编辑数据。
- UI 保留稳定控件与正在输入的草稿。鼠标松开、展开组、切换控件和异步结果返回均不能销毁未提交输入或吞掉点击。验收覆盖第一次操作，而不是只用第二次操作或键盘滑块代替。
- POI 显示关联地貌、到达路线、停留支撑和观察目标。Pull／Push／回报必须能在规划与实际相机中找到空间依据，名称不构成验收证据。

### 17.5 POI 场所与通路节点解耦（同日补充）

POI 是以用途、空间范围和布局关系描述的场所，不是道路转折点或一个看向山群的相机点。通路节点负责连接、转向、跨越与支撑面切换；POI 通过入口接入通路，包含活动区、地标、观察位置和内容槽位。新增村落、营地、遗迹或资源区域时，复用这些构成；用途保持可扩展，不为每一种场所另造基础资产系统。

- **点**：通路锚点、场所入口、地标与内容位置；跨越点保留两岸接点。
- **线**：物理动线、入口连接、岸线、山脊及视线关系；跨越动线关联桥梁占位。
- **面**：场所范围、活动区、视域扇形、水域及地貌留白。
- **体**：山群 outer OBB、平台、桥面及未来对象的空间预留。

场所布局依据地形、可用空间、视线和入口关系生成；移动场所不得隐式移动道路锚点或整平整个场所半径。需要挖填地形时必须有明确的地形意图。当前白盒生成平台、入口地标和内容占位；这些槽位未来可承载素材，但不在本阶段加载真实岩石、建筑或桥梁。线索、机关、目标、资源获取与交互规则属于未来玩法配置，规划器提供空间位置及连接契约。

验收必须同时看见场所范围、入口到通路的连接、活动区和占位体，且能够独立修改场所与通路节点。不能用一个 POI 图标、名字或观察扇形代替完整场所表达。


### 17.6 三个参考构图与六类支柱组合（2026-09-08 最新实施方向）

根据用户“开始实现这 3 个”及“用实验分支的立方体支柱拼装六种岩石结构”，先以三个有明确空间关系的固定白盒场景收敛能力：开阔水谷、河谷聚落、峰林跨河。每个场景包含出生视野、目的场所、首段接近路线、水域及山群；主面板只显示该场景的六个语义控制。原全局随机模式保留为独立选择，不将三个案例描述成已经完成的大世界随机导演。

- 山体改用具有占地厚度的柱状体网格采样轮廓：冠峰／尖塔、岩壁、扶壁／山肩、台地／帽岩、鞍部／缺口、山脚裙边。整组外包围范围继续用于选择和聚焦，不以一个外包围盒替代内部形状。六类是可组合的轮廓职责，不能据此宣称穷尽自然形态。
- 支柱支持宽、深、高、朝向、底部海拔及自定义上下轮廓。鞍部保留中央缺口；离地上部体量与两侧支撑峰组合表达岩门。普通基底保持平缓，允许埋底；高低和镂空由白盒体量承担。
- 先选整组调形，再在组内选择单根支柱；2D 平面、45°和 3D 使用同一组已发布几何。岩体、台地、建筑占位、地标和桥面用类别颜色区分，不按远近给资产强行分类。
- 三个场景先支持有意义的整体参数及局部编辑，再由用户调整构图和比例；此阶段不追求纹理、植被或真实岩石与建筑替换。场景布局改变不能重置无关的局部编辑。
- 登高和跨越使用可见且参与碰撞的支撑面。3D 继续复用 Seed 的 Orbit／Free、2 m/s、Q/E 和真实 Terrain／Water；有限案例的连续通行检查不等于任意参数组合或完整角色物理系统已经得到保证。
- 三个截图只约束可辨认的空间关系与出生构图方向，单张截图不能唯一确定实际尺寸、镜头或背面几何；当前实现与参考图的美感相似度由用户继续收敛。技术检查不得冒充审美验收。


### 17.7 地貌结构先行与可选区域（2026-09-14 用户修正）

规划图必须直接表现峡谷、悬崖、台地等结构的形状和负空间，并可点击整片区域显示结构名称。岩石原子提供可组合形状与职责；地貌实例决定轴线、通道、两岸组装及地势剖面，不能先撒石头再补地貌标签。河流、通路与观察意图共享这一结构依据。固定 seed=1 参数继续用于复现，禁止针对种子写坐标特例。

首个落地类型为双岸峡谷：先在真实陆域内拟合弯曲谷底与两岸空间，再沿局部切线组装岩壁、冠峰和山肩；地势使用结构纵断面和横断面，独立于单岩高度。峡谷范围包含通道及两岸，单侧岩壁仍可选。后续结构类型和完整六职责资产目录仍须分别实现，不能把一个峡谷模板等同于通用地貌导演。


### 17.8 峡谷平面组合与水系统可编辑域（2026-09-15 用户收敛）

当前先假设基础 FBM 地形，不规划海拔、高差、坡度与剖面；山脊实体道路暂缓。先通过两岸旋转 OBB 的组合及并集表达开阔、收束、错位、转折和展开。规划 OBB 是体量区域，不要求一块对应一个岩石素材。峡谷拥有山体密度、开阔程度、错位程度三个 0～1 参数；密度调整占用体量与搭接，开阔度调整段落留白，错位度调整两岸相对位置与朝向。

不提前勾勒具体河流。蓝色闭合虚线表示独立的水系统可编辑域，由旋转矩形并集形成连续区域，不是水面、河床或最终河岸；域内交给水系统，域外受其他模块占地限制。水模块后续维护实际河形、深度和流向。不得将该范围存成已生成的真实 PlanWater 或水面纵断面。


## 2026-09-15：参考轮廓覆盖实验与职责白盒方向

独立 canyon-shape-study 自动描绘样本输入与 OBB 拟合已实现，未接入世界规划。固定参考两岸覆盖率分别94.5743%和94.6021%，使用35/56块；越界率约0.000209%/0.000399%。3项测试通过，覆盖率使用独立多边形面积积分而非拟合采样计数。结果和目标SVG保存在实验目录。轮廓为人工描绘，不是图像分割真值，覆盖成功不代表用户视觉验收。

用户随后指出精确轮廓可能本末倒置：ABC结构应由有职责的白盒体量与负空间表达，真实岩石决定细部轮廓。因此保留本实验为辅助对照，暂停向全局生成接入；下一步先讨论开阔入口、错位窄口和转折展开的体块职责及几何验证，不以高覆盖率替代结构成立。

地表默认草地，仅道路和广场泥土。2D 使用同源矢量轮廓，白盒进入时才生成 1024 alphamap。建筑 OBB、门、围栏、树石通过同一 snapshot 渲染与导出；白盒使用米制网格与 FBM 地面，并加入树干、石块和围栏碰撞。

验证：WorldSettlementPlanner 的 11 项测试包含 32 个种子的语义参数极值组合、确定性、道路端点连通、最终占地避让、局部隔离、空村庄和故意断路/侵入负控。相关 palette、reference、scene、third-person 测试合计 21 项通过；terrain 类型检查通过。一次本机测试纯规划生成中位数约 22 ms、P95 约 35 ms，不含首次页面加载或 3D 初始化。美观与漫游感受仍由实际体验决定。

扩展边界：当前只接入树、石两种景观代理及两村庄的配置；后续地貌可复用米制数据、模块依赖和占地查询，但尚无任意地貌动态插入的产品界面，也不宣称完成任意世界扩展。

## 2026-09-18 POI 实验的分级布点与接路职责修正

在独立 POI 工作树内，将 POI 从独立撒点改为大型→中型→小型顺序补点并跨级避让；没有 cell 区域。符号具有明确大小差异，内容占地仍由实际元素拥有。中型房舍组、小型独栋复用建筑参数；大型/中型地貌按组合配置抽取。

道路入口在空间元素的端口数据声明接入需求及朝向，不声明目的地；路网模块统一选择拓扑、绕障并保证同一陆域的必要节点连通。连接为带种子扰动的树和可配置附加边，不要求全图成环。路宽和弯曲进入实际几何，失败保留上次可行结果，海岛之间不自动跨海接路。

景观密度由环境距离带和海拔/坡度/局部高差共同约束，规则独立配置。左/右界面采用环境、空间布局、景观等层级，父图层关闭禁用后代；显示层级不冒充新增生成器。现阶段及未接入能力见 [POI_EXPERIMENT.md](semantic-study/POI_EXPERIMENT.md)。

## 2026-09-18 用户确认的白盒表现约束

测试实体只用规划快照的 OBB 拼装，加分类颜色和米制网格；禁止树冠等具象占位模型改变体量判断。实体的渲染、拾取和碰撞共用数据，保持占地、底高、高度、朝向。道路/地表保留规划轮廓用于接缝检查。素材适配必须保持同一包络和落地基准，白盒通过不等于未经尺寸校准的素材也能通过。界面移除底栏及顶部聚焦按钮，保留 F；右侧层级显示明确折叠箭头。

## 2026-09-18 POI 实例树与内容分级修订

依据用户最新约定，大型候选为村庄/峡谷，中型为散落房舍/台地/断崖，小型为高树；候选范围与预算来自配置，实例以 POI 成员关系发布。右侧只列当前已生成内容，按大中小 POI 组织，不能把村庄、地貌或场所建筑硬编码成独立于 POI 的主分类。父开关控制实际成员并禁用子开关，折叠复用左侧原生 details；名称、内容轮廓及未填充点均为辅助显示。已填充 POI 不重复画圆圈。

峡谷与河流共享连续曲线，参数控制长度、方向、弯曲、谷底宽度、岸壁宽高和河宽变化；不强制分支汇流模板。景观实例发布所属 POI，全局参数可被逐 POI 密度、树高范围、环境密度和生长条件覆盖。高树是 POI 主体，周边景观密度为零不删除主体。显示层不得改变生成数据，白盒仍复用真实 OBB 包络。

## 2026-09-18 参数更新性能边界

用户要求参数调整达到毫秒级，去除浪费的计算。已验证空间依赖不变时，景观密度、环境权重、海拔/坡度筛选、树高及其逐 POI 覆盖可独立更新；不重新分配 POI、重建建筑或路网。占地变化必须重新校验，不能用显示上的即时变化代替真实求解。道路/地貌/世界轮廓修改仍执行所需空间求解，不能宣称全部参数已有几十毫秒的局部求解能力。

## 2026-09-18 Hierarchy 交互分区

依用户最新要求，每行固定为左侧箭头、中间名称整片区域、右侧显隐勾选三个独立交互区。仅箭头改变展开状态；中间选择、高亮并聚焦，不展开 POI 子项；右侧仅改变图层显隐，保留父关禁用子开关及子项偏好。此约定取代旧的整行原生 details/summary 折叠。预览拾取仍可展开祖先以定位具体元素；分组名称高亮该组并聚焦其成员范围，无空间成员的世界/辅助组回到全图。


## 2026-09-18 编辑单位与参数清理

按用户要求，地貌内部用于拼形的岩体/OBB属于组合实现细节，保留白盒及占地数据，但不作为默认参数与Hierarchy操作单位；选中整块地貌调其组合参数。村庄、地貌与其独立子元素要有明确入口，避免同一操作区重复展开所有祖先参数。

POI范围本轮暂按“内容可用占地上限”实现为可选米制半径，区别于点间距、主体形状尺度和周边景观密度。自动范围依据主体实际占地，显式范围参与最终验证；仅选中显示，不恢复全图细胞或重复圆标。增大范围不等于自动放大内容。此语义是等待用户进一步细化前的实现假设，不宣称通用任意轮廓区域已完成。道路宽度必须到具体可选择的道路实例，并进入真实轮廓/导航与碰撞检查。
