# 大世界模块约束契约

日期：2026-09-10。状态：实现前设计，尚未实现或通过运行验证。

## 1. 本轮决定

当前优先证明：布局由模块关系与规则构造，编辑沿同一套关系协调。暂不开展 Seed 多样性、美感、真实素材及 3D 渲染验收。主要成果为完整 2D 规划；高度相关关系必须有规划数据，缺失时标为未检查，不能用平面相交代替三维判断。

世界范围 2048×2048 米，高度图不超过 1025²，alphamap 不超过 1024²。保留矩形组合与平滑轮廓核心；矩形是模块内部的形状构造数据，模块间使用编译后的权威轮廓与空间接口。细节尺度不低于约 4 米，不将其作为所有碰撞检测的固定步长。

本文件补充《地形规划V2.md》，按用户最新决定收敛本轮执行范围：首批地貌为山群、峡谷／开阔谷地；陆域、水系、村落、物理与视觉关系、出生点需配合完整。用户参数使用面积占比、密度、方向等相对变量；物理长度、能力阈值由内部配置提供。出生点在已有布局中最后选择，不驱动全图放射分布。

## 2. 抽象与所有权

保留七类职责：陆域与基础高程、地貌、水系、场所、通行、视觉、出生点。峡谷是地貌模块的一种语义组合，不重复拥有其中的河流或道路；它引用水系、通行模块生成的对象。村落实例内部拥有建筑、活动区和内部入口连接。

不用全局万能优化器，也不让模块互相调用并修改对方数据。采用：**模块提出候选与调整方案，协调器管理事务和资源，独立检查器审核候选快照。** 所有读操作针对不可变快照，只有拥有者能编译对象的新版本。

### 2.1 公共记录

| 记录 | 必需字段与含义 |
| --- | --- |
| ModuleInstance | 稳定 id、类型、父对象引用、语义参数、局部覆盖、锁定自由度、生成版本、revision；不以数组下标作为身份 |
| Geometry | 点、带宽曲线、多边形（含洞／多连通分量）、体量及其坐标；X/Z 为米、Y 向上、角度统一 radians；旧 0～2048 坐标通过显式适配保留 |
| SpatialExtent | ownerId、geometryId、role、适用高度区间／面引用；role 区分组织范围、实体占用、通行预留、岸带、视觉影响、地势影响 |
| Surface | ownerId、有效平面范围、高程求值与误差、坡面／台面类型；未知高度显式标记 unknown，不能默认 0 |
| Port | ownerId、位置与朝向、接入范围、宽度、高度／面引用、允许连接能力；同一连接两端引用端口而非复制位置 |
| Relation | id、参与对象及端口、类型、作用范围、必需／偏好、检查配置、允许修复操作；连接图可以有环，所有权树不能有环 |
| Adjustment | 请求与实际参数、变更对象、触发约束、修改范围、备选动作及代价、未满足需求；不把内部缩小后的值冒充请求值 |
| CheckResult | 规则 id、对象与 revision、pass/fail/unknown、测量值／容差、冲突位置、原因；可选关系未启用记 not-applicable，不是 pass |

共同关系原语为包含、避让、沿随、相接、承接、跨越、保留空间、观察、遮挡；具体模块组合这些原语，不按未来所有 POI 名字预制分支。约束依赖必须包含查询范围：新岩石进入视廊，即使以前没有对象引用，也应触发重查。

模块拥有自己的端口与几何；协调器唯一拥有已接受的关系、预留及跨模块端口绑定。汇流节点由水系拥有，不由各支流复制；移动一个节点、相关预留和消费者编译结果在同一事务接受。模块只能提议关系变化，不能私下覆盖已接受关系。

### 2.2 重叠的默认含义

| 相遇对象 | 默认规则与合法例外 |
| --- | --- |
| 山群范围与河流／道路 | 组织范围允许重叠；检查具体岩体、河床、岸带和通行范围 |
| 同山群岩体 | 允许有声明的拼接重叠；不能因此填掉谷地、山口、台面或通道预留 |
| 不同山群岩体 | 默认避让；明确共同山体关系后允许融合，重新检查双方空隙与通路 |
| 道路与岩体 | 地面通路不得穿实体；登高通路必须引用承接面，并检查路径上方角色净空，不能豁免整块岩体 |
| 道路与水域 | 默认不可作为陆行边；有跨越连接计划或明确涉水能力时分类处理 |
| 河流与河流／湖泊 | 声明汇流／分流端口才可合并，更新水域并集及连接图；偶然重叠不能自动充当合法汇流 |
| 村落范围与道路 | 允许接入入口和内部通路；建筑、活动区及入口净空按各自规则检查 |
| 建筑与岩体／水域 | 默认禁止占用；本期不隐含水上建筑或悬崖建筑能力 |
| 地势影响、视觉影响与任意范围 | 不作为平面排他占用；按高程合成或指定观察关系处理 |

组织范围用于选中和展示归属，不能成为一刀切的碰撞区域。禁止“有一个合法 relation，就忽略这两个对象之间的所有碰撞”；例外只在关系指定的空间与高度范围生效。

## 3. 模块输入、输出与责任

| 模块 | 必须读取 | 必须输出 | 自己维护 | 可接受的外部请求 |
| --- | --- | --- | --- | --- |
| 陆域／基础高程 | 世界范围、面积与形状意图、已保留用地和端口 | 主岛／离岸岛范围、岸线、海域、地表高程、海岸过渡影响带 | 陆域拓扑、洞的语义、边界、基础高程连续；宽范围抬升不制造孤立尖峰 | 调整岸段、保留登陆区、宽范围抬升、局部削平／开槽；不能删已锁定场所 |
| 山群／谷地 | 可用陆域或明确离岸岛支撑、地貌意图、已约定水槽与通道 | 群范围、岩体包围体及支撑数据、山脚、山肩／台面、山口、谷底走廊、形态骨架 | 单体与组合范围一致、接地、拼接、指定负空间连续；峡谷两侧体量与谷底具有相对高差 | 让出通道、移动山脚、改变开口、调整高度、提供连续登高承接面 |
| 水系 | 海岸出口、地表与谷地、可用岸边空间、源汇和形状意图 | 有向水网、共享汇流端口、河湖轮廓、水面／河床纵断面、岸带、塑形要求 | 水网连通、宽深合法、湖面统一、节点水位连续、普通水流不逆坡；保留矩形形状变化能力 | 改线、扩宽、改变汇入位置、协调水位或岸带；改动同步上／下游端口 |
| 村落 | 用地、承接面、通路接入需求、水体与实体范围 | 组织范围、建筑 OBB、建筑入口、活动区、场所入口及内部通路 | 建筑范围内分布、间距、基础高程、建筑入口接入活动区和场所入口；密度按剩余容量计算 | 转移入口、局部移位／重排建筑、调整用地或台地需求；不靠删除入口让村落成立 |
| 通行 | 必需目的地、端口、障碍、承接面、通行能力 | 地面／岸边／登高通路、走廊范围、纵断面、连接图、跨越接口 | 全宽连续、面承接、坡度／净空、连接点一致；物理动线不限于道路涂层 | 改线、换端口、增加山口或跨越需求；不直接削山和改水 |
| 视觉 | 已有目的地、可到达观察空间、体量与高程 | 观察点、目标引用、虚线扇形、有效视廊、可选近中远对象关系、遮挡请求 | 意图有实际目标与空间对象；不要求全图所有观察点均满足相同构图 | 调整观察位置或方向、替换非锁定目标、减少次要遮挡意图；实体调整交给拥有者 |
| 出生点 | 场所／通路上的可用候选、承接面、网络、可选视觉意图 | 位置、高度、朝向、所属面、网络接入 | 安全落脚、净空、接入必需通行网络 | 重新选址；用户明确锁定后转成必须保护的局部条件 |

地形最终高度由陆域／高程职责统一合成。山群提交宽范围抬升意图，水系提交河床和岸坡要求，道路提交必要承接要求；不能三个模块分别给同一位置写互相矛盾的最终高度。二维阶段允许分片高度函数和纵横断面作为权威规划面，不强制生成整张 heightmap。

高度请求统一提供作用范围、等式／上下界／目标趋势、误差及 H/S 性质。基础起伏与宽范围抬升先形成偏好面，再满足明确河床、岸坡、地面路与基础的条件；互斥硬条件返回冲突，不以写入顺序决定胜负。高程模块返回实际 Surface revision 和未满足请求；河床、岩体接地、地面道路与建筑针对同一版最终面重编译和检查。岩体顶部承接面仍由地貌拥有，引用最终基础面计算绝对高程；地面路请求不能改变架空岩面。坡面规划未提供完整定义时，不声称已承接。

连接需求显式区分 `planned-connectivity`（规划可连接）与 `supported-traversal`（已有承接可通行）。本轮跨水／岛间连接只提供通用跨越规划：端口、净宽、绝对高差、跨度、净空包络及能力配置版本；不生成桥素材。能力配置至少声明跨度上限、坡度上限、落脚长度和净宽，未配置则返回 unknown，不默认任意跨度可连接。跨越记录包含责任方和 planned/supported/unresolved 状态。村落对外的全图关系可要求 planned-connectivity；出生点落脚及其接入本地通路必须满足 supported-traversal；两种结果分开展示，整图不宣称已可漫游。

统一内部配置分为 GeometryTolerance（坐标／曲线误差）、TraversalProfile（角色宽高、净空、纵横坡与断坎）、ConnectionProfile（跨越能力）、TerrainProfile（岸坡和宽范围高程）、SolveBudget。能力值必须来自显式配置并随检查结果保存；缺值不赋予无限能力。这里不编造最终角色或桥梁能力，开发正反案例可使用明确标注的测试配置，不能替代未来运行时能力核对。

四种地表层为泥土、草地、道路、沙地。水下河床属于泥土；岸边黄色区域对应实际过渡带。相交时由地表编译规则输出归一化权重，道路可穿过泥土过渡带但不能绕过通行规则。固定海岸缓坡属于内部配置，不新增用户滑杆。

## 4. 可执行约束目录

H 为必须满足；S 为可调整偏好。未知信息不能通过 H 检查。以下数值阈值集中配置，不写死在各模块里，也不作为用户常规参数。

| ID | 对象／规则 | 测量或检查方式 | 冲突的首要处理 |
| --- | --- | --- | --- |
| G01 H | 权威轮廓有效 | 有限坐标、闭合、自交、面积、洞包含及世界边界；检查最终平滑轮廓，不只检查构造矩形 | 所属形状模块修复局部接合／曲率；保持连接语义 |
| G02 H | 容纳与范围 | 子几何减允许区域为空；几何距离及允许容差；部分包含不能靠中心点通过 | 拥有者移动／重组；必要时申请扩大范围 |
| G03 H | 实体避让 | 宽相位包围范围查询，窄相位多边形／OBB 检查；有高度时再检查体区间 | 按关系例外判断后，拥有者提出局部移位或让路 |
| G04 H | 预留空间 | 实际实体不能侵入已接受的通道、入口和净空 | 修改后来生成对象；用户主动修改对象时协商关联空间 |
| T01 H | 接地与承接 | 岩体底部与所属面允许埋深；建筑基础与面高程相容；通路承接域覆盖全宽 | 调整底部／基础／规划面，不能只改画面位置 |
| T02 H | 峡谷语义 | 谷底走廊从入口至出口连通；沿变化段的横截面检查两侧岩体、相对高度和净宽；局部扩口显式允许 | 调整两侧体量与山口；不能只有名称叫峡谷 |
| W01 H | 水网连接 | 共享端口坐标与水位一致，河湖连接有非零有效宽度；有向图无循环，分流再汇合允许 | 重算接合区域；局部河段影响传播到共享节点 |
| W02 H | 源汇归属 | 源头为显式内陆源区／湖口；末端连接海域或声明的终端湖；不能存在未声明悬空末端 | 换出口／源区或协调谷地，不能直接截断 |
| W03 H | 水面与河床 | 河床低于水面；普通河流沿向水面不升高，湖面恒定；水陆交界来自同一截面 | 水系与高程模块联合调整断面；瀑布不作隐式兜底 |
| W04 H | 河流与山群 | 水槽不穿实体；谷地关联河段的水域与要求岸边通路处于可用谷底；检查弯道及汇入口最窄处 | 改河形或让出山脚；不强制每条河都处于峡谷 |
| P01 H | 村落内部可达 | 每个必需建筑入口经内部净宽通道连到活动区和场所入口 | 保留通路后重排建筑，再计算密度容量 |
| P02 H | 村落对外可达 | 每个要求接入的村落至少一个端口接入必需网络；检查原始需求集合，不能仅检查成功生成的入口 | 调整场所入口、外部路线或封堵体 |
| R01 H | 地面通路避障 | 最终平滑路线的全宽走廊减承接域为空，且与障碍无非法相交；端点连接一致 | 在预留走廊内改线；否则向障碍拥有者请求让位 |
| R02 H | 登高通路 | 纵断面连续，整段有承接面引用；坡度、横坡、断坎、上方净空满足通行配置 | 加长／折返路径或改变山肩与台面；目标不可直接删掉 |
| R03 H | 跨越连接 | 两端接入有效地面与路线，具备落脚面积、高差、跨度和净空；满足已声明连接能力 | 改交点／岸段／端口；没有能力时仅为未实现需求 |
| R04 H | 网络真实性 | 地面边与“计划跨越边”分别构图；不得把待建连接记为已可步行 | 修复缺边；展示规划连通和已承接连通两种结果 |
| V01 H/S | 指定可见关系 | 观察者位于有效面；视线高度、目标样本及与体量相交；记录样本与误差 | 优先移观察位置／次要遮挡物，必要时放弃 S 关系 |
| V02 S | 层次、pull/push | 关联路径片段、目标投影方向、近中远对象距离次序；push 体确实改变可用通廊，pull 目标有可见依据 | 调整局部开口、体量或路线；不承诺玩家心理反应 |
| S01 H | 出生安全 | 承接、净空、非水域，接入声明可达网络 | 在已生成可行位置中重新选择 |
| E01 H | 编辑一致性 | 无悬空引用，关联端口更新，所有依赖失效后重查；锁定字段未变；发布 revision 一致 | 原子回滚整个相关提案，不发布半张新图 |

视觉规则只有显式标为必需的关系才作为 H，不把整个视锥清空。采样可见率是白盒几何估计，不能声称像素精确可见率。没有高度数据时 V01、R02、W03 返回 unknown；2D 中也必须展示尚未完成，不能伪造全绿。

上面的 unknown 规则适用于所有依赖高程的检查，包括 T01、T02、S01。协调器从原始需求、对象类型与关系独立生成 CheckObligation 清单；每个义务必须具有同版检查结果，缺失即 unknown。not-applicable 必须带适用性依据。P02、R04 和 S01 按需求声明的网络类型检查，不能混用两个图。

碰撞检查采用最终曲线的自适应离散近似，记录最大几何误差；宽度净空检查加入该误差的保守余量。道路长度采样不替代边界交叉检测，细窄障碍不能落在固定 8 米采样间隙中。面积误差、接触误差、通行余量分别配置，不能用“允许误差”接受整段断连。

## 5. 构造与协调管线

选择分阶段串行提交，独立候选计算可并行；首版不要求并行。模块关系允许双向，但单次执行不递归互调。

1. **需求与粗范围**：在陆域内共同分配地貌、水系、场所的粗范围与接口；登记所有必需对象／连接需求。村落不必等山体细节全部生成后才找剩余空地。
2. **协同预留**：水系与谷地共享水槽／岸边需求；场所与通行共享入口及通廊需求；确定关系后冻结本轮预留。粗范围未满足时即协调，不先摆满岩体和建筑。
3. **模块内部编译**：在预留条件内生成矩形组合轮廓、岩体、河湖、建筑与通路。山群和河流没有永久的谁服从谁；拥有者按本次意图处理收到的需求。
4. **具体冲突协调**：独立检查器定位冲突，相关模块返回有限备选提案；协调器应用一组相容提案后重查。
5. **视觉与出生**：在有效物理布局上选择有意义的观察关系，必要时发起局部调整；出生点最后选定。视觉调整后再次检查物理关系。
6. **发布**：所有本次必需规则通过才发布；保留实测值、修改记录和缺失能力，预览只读取快照。

预留冻结仅对一轮候选计算有效。需要拓宽河道并移动岸路时，协调器建立下一版预留，整组重新接受后使旧消费者失效；锁定空间不可解冻。这样既能联动，又不会出现各模块自行撤销预留。

### 5.1 最小模块接口

三个操作足够，不引入任意脚本式规则语言：

- `propose(intent, context)`：读取空间查询、参数、相关需求与预算，返回拥有者的数据候选、对外端口、预留、依赖以及未满足需求；不修改共享状态。
- `revise(current, requests, context)`：根据具体约束请求返回有限替代候选，包含改动范围、影响对象、实际参数和代价；内部使用自己的矩形／图／采样算法。
- `check(candidate, context)`：模块内部不变量检查。公共关系另外由独立检查器读取最终几何，不直接相信生成器的成功标志。

请求统一携带：constraintId、参与对象、几何范围／端口、希望达到的条件、可调整自由度、锁定项、基准 revision。首批请求只实现让出通道、调整范围、重定位端口、匹配支撑／水位四类；视觉开口用让出指定体空间表达。

### 5.2 冲突优先级和终止

- 几何安全、锁定字段、必需关系共同构成不可违反条件，不能按一个加权分数互相抵消。
- 在可行方案中，优先满足本次编辑意图，再减少受影响对象与位移／形变，最后优化视觉等偏好。用户正扩宽河流时不能默认将河宽缩回去而优先保护未锁定岩石。
- 锁定字段与必需关系相互矛盾时返回具体冲突集合；不假装总有解。实际可调范围可以变化，但请求值与实际值分开保留并解释。
- 所有模块共享单次事务预算；初始开发配置：最多 4 轮协调、每个冲突最多 8 个不同备选，每个子搜索消耗全局候选／几何检查预算。具体上限是工程初值，不是成功保证。
- 以实际几何、需求、锁定项的语义摘要识别重复状态；revision 只用于过期检查，不进入循环判据，以便发现 A→B→A。已否决方案不再尝试；相同冲突往返则终止，不能模块各自重置预算。
- 编辑失败保留上一有效快照；首次生成失败可显示明确的基础可用布局，但必须注明未满足哪些必需内容，不能计为本次完整布局成功。必需村落／跨越／登高目标不得静默省略。

### 5.3 局部编辑的影响范围

初始影响集 = 旧新几何范围的并集与余量 + 对象引用依赖。然后加入跨出该范围的关系：水网上下游、通路连通、长视线、地势影响面等。每个提案扩大的范围都需要再查询依赖。

局部编辑不保证固定半径，也不能整图重新抽样。无关模块复用已有数据；受影响且未锁定的模块通过同样 propose/revise 流程调整。连续编辑取消旧作业；过期 revision 的结果不可覆盖新请求。

## 6. 实现前推演与数据自测清单

以下为测试设计，未执行。以关系和反例为主，不以某张图片为答案，不优先扫描随机种子。

| 情况 | 预期行为 | 必须捕获的错误 |
| --- | --- | --- |
| 山脚伸入已有道路 | 发现全宽碰撞，局部改线或要求山群让出通道 | 仅检查中心线、直接删除路线 |
| 道路位于山群范围内但不碰岩体 | 允许通过 | 把群范围整个标成障碍 |
| 谷地内河流扩宽挤到岸路 | 联合让出山脚或改岸路；检查汇流端口 | 水域变宽但泥土带、道路、山脚不动 |
| 主河弯曲使支流接合脱开 | 共享端口带动支流末段重编译 | 两个轮廓视觉靠近就算连接 |
| 湖水位变化 | 更新河口和河床断面，检查村落及岸路 | 只变水面显示，不更新接触关系 |
| 村落密度增加 | 预留入口和内部通路后填充容量 | 有外部道路但建筑门口全部堵死 |
| 山群高度增加 | 更新宽范围高程意图、承接面、登高路径和相关视线 | 路线终点只用相对岩高当绝对海拔 |
| 同山群两岩拼接 | 允许合法交叠，保持山口净空 | 全部禁止重叠或全部豁免 |
| 地面线路穿水 | 产生可检查两端与能力的连接需求 | 无跨度／高度条件仍算已可走 |
| 删除跨越连接 | 规划网络明确断开，必要连接失败 | 地图有线就持续显示连通 |
| 新岩体进入已有视廊 | 空间查询使观察关系失效并重查 | 只沿旧对象引用更新，漏掉新遮挡 |
| 视觉开口与村落入口冲突 | 保留必要通行，调整／撤销次要视觉请求 | push 物体封死唯一出口 |
| 岛屿缩小影响岸边村落 | 相关模块协商迁移／范围调整，锁定冲突时保留旧图 | 裁掉超界建筑或强制吞掉必需场所 |
| 两个模块互相推回 | 检出重复状态，有限结束并解释 | 无限协调、换 Seed 掩盖问题 |
| 微小障碍位于采样间隙 | 窄相位仍检出全宽相交 | 仅固定步长采样漏检 |

每项先有通过案例，再主动注入违规数据确认检查器会失败；检查器和生成器不能共享同一个“已经有效”布尔值。需覆盖三方以上组合（河流＋岸路＋山脚＋村口），两两无碰撞不等于全网可达。

结果提供规则 id、对象 id、测量值及地图定位，方便后续选中高亮。数据层通过条件：必要对象未丢失、H 检查无 fail/unknown、修改原因可追溯；S 关系单独统计。仅平面部分通过时明确叫“平面约束通过”。

## 7. 与现有实现的差距及实施入口

| 当前代码 | 可保留 | 必须改造 |
| --- | --- | --- |
