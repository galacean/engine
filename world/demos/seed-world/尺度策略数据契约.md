# 尺度策略数据契约（2026-09-17）

状态：数据设计提案。第三人称尺度角色已接入；以下建筑与间距规则尚未替换当前生成器。单位统一为米，面积为平方米，速度为米/秒。

## 统一输入

```json
{
  "version": 1,
  "actor": {"heightM": 1.8, "collisionDiameterM": 1.0},
  "movement": {"walkMps": 2, "runMps": 8},
  "architecture": {
    "house": {
      "bayWidthInHeights": 2,
      "bayDepthInHeights": 2,
      "floorHeightInHeights": 1.6,
      "bayCountX": [1, 2],
      "bayCountZ": [1, 2],
      "floorCount": [1, 2]
    }
  }
}
```

人体身高与速度由用户确认；碰撞直径沿用当前白盒，不等于人体肩宽。house 系数是待标定的风格样本，非建筑规范或人体唯一推导结果。开间只用于约束外部体量，不生成室内房间。

## 推导

开间宽 Bx = 人高 × bayWidthInHeights；进深 Bz 同理。
建筑宽 W = Bx × 开间数X；深 D = Bz × 开间数Z；高 H = 人高 × 层高比例 × 层数；占地 A = W × D。
示例：2×1开间、1层，结果7.2×3.6×2.88米、25.92平方米。高度指建筑白盒墙体总高；屋顶另记，不能与总高混淆。
门净宽 >= 碰撞直径 + 2×侧向余量；门净高 >= 人高 + 头顶余量。余量属于内置通行策略，不按移动速度放大。
院落大小由建筑占地及建筑覆盖率推导，保留随机长宽比；覆盖率也属于待标定策略，不能仅由人高决定。

## 间隔策略

每种关系记录：id、referenceSpeedMps、referencePathGapM、minClearanceM、calibrationId。
目标净路程 = max(minClearanceM, referencePathGapM × 设计行走速度 / referenceSpeedMps)。
referencePathGapM 在第三人称白盒中标定；不预设3/5/7秒为公理。它与速度合起来仍隐含通过时间，这是无法消除的设计选择。
净路程指模块出入口之间沿可行走路线的长度，不是中心点直线距离。中心距还取决于双方占地与朝向。
只对标记为 travel 的间隔缩放；院门、巷道净宽、围栏退让等 clearance 关系依据人体通行。
Shift运行时不改变布局。修改设计速度才重新编译受影响间隔；几何不可行时报告目标与实际差异，不能偷偷压缩房子或全图重试。

## 给AI与测量端的输出

每个结果保存 policyVersion、ruleId、输入、实际米制结果、人体倍数、目标值/实际值、校准记录。
例如：house-7：2×1开间/1层，7.2×3.6×2.88米，25.92平方米；heightInActors=1.6。
关系记录：fromGate、toGate、targetPathGapM、actualPathGapM、walkSeconds、runSeconds、status。
报告只描述尺寸、净空和连通性；不能以通过时间合格宣称空间变化丰富或美感达标。

## 第三人称实现边界

米制胶囊外观，高1.8米、直径1米；Galacean capsule primitive 的height为中间圆柱长度，因此传入总高减去直径，避免多算两端半球。
相机目标为脚底+0.8身高，臂长3身高；FOV固定沿用白盒策略，均不新增用户滑条。
OBB膨胀射线和FBM采样使镜头收近。运动仍是原保守圆柱控制器，非完整胶囊物理。地形碰撞为采样近似，未宣称生产角色控制器。
