# Lake 湖盆编辑与 High 光学标定

本批仅用于独立 Gallery Lake。沿用现有 WaterBody / Heightfield / High SSR 链路。

## 编辑语义

- `LakeEditDocument.boundary` 是可编辑的湖盆参考轮廓，`basin.referenceLevel` 是固定的地形基准面。
- 修改轮廓、采样精度、盆底深度或岸坡宽度：显式生成新的 `LakeTerrainSnapshot`，同步替换可见地形和水体。现有景物保留 XZ 位置，并保持相对地面的高度。
- 只修改 `boundary.waterLevel`：复用同一份地形快照，不夹紧、抬升或压低床高；实际水域随淹没范围变化。
- `LakeTerrainBoundary` 求可见地形三角面与水平水面的交线。这个解析后的闭合岸线交给现有 Lake 编译器，用于水面网格、岸线场和水域判定。
- CPU 湖底采样使用与地形网格相同的三角形插值。GPU 深度图仍有格网过滤和量化误差，不承诺逐像素等于 CPU 查询。
- 地形边缘被淹没、没有湿润湖盆或岸线相切等情况拒绝发布，并保留上一完整版本。

## 发布与清理

`LakeEditSession` 串行准备修改；新请求取消旧请求。准备阶段生成地形、红色实际采样点和 WaterBody replacement，完成后同步发布。旧资源仅在发布完成后释放；准备、上传或发布失败时回滚。撤销恢复上一份编辑文档；取消保留当前已发布版本；重置恢复默认湖盆。

页面销毁先取消编辑，等待候选资源回滚，再销毁 WaterBody 和借用资源，最后由现有异步清理屏障销毁 Engine。单独改水位不上传新的地形网格，逐帧也不重建地形。

## 操作入口

开发预览中展开 Water DevTools → Lake：控制点、水位、湖盆深度、岸坡宽度、光学标定、Undo / Cancel / Reset。生产预览保留 `window.lakeDemo`，不挂载开发面板。

```js
await lakeDemo.setWaterLevel(0.3);
await lakeDemo.setBasin(4, 8);
await lakeDemo.undo();
await lakeDemo.setCalibration(true);
lakeDemo.probe(0, 10); // 默认轮廓、水位 0 时深度 0.25 m
lakeDemo.probe(0, 0);  // 1 m
lakeDemo.probe(0, -10);// 2 m
await lakeDemo.reset();
```

水深标定沿 Z 轴设置三段床高，湖岸附近仍保留过渡坡。2 米棋盘格用于比较折射开关。水位改动会改变标定深度；应先重置再开始标准对照。

## UE 参考与差异

参考本机 UE Water 插件的 `WaterBodyLakeComponent.cpp`（`GenerateWaterBodyMesh`）与 `WaterBrushManager.cpp` 的距离场、JumpFlood、ElevationCurve 流程：闭合样条定义水平湖面，地形雕刻由编辑侧独立处理。

本实现采用演示侧距离剖面生成可撤销地形快照，再求地形与水面的交线；保留 Galacean 现有确定性 Lake 扫描线三角化。没有移植 UE 的 Landscape Edit Layer、JumpFlood 或 constrained Delaunay。浮力和完整样条图形编辑器属于后续范围。岸边景观生成见下节。

## 验收要点

1. 水位 −0.3 / +0.3：地形哈希、床高、地形上传次数不变，中心水深分别为 2.9 / 3.5 米；连续撤销回到默认值。
2. 凹岸与干地内环：交线贴合地形三角面，查询不会把干地判为水面。单元测试覆盖这两种轮廓。
3. 上传失败、发布失败、旧请求被取代、编辑中销毁：上一完整版本不受影响，候选资源被回收。
4. High 标定：查询 0.25 / 1 / 2 米区域；比较折射、深度着色、接触泡沫与反射开关；在近景和低视角检查前景物体、岸边树木及 SSR 屏幕边缘退化。
5. 最后检查浏览器运行错误、失败资源请求和编辑后的资源计数。

## 岸线景观与地表（2026-09-10）

`LakeLandscapeLayout` 消费已发布的实际岸线与地形高度，按岸线弧长选择组团中心，再用岸边距离、水深、坡度与间距筛选候选位置。模型和 KTX2 纹理继续由 Demo 资产库共享；生成器不修改水位、湖盆或 Water 编译产物。参考 UE 的 Water → PCG 数据方向，分布规则由 Demo 自己定义。

- 树木放在干岸并避开陡坡；保留较稀疏的前景。蕨类集中在干燥的近岸区域。
- 石块分为岸边组团、浅水零散与少量深水石块。水下石块按真实模型高度限制缩放，保持顶部在水下。原有三个光学接触探针保留，生成器为它们留出间距。
- 默认上限为 7 棵树、32 株蕨类、16 块岸石、12 块浅水石和 4 块深水石，共 71 个景观对象。地形约束不足时允许少放，不为凑数量突破约束。每组候选次数有上限，只在初始化或显式生成时运行。
- 地表材质根据实际床高相对水位、几何坡度和连续噪声混合草、泥、沙，区分湿润和深水区域。噪声只改变地表外观，不移动岸线，也不改变深度查询。没有新增纹理或离屏 pass。

操作：展开 Water DevTools → Lake。`Landscape seed` 修改种子；`Landscape / 景观状态` 显示 Ready 或待更新；点击 `Regenerate landscape / 重新生成景观` 应用当前湖泊版本与 seed。水位、湖形或湖盆改变后，旧景物仍随地形贴地，但其分布明确标为待更新，需要显式重新生成。取消保留已发布景观；生成过程先准备隐藏实例，成功后替换，准备失败回收候选并保留旧景观。

程序接口：`lakeDemo.setLandscapeSeed(42)`、`await lakeDemo.regenerateLandscape()`、`lakeDemo.cancelLandscape()`。`lakeDemo.snapshot().landscape` 返回来源、seed、布局哈希和过期状态；`lakeDemo.landscape()` 返回生成时的位置、分区与约束读数，过期时不应把这些读数当作当前地形上的新生成结果。
