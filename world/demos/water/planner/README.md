# Planner 水体联调

入口：`/demos/water/planner/index.html`，默认 Seed 1，也支持 `?seed=2`。页面固定展示 Planner 天然水域与道路，以及浅溪、河流、瀑布、阶梯和小湖；不再提供展示功能切换，旧 `case` 参数不生效，发布后从 URL 移除。内部单功能配方仍用于确定性测试，不作为页面模式。

全屏画布与一个小面板。左上角提供“环绕 / WASDQE”双向切换，沿用同一相机位置与朝向；点击画布后 WASD 平面移动，Q/E 下降上升，拖动转向。面板输入、画布失焦和模式退出均不保留键盘移动。“全景”查看主岛和离岸岛，“聚焦水体”查看局部；面板显示世界尺寸、Seed 与岛屿数量。选择列表分为河流与湖泊、跨河连接、全局道路，可聚焦各元素。水体支持调整宽深/岸坡/湖泊水位、编辑控制点、撤销重做；地形、水体、道路材质和跨河连接可分别隐藏。道路和桥当前提供查看与聚焦，不新增独立的路网编辑工具。查询与发布状态默认折叠。

## 接入

“光照对照”提供原预览光照与 Scene_Demo 光照两种模式。后者沿用授权 Farmlands 天空贴图、主光、三色环境光、反射强度和雾参数，关闭原预览的 ACES、曝光、暖色和 Bloom。首次切换准备环境缓存，之后直接复用；地形、道路、桥、水体及查询版本不重建。完整 Planner 保留自己的光照。动态云影未复现，具体源参数及适配边界见 [光照来源](assets/FARMLANDS_LIGHTING_SOURCE.md)。

- `WaterPreviewPlan.ts` 使用 Planner 的 `createSeedPlanningDocument` 和共用 `SpatialTerrain` 入口：世界 1024 × 1024 米，主岛、离岸岛及基础地形带按相同作者配置和 Seed 生成。默认 Seed 1 与指定参考页实际显示的配置一致；旧 URL 的 `g=1729`、`h`、`height`、`alpha` 不作为新版参数。背景 Heightmap/Alphamap 与 Planner 同为 1024 × 1024，背景高度采样间距为 1024/1023 米。单功能展示只执行地形与水域生成；`planner` / `all` 复用 `generateSpatialWorld` 的水域、体量/端口、障碍和路网计算，通过 `environment:false` 跳过生态及视觉引导生成。POI 计算是复现原路网的必要依赖，不加载或展示其建筑、岩石资产。
- `WaterPreviewProjection` 只发布水域、全局道路（含网络连接）和桥所需内部通道，保留地形高程场及通行剖面。用于增量修复的完整几何布局只存在编译器私有 WeakMap，不写入作者数据或工程文件。
- 桥和 `roadApproaches` 使用 `planningWhiteboxes` / `whiteboxGeometry` 的实际发布尺寸与桥面高度；道路复用生产 Terrain 的 Alphamap。简单桥面用于定位和通行几何检查，未新增桥梁美术资产。
- 作者数据使用 `PlanningDocument` / schema / `PlanningSession`，通过 `exportPlanningRecipe` 进入水域生成。生成数组不是编辑入口。
- 地形渲染复用 `PlanningTerrainView` 的生产外观、最终高度图和 Terrain 精细替换块。水体复用 `PlanningWaterRuntime`、原生组件/资源及其唯一 `WaterSystem`；保留宿主默认海洋配置。
- Lake High `lake-water-look-v1`、Ocean `ocean-look` 沿用独立 Water 案例；河流使用用户确认的 Farmlands Scene_Demo 预设 `farmlands-scene-demo-river-v1`。配置由 `shared/water` 拥有，案例只提供场景输入和编辑 UI；不采用 `water/island` 的场景专属调参。
- `WaterPreviewEnvironment` 提供程序化天空与实时 IBL（128 像素、64 采样），Water 通过现有 Planner 原生运行入口借用天空环境反射；首次发布等待烘焙完成。颜色输出沿用独立湖泊案例的 HDR/ACES、曝光 +1、色温 +10 与 Bloom。保留 Planner 地形/湖底材质；河床增加同源覆盖驱动的 Farmlands 砂石层，不引入景观或云体积渲染。
- 修改先准备隐藏地形、跨河几何与原生批量水体，再在同一同步接受点发布。失败保留旧版，页面销毁取消准备并清理所属资源。

后续水体功能在水系统与 Planner 作者模块实现后，此案例直接消费相同能力。新增展示输入放在 `createWaterPreviewDocument`；不在案例复制 Compiler、Backend 或查询实现。开发者可通过 `window.waterPreview.session` 调用 Planner 的编辑/创建/移除接口，通过 `sampleWater` / `sampleDrops` 查看已发布查询。

这是水体联调入口，使用同一地形与水体消费者；完整 SeedWorld 的布局协调与玩法回归仍在原入口验证。此案例不读取或覆盖普通 SeedWorld 的本地工程。

## 2026-10-11 · 局部地形准备与 Worker 差量交付

预览与 Planner 的 `PlanningTerrainView` 共用候选资源保留机制：未变化的 Terrain 批次保留网格和材质，道路沿用相同 Alphamap 与图层绑定，草地颜色场按 Engine 和 Seed 借用。背景按原有网格分块，保留原高度、洞、三角形方向及整图计算的法线；背景与道路像素不对齐时保留完整背景。桥根据 Planner 已发布桥面/引道数据决定是否保留，只有同步共同提交时才移入新的场景根节点。准备、失败回滚、旧版退休分别持有并释放自己的资源引用。

`PlanningRasterTransfer` 同时用于 Planner 栅格线程与预览线程。请求明确指明基线，响应交付变化高度区间和精细块，未变化的 Alphamap、Ocean 和洞数据省略。接收方重建不可变快照并继续走原有 adopt 与共同发布入口；尺寸或编码范围变化时退回全量。缓存只保留请求基线和最新候选，取消候选不会丢弃仍在使用的基线。作者数据、布局、精细地形和水体精度不变。

调试接口 `waterPreview.terrainPreparation` 显示最近一次共同发布创建/复用批次数与桥是否复用；`waterPreview.rasterTransfer` 显示后台阶段、全量/差量类型及数值数据字节数。字节数不包含作者文档、布局对象、字符串和消息协议开销；仍有布局求解、背景扫描与湖泊自身编译成本。实测与验证记录见 Planner `V2_IMPLEMENTATION.md` 的本日局部准备记录。


## 2026-10-12 · 展示水体顺应基础地形

初始示例不再集中摆在世界中心并用整条河最低点定统一水位。`WaterPreviewSites` 在同一 Planner 基础地形上确定性选址，避让初始天然水域及其他展示案例；结果仅写入现有作者参数，后续经 PlanningSession、Worker 和共同发布入口消费。编辑或撤销不重新选址其他水体。

- 浅溪/普通河流沿当地下降方向布置，按每 2 米作者锚点生成局部高程，校验单调下降、坡度及完整路径地形支撑。保留 1 米宽/0.1 米深浅溪，普通河流 4 米宽/0.6 米深；不通过加宽、加深或填土兜底。
- 瀑布/阶梯从上下游及平台范围的实测地形推导落差，不再固定扣除 3 米。沿当地主要下坡网格轴布置初始落水段，避免斜向断崖在现有网格上的锯齿；任意斜向落水的通用网格衔接并未在本轮修复，编辑方向能力不受此初始策略限制。
- 湖泊保留 7 米半径、2 米湖盆深度。在湖岸、岸坡与捕获边界范围选择起伏不超过 0.8 米的地块，按 0.5 米作者探针校验参考水位，不在高坡上强制压低水位造深坑。
- 初始选址预算为普通河槽总开挖不超过水深加 0.6 米、落水案例不超过 2.5 米；这些只用于筛选展示位置，不是引擎或后续编辑的硬限制。找不到合适候选时明确报错，不发布深挖兜底。背景地形与局部精细 Terrain 的采样参数、网格和 Water 查询实现均未降低精度。
